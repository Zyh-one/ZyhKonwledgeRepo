然后，去简单了解Angular前端框架以及一些文件组织形式，其中梳理了组件Component，模块Module，路由route，服务Service等基础概念，也关联上前端代码是如何映射到浏览器上的。

最后，突然得知可以直接修改Swagger.yaml，通过一些命名自动修改前端和后端的代码

以下是当前paas项目的代码自动化构建流程，后续可以持续总结和扩展

# Swagger 代码生成流程

项目采用 Swagger Spec First 模式。修改 API 字段、枚举或接口时，只修改对应服务的 `swagger.yml`，不要手动修改生成代码。

以下以 `compute` 服务为例。

## 1. 修改 Swagger

编辑：

```text
api/compute/swagger.yml
```

## 2. 生成并构建后端

```bash
(cd api && go generate ./compute/restapi/...)
(cd api && make build)
```

如需运行测试：

```bash
(cd api && go test ./compute/...)
```

完整生成一致性检查：

```bash
(cd api && make -j generate-check)
```

## 3. 生成前端 Client

```bash
(cd webapp/caip && yarn generate:swagger -- --project="compute")
```

## 4. 检查改动

在项目根目录执行：

```bash
git diff -- api/compute
git diff -- webapp/caip/projects/client/src/lib/compute
```

确认 Swagger 和自动生成的 Go、TypeScript 文件一并提交。

其他服务只需将命令中的 `compute` 替换为对应服务名。
