# 寒武纪 PaaS 平台监控指标链路

## 1. 文档范围

本文结合 `devplatform` 部署文件、后端配置、前端 PromQL 和黄区生产集群只读查证结果，整理 PaaS 平台监控数据链路。

黄区使用 VictoriaMetrics Cluster 承担中心采集、存储和查询能力，未发现独立 Prometheus Server、Prometheus Operator 或 Thanos。VictoriaMetrics 替代的是 Prometheus Server 的运行时职责，并继续兼容 Prometheus 指标格式、标签模型、PromQL 和 HTTP API。

## 2. 四层监控体系

```text
PaaS 页面层
  paas-web：筛选对象、组织 PromQL 和展示图表
        │ /api/monitor
        ▼
monitor-server 平台查询层
  鉴权、限制 Namespace、转发查询
        │ Prometheus 兼容 API
        ▼
VictoriaMetrics 数据层
  vmagent → vminsert → vmstorage ← vmselect
        ▲
        │ 抓取 /metrics
Exporter/指标生产层
  kubelet、node/GPU/MLU Exporter、vLLM、Envoy
```

| 层次 | 主要组件 | 职责 |
| --- | --- | --- |
| PaaS 页面层 | `paas-web` | 筛选业务对象并展示图表 |
| 平台查询层 | `monitor-server` | 鉴权、限定查询范围、转发 PromQL |
| 监控数据层 | `vmagent`、`vminsert`、`vmstorage`、`vmselect` | 采集、写入、存储和查询时间序列 |
| 指标生产层 | kubelet、Exporter、vLLM、Envoy | 测量并暴露 Prometheus 格式指标 |

> 指标生产者负责产生数据，VictoriaMetrics 负责采集、保存和查询，monitor-server 负责受控地提供数据，PaaS 页面负责解释和展示数据。

## 3. PaaS 页面层

`paas-web` 部署在 `devplatform` Namespace。Predictor 监控页面负责获取业务信息、计算时间范围和步长、管理 version/pod/container/path 等条件、填充 PromQL 模板、调用 `/api/monitor` 并转换图表数据。

```text
Browser → PaaS Ingress → devplatform/monitor-server:80
```

前端不直接连接 VictoriaMetrics。

## 4. monitor-server 平台查询层

`monitor-server` 部署在 `devplatform` Namespace，主要负责：

1. 接收前端监控请求；
2. 验证身份和项目权限；
3. 限制允许查询的 Namespace；
4. 访问 `/api/v1/query` 或 `/api/v1/query_range`；
5. 将结果返回前端；
6. 调用或管理告警规则接口。

```text
paas-web → monitor-server → vmselect → vmstorage
```

`monitor-server` 不是指标生产者，也不是时序数据库。

## 5. VictoriaMetrics 数据层

### 5.1 黄区实际拓扑

| 组件 | 数量 | 职责 |
| --- | ---: | --- |
| `victoria-metrics-operator` | 1 | 管理 VM 系列 CRD 和工作负载 |
| `vmagent` | 2 个 shard，每个 1 副本 | 发现、抓取并转发指标 |
| `vminsert` | 2 | 接收写入并分发到存储节点 |
| `vmstorage` | 2 | 持久保存时间序列 |
| `vmselect` | 4 | 执行 PromQL/MetricsQL 查询 |
| `vmalert` | 1 | 执行告警和 recording rules |
| `vmalertmanager` | 1 | 管理告警通知 |

```text
Exporter /metrics
  → VMServiceScrape / VMNodeScrape
  → vmagent → vminsert → vmstorage
                         ↑
monitor-server → vmselect┘
```

### 5.2 vmagent 与采集声明

黄区 `VMServiceScrape` 分布在 `monitoring`、`aibrix-system`、`envoy-gateway-system`、`llm-webui` 和 `serving-system`；`VMNodeScrape` 位于 `kube-system`，用于 kubelet、cAdvisor 和 probes。

仓库中的 `prometheus-k8s` ServiceAccount 是历史命名，实际执行采集的是 vmagent，不能据此推断存在 Prometheus Server。

### 5.3 prometheus-adapter 的边界

`prometheus-adapter` 只把 vmselect 中的指标转换为 Kubernetes Custom/External Metrics API，主要供 HPA 使用：

```text
HPA → prometheus-adapter → vmselect → vmstorage
```

普通页面查询不经过 adapter。

## 6. Exporter/指标生产层

### 6.1 Kubernetes 基础指标

| 生产者 | 观测对象 | 典型指标 |
| --- | --- | --- |
| kubelet/cAdvisor | Pod 和 Container 资源使用 | `container_cpu_usage_seconds_total`、`container_memory_working_set_bytes` |
| kube-state-metrics | Kubernetes 对象状态和标签 | `kube_pod_labels`、`kube_pod_status_phase` |
| node-exporter | Node 操作系统资源 | `node_cpu_seconds_total`、`node_memory_*` |

### 6.2 GPU

GPU/DCGM Exporter 产生利用率、显存、温度、功耗和健康状态指标。按 Predictor 展示时，需要通过 `namespace`、`pod`、`container`、`gpu` 或 `uuid` 关联设备与业务容器。

### 6.3 MLU

MLU Exporter 产生 `mlu_utilization`、`mlu_memory_utilization`、温度和功耗等指标，并可能借助 `mlu_container` 通过 `uuid`、`type`、`vf` 关联 Pod。

### 6.4 Predictor/vLLM

vLLM 推理容器暴露请求吞吐、运行/等待请求、Token、TTFT、TPOT、KV Cache、Prefix Cache 和 Spec Decode。`vllm:*` 既可能是原始指标，也可能是 recording rule 生成的指标。

### 6.5 Envoy

Envoy Gateway 和 `envoy-svc-exporter` 暴露请求量、状态码、路径、延迟、错误率和上游连接等服务指标。

具体指标拆解分别见：

- [硬件监控](3类监控指标/硬件监控/README.md)
- [服务监控](3类监控指标/服务监控/README.md)
- [大模型监控](3类监控指标/大模型监控/README.md)

## 7. 三类监控图

| 监控类型 | 主要生产者 | 主要内容 |
| --- | --- | --- |
| 硬件监控 | kubelet/cAdvisor、node/GPU/MLU Exporter | CPU、内存、网络、磁盘、设备利用率和内存 |
| 服务监控 | Envoy、`envoy-svc-exporter` | 请求量、状态码、路径、延迟和错误率 |
| 大模型监控 | vLLM、AIBrix、recording rules | Token、TTFT、TPOT、请求队列和缓存 |

三类图虽然都通过 `monitor-server` 查询，但底层指标不是同一个服务产生的。

## 8. 组件位置总表

| 组件 | 位置 | 主要职责 |
| --- | --- | --- |
| `paas-web` | `devplatform` | 前端监控页面 |
| `monitor-server` | `devplatform` | 鉴权和 PromQL 转发 |
| Predictor/vLLM | 用户项目 Namespace | 推理服务与 LLM 指标 |
| Envoy Gateway/exporter | `envoy-gateway-system` | 服务请求和网关指标 |
| VictoriaMetrics Cluster | `monitoring` | 采集、存储、查询和规则计算 |
| node/GPU/MLU Exporter | 各节点或 `monitoring` | 节点与设备指标 |

## 9. 总结

```text
设备/容器/应用
  → Exporter 或 /metrics
  → vmagent → vminsert → vmstorage
  → vmselect → monitor-server → paas-web
```

排查时依次确认指标是否暴露、vmagent 是否发现目标、vmselect 是否能查询到序列、标签能否关联业务对象、monitor-server 是否连接正确，以及前端 PromQL 是否匹配实际指标。
