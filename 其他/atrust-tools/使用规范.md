# aTrust 最终使用规范

## 目标

本方案只解决两个问题：

1. aTrust登录期间，用独立 Chrome访问 ChatGPT和 Gemini；
2. 结束使用后，一键彻底退出 aTrust并快速恢复普通网络。

不再维护普通 Chrome、Codex、VS Code与 aTrust的同时兼容，也不修改系统 DNS、默认路由或公司网卡配置。

## 日常流程

### 1. 启动并登录 aTrust

从应用菜单打开“aTrust 启动”，完成管理员授权，然后在 aTrust界面登录。

### 2. 使用公共 AI网站

从应用菜单打开“aTrust 专用 Chrome”。该浏览器使用独立 Profile，并通过：

```text
127.0.0.1:18787
```

访问 ChatGPT和 Gemini。代理内部使用 Cloudflare DoH解析公共域名，不修改系统 DNS。`*.cambricon.com` 强制绕过代理。

aTrust登录期间不要用普通 Chrome访问公共 AI网站。

### 3. 快速退出

从应用菜单打开“aTrust 快速退出”并完成管理员授权。该入口会：

1. 关闭专用 Chrome；
2. 停止18787代理；
3. 停止并清理 aTrustAgent、aTrustXtunnel和 aTrustTray；
4. 删除残留 `utun*` 接口及其关联路由；
5. 刷新 systemd-resolved缓存；
6. 重启普通 Chrome的 NetworkService，清除旧 DNS和 socket，但不关闭普通 Chrome标签页。

完成通知出现后，普通 Chrome应立即恢复原网络环境。

## 安全边界

- 不修改 `/etc/resolv.conf`；
- 不修改公司 DNS服务器；
- 不修改默认路由；
- 不设置桌面全局代理；
- 不删除 aTrust原厂安装文件；
- 只有执行“快速退出”时才删除 `utun*`，此时 aTrust已停止。

## 安装与更新

审查本目录内容后执行：

```bash
sudo /bin/bash ./其他/atrust-tools/install-final-mode
```

该命令会安装最终入口，并删除旧的 split、路由守护、DoH、DNS测试及 Codex/VS Code代理脚本。

## 故障处理

若“aTrust 专用 Chrome”不能访问公共 AI网站：

```bash
ss -lntp | grep 18787
```

若“快速退出”后普通网络仍异常，先完全重启普通 Chrome；仍未恢复时检查：

```bash
resolvectl status
ip route show default
```

不得通过更换全局 DNS解决。
