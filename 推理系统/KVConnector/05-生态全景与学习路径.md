## 5.2 推荐拆解顺序

### 第一阶段：吃透抽象

看 `KVConnectorBase_V1`（[03](./03-工作原理-KVConnectorBase_V1.md)），重点：

```
KVConnectorBase_V1
├ Scheduler Connector
└ Worker Connector
   ├ get_num_new_matched_tokens()
   ├ start_load_kv() / wait_for_layer_load()
   ├ save_kv_layer() / wait_for_save()
   └ request_finished() / get_finished()
```

> 目标：明白 vLLM Core 和外部 KV 系统的边界在哪里。

### 第二阶段：MooncakeConnector

与当前 PD 场景最直接相关。

> 目标：完整画出一次 Prefill → Decode 的 KV 数据流和控制流（见 [04 §4.1](./04-典型示例.md)）。

### 第三阶段：当前 MLU KVOffload 实现

不要先照 upstream 猜。直接从指标反查：

```
vllm:kv_offload_total_bytes_total{transfer_type="MLU_to_CPU"}
vllm:kv_offload_total_bytes_total{transfer_type="CPU_to_MLU"}
```

分别在 vLLM-MLU 分支找 `.inc()` 调用位置。

> 目标：明确当前寒武纪版本 Store / Load 的真实触发条件。

### 第四阶段：MooncakeStoreConnector

> 目标：明白 External Prefix Cache 从"单机 CPU Cache"扩展成"分布式 KV Pool"后发生了什么。重点：Hash、Lookup、Put/Get、Store namespace、TP shard。

### 第五阶段：LMCache

> 目标：从另一个成熟实现观察 KV Cache 服务化、多级存储和跨实例复用。

### 第六阶段：NIXL

> 目标：深入 KV Transfer 数据面与 RDMA/UCX 等高性能通信。细节见 [`../其他细节/PD分离/Nixl/Nixl握手.md`](../其他细节/PD分离/Nixl/Nixl握手.md)。

### 第七阶段：MultiConnector

最终把 PD Transfer + External Prefix Cache + KVOffload + 多级 KV Cache 组合起来理解。

## 5.3 拆每个 Connector 的 10 问 Checklist

固定用这套问题拆源码：

1. **它解决什么问题？** — PD Transfer？External Cache？CPU Offload？Distributed Store？
2. **KV 存在哪里？** — Device？CPU？Remote DRAM？SSD？
3. **KV 的 Key 是什么？** — Token Hash？Block Hash？Request ID？Model/TP/PP/Rank 是否进 Key？
4. **什么时候 Lookup？**
5. **什么时候 Store？**
6. **什么时候 Load？**
7. **什么时候 Evict / Free？**
8. **Scheduler 和 Worker 分别负责什么？**
9. **数据传输协议是什么？** — memcpy / RDMA / UCX / NIXL / Mooncake Transfer Engine
10. **有哪些指标能证明数据链真的执行了？** — External Hit Tokens、Store/Load Bytes、Transfer Latency/Failure、Preemption、TTFT/TPOT/ITL

## 5.4 当前 MLU 环境关注顺序

结合真实监控，优先串：

```
External Prefix Cache Queries
        ↓
External Prefix Cache Hits
        ↓
CPU → MLU Load Bytes          # 验证 Lookup → Hit → Load
        ↓
Prefill Compute → MLU → CPU Store Bytes   # 验证 Compute → Store
        ↓
num_preemptions               # 明确 KVOffload ≠ Request Preemption
        ↓
Prefill → Decode KV Transfer Bytes / Latency / Failure   # PD 链路
```

最终形成 `External Cache → Prefill → PD Transfer → Decode` 的一整套 KV 数据面监控。
