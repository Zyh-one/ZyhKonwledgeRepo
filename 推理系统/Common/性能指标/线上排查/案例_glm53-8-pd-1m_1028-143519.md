## 2. 现象 → 证据对账表

| 观测 | glm53-8-pd-1m prefill | glm53-pd-1026 prefill | glm52-8-pd-1026 prefill |
|---|---|---|---|
| KV 使用率 | avg **0.089%** max 0.73% | avg **10.5%** max 47% | avg **11.8%** max 59% |
| 请求速率 | ~10 req/min | ~28 req/min | ~17 req/min |
| prompt 长度 | 9.6 万 token/req | 8.8 万 token/req | 8.8 万 token/req |
| 缓存 token 占比(cached/prompt) | **97.4%** | 93.8% | 91.8% |
| 每请求新算 KV(computed_sum/count) | **2512 token** | 5410 token | 7246 token |
| TTFT avg / max | **2.0s / 6.5s** | 3.8s / **65.9s** | 3.6s / **62.4s** |
| waiting avg / max | **0.04 / 1.1** | 1.33 / 18.1 | 1.25 / 36.1 |
| offload 字节(store vs load) | store 8.0e12 ≫ load 1.5e11 | load 1.8e15 ≫ store 2.4e13 | load 1.0e15 ≫ store 2.2e13 |
| decode KV 使用率(对照) | avg 8.1% max 38%(正常) | avg 11.8% max 33% | avg 27.4% max 80% |

**关键推算**:1m 服务 prefill 峰值在用量 = 0.73% × 38.4 万 ≈ **2800 token ≈ 单请求新算量(2512)**;若按 stock vLLM "命中块也被请求引用"的语义,96k token 请求即使只驻留 0.5s,均值也应 ≈ 2%(实测 0.089%,差 25 倍,且 21ms 驻留在物理上不可能)。→ **该服务引擎上 prefix 命中块的 KV 不占 GPU 池**(从 offload 层直传/流出),GPU 块只短暂承载新算部分。1026 两服务则相反:整段 KV(含命中前缀)驻留 GPU 池约 0.8s/请求,且 offload 流量为 load 主导(命中 KV 从共享层读入 GPU)。

**最终结论**:prefill KV 使用率 ≈ 0 是"97% prefix 命中 + shfs 连接器 + 命中块不占 GPU 池"组合的**正常形态,非故障**——该服务恰是三者中最健康的(TTFT 最低、零排队)。1026 服务 non-zero 同为正常形态,但其出现的排队/T 尾(waiting max 18~36、TTFT max 60s+)与 MAX_NUM_SEQS=4、整段 KV 驻留 GPU 的形态叠加负载(~3× 请求速率)相关,是另一条需要关注但独立的线索。

## 3. 待确认项(已超出只读指标范围)

1. 模型包 0.0.1076 → 0.0.1078 之间,prefix 命中块"是否驻留 GPU 池/是否计入 kv_cache_usage_perc"的行为改动——建议与引擎侧对 changelog。
2. BLOCK_SIZE 16 → 256 变更的动机及其对 shfs 传输粒度/驻留时长的影响。
3. 1026 服务 prefill MAX_NUM_SEQS=4 是否为排队长尾的约束来源(负载受控复测可区分"引擎行为回退"与"负载差异")。

## 4. 方法论沉淀

1. **KV 使用率 ≈ 0 先查流量再定性**:本次若只看曲线会误判"服务没在干活";prompt_tokens/success/TTFT 正常即排除故障。
2. **该指标对 prefix 命中块不可见**(无引用即 free),"命中块是否驻留 GPU"在不同引擎构建间可能不同——跨服务对比 KV 使用率前,先核对模型包构建号与 BLOCK_SIZE/MAX_NUM_SEQS 等 env。
3. `vllm:request_prefill_kv_computed_tokens_sum/count`(Histogram 家族)给出"每请求新算 token 数",与 KV 使用率峰值互验是判定"池里只有新算块"的最快手段。
4. `vllm:kv_offload_store/load_bytes_total` 的方向不对称(store≫load vs load≫store)可作为 KV 数据路径(直传 vs 经 GPU 暂存)的旁证。
5. 候选新签名:**PD prefill KV 使用率 ≈ 0 + 流量/TTFT 正常 + 高 cached 占比 → 命中块不经 GPU 池的直传形态(非事件)**;建议复核后升入词典统计假象清单。
