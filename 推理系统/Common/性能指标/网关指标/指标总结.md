# 网关指标分类总结

本文只总结当前平台网关监控代码已经实际使用的原始指标，包括指标分类、含义、类型、单位、主要标签和判读边界，不展开 PromQL，也不收录尚未接入的连接、控制面、运行时等扩展指标。

整理依据为当前 `zyh/gateway-metrics` 工作区的 `gw-query.constant.ts` 和网关监控组件，共 **11 个原始指标**。本文不涉及集群查询，也不包含 vLLM 推理引擎内部指标。

## 1. 分类总览

| 分类 | 指标数 | 来源组件 | 主要观察对象 |
| --- | ---: | --- | --- |
| 路由与前缀索引 | 4 | AIBrix gateway-plugins | balanced 本地前缀元数据容量、前缀索引可用性 |
| 入口请求与结果 | 3 | Envoy Proxy downstream | 客户端到网关的请求量、响应结果和在途请求 |
| 上游转发、时延与健康 | 4 | Envoy Proxy upstream | 网关到上游服务的请求、时延和成员健康 |
| **合计** | **11** |  |  |

## 2. 路由与前缀索引

### 2.1 Balanced 本地前缀索引

以下三个指标都属于当前内部 AIBrix 实现的 **balanced 路由专属指标**，受 `AIBRIX_BALANCED_LOCAL_ROUTER_METRICS_ENABLED` 开关控制，并在 balanced 本地路由决策路径中更新。

| 指标 | 类型 | 原始单位或范围 | 含义 |
| --- | --- | --- | --- |
| `aibrix_balanced_local_prefix_cache_usage_ratio` | Gauge | 比率，通常为 0～1 | 单个 gateway-plugins 副本的本地前缀哈希 LRU 索引条目容量使用率，即 `entries / capacity` |
| `aibrix_balanced_local_prefix_cache_entries` | Gauge | entry | 单个 gateway-plugins 副本当前保存的 prefix hash entry 数 |
| `aibrix_balanced_local_prefix_cache_capacity` | Gauge | entry | 单个 gateway-plugins 副本的本地前缀哈希 LRU 索引条目容量上限 |

共同特征与边界：

- 每个 gateway-plugins Pod 都维护独立的本地索引，多副本之间不是一份共享缓存。
- entries 是前缀哈希元数据条目数，不是 token 数、请求数或 vLLM KV block 数。
- capacity 是条目数上限，不是内存字节数、GPU 显存容量或 vLLM KV Cache 容量。
- usage ratio 达到 1 表示本地 LRU 元数据容量已满，后续插入可能驱逐旧条目；不表示请求失败或 GPU 显存已满。
- usage ratio 下降只能直接说明 entries 减少或 capacity 增大，不能仅凭该指标判断具体原因。
- 这三个指标描述的是**网关用于路由决策的前缀元数据**，不能说明真实 vLLM 是否命中已有前缀、复用了多少 KV Cache，也不能推导 Prefix Caching 命中率。
- 指标为全局、model-agnostic 口径，没有模型标签；其他路由算法不经过这组指标的更新路径。

**主要定位标签：** `cluster`、`namespace`、`job`、`pod`；完整序列身份以实际裸样本标签为准。

### 2.2 前缀索引可用性

| 指标 | 类型 | 原始单位或范围 | 含义 |
| --- | --- | --- | --- |
| `aibrix_prefix_cache_indexer_status` | Gauge | 状态值，1=可用、0=不可用 | 表示 AIBrix 前缀索引是否可用，通过 `indexer_type` 区分索引类型 |

已知 `indexer_type`：

| 标签值 | 含义 |
| --- | --- |
| `local` | 本地前缀索引 |
| `sync` | 同步前缀索引 |

该指标回答“索引是否可用”，与 balanced 三项回答“本地索引容量用了多少”不是同一问题。它不属于 balanced 专属指标；无返回序列时也不能直接解释为状态 0。

**主要定位标签：** `cluster`、`namespace`、`job`、`pod`、`indexer_type`。

## 3. 入口请求与结果

这里的 downstream 指 **客户端 → Envoy Proxy**。

| 指标 | 类型 | 原始单位 | 含义 |
| --- | --- | --- | --- |
| `envoy_http_downstream_rq_total` | Counter | request | Envoy HTTP Connection Manager 累计接收的下游请求数，可用于观察请求增量和请求速率 |
| `envoy_http_downstream_rq_xx` | Counter | request | 按响应码类别累计统计下游请求，用于观察 2xx、3xx、4xx、5xx 的分布 |
| `envoy_http_downstream_rq_active` | Gauge | request | Envoy 当前正在处理的下游请求数，反映在途请求或并发状态 |

判读边界：

- `envoy_http_downstream_rq_total` 是进程累计值，不是某个图表时间窗内天然存在的请求总量；进程重启会影响原始读数。
- `envoy_response_code_class` 的原始标签值为 `"2"`、`"3"`、`"4"`、`"5"`，分别对应 2xx、3xx、4xx、5xx，不是 `"2xx"` 等字符串。
- 当前平台把 2xx 和 3xx 计入网关 HTTP 成功率，但该成功率不等于模型推理业务成功率。
- 2xx 不能单独证明流式响应完整结束或模型输出满足业务要求；4xx/5xx 也需要结合具体路由和上游响应继续定位。
- active 表示尚未处理完成的在途请求，不是窗口内累计完成的请求数。其升高可能来自到达流量增加，也可能来自上游处理变慢。
- 这些指标没有模型或租户 `label_id`、`label_version` 维度。

**主要定位标签：** `cluster`、`namespace`、`pod`、`envoy_http_conn_manager_prefix`；响应码指标另带 `envoy_response_code_class`。

## 4. 上游转发、时延与健康

这里的 upstream 指 **Envoy Proxy → 上游服务**。`envoy_cluster_name` 是 Envoy 配置中的 upstream cluster 名称，不是 VictoriaMetrics 的 `cluster` 标签，也不能默认等同于模型名。

| 指标 | 类型 | 原始单位 | 含义 |
| --- | --- | --- | --- |
| `envoy_cluster_upstream_rq_total` | Counter | request | 发往各上游 cluster 的累计请求数，用于观察上游请求增量和请求速率 |
| `envoy_cluster_upstream_rq_time_bucket` | Histogram Bucket Counter | 每个桶的样本值为 request；`le` 为 second | 按累计时延桶记录上游请求耗时的观测数，用于估算上游请求时延分布和分位数 |
| `envoy_cluster_membership_healthy` | Gauge | member | 当前 Envoy 副本观察到的某个上游 cluster 的健康成员数 |
| `envoy_cluster_membership_total` | Gauge | member | 当前 Envoy 副本观察到的某个上游 cluster 的成员总数，是计算健康比例的总量依据 |

判读边界：

- 上游重试可能使一次下游请求产生多次上游请求，因此上游请求量不要求与下游请求量相等。
- `envoy_cluster_upstream_rq_time_bucket` 的 `le="+Inf"` 桶包含全部观测；分位数来自桶分布估算，受 bucket 边界和桶内插值影响。
- 当前只使用上游时延 `_bucket`，没有对应的 `_sum` 和 `_count`，不能据此计算精确平均时延。
- 健康成员数和成员总数都是单个 Envoy 副本的观察值。多 Envoy 副本可能重复观察同一批上游成员，跨副本求和不一定等于全局去重后的物理实例数。
- 健康比例描述健康成员占成员总数的比例，不表示“窗口内所有实例始终健康的时间占比”。
- 这些指标没有模型或租户维度；上游 cluster 与具体模型的对应关系必须以实际 Envoy 配置为准。

**主要定位标签：** `cluster`、`namespace`、`pod`、`envoy_cluster_name`；时延桶另带 `le`。

## 5. 统一口径与排除范围

### 5.1 标签口径

- `cluster` 是监控抓取链路注入的集群标签。
- `namespace` 是网关系统组件所在的 Kubernetes namespace，不是租户业务 namespace。
- `job` 用于区分采集目标；AIBrix 路由与前缀索引指标当前对应 `aibrix-gateway-plugins`。
- `pod` 用于区分具体组件副本。本地前缀索引、活跃请求和成员健康等指标都需要注意副本口径。
- 当前网关指标没有租户 `label_id`、`label_version` 等标签，不能按租户或模型直接拆分。

### 5.2 不属于本文的指标

- vLLM TTFT、TPOT、E2E、Prefix Caching 命中率和 KV Cache 使用率属于**推理引擎指标**，不是网关指标。
- 下游或上游连接、监听器、controller reconcile、workqueue、Kubernetes API client、Go/process/Envoy 运行时指标当前未被平台网关监控代码实际使用，因此不在本文 11 个指标之内。
- 请求总量、QPS、成功率、时延分位数和健康比例等是由上述原始指标计算得到的展示结果，不重复计为新的原始指标。
