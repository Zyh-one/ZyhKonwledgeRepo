# GLM-5.2 张量维度变化流程

本文回答一个问题：**一个 token 从进入 GLM-5.2 到吐出 logits，每一步算子拿到什么形状的张量、乘了什么形状的权重**。GLM-5.2 与 GLM-5.3 是同架构（`GlmMoeDsaForCausalLM`，两份 config.json 仅差 `moe_router_dtype` 等三个非维度字段，已逐字段 diff 确认），因此本文的维度体系与 [GLM-5.3 架构拆解](../GLM-5.3/GLM-5.3.md) 完全一致，但视角不同：那篇按模块拆结构，本文按**前向数据流**走一遍主线。

# 1. 全程总览

```text
ids [B, T]
  │ Embedding
  ▼
x [B, T, 6144] ──────────────┐
  ▼ 78 × Transformer 层       │ 残差流全程 [B, T, 6144] 不变
  每层: RMSNorm → MLA+DSA 注意力 → 残差
        RMSNorm → dense MLP(前3层)/MoE(后75层) → 残差
  ▼ ─────────────────────────┘
final RMSNorm → LM Head → logits [B, T, 154880]
  │（Decode 时）
  ▼ 采样出 token_t；最后层 hidden h_t 同时送入 MTP 层（第 79 层）
MTP: concat[emb(token_t), h_t] → 1 个 Transformer 块 → 共享 LM Head
     → draft 出后续 token，与主模型一次 forward 逐位校验   (§5)
```

维度主线只有一条：除 LM Head 出口外，**所有张量都围绕 `[B, T, 6144]` 展开又收回**，中间在注意力/MoE 内部短暂进入头维、潜维、专家中间维。与 [Transformer 自回归生成的最小闭环](<../../推理算法/0-Transformer 自回归生成的最小闭环.md>) 的通用主线一致。

# 2. 入口：Embedding

`ids [B, T]`（int64）→ 查表 `W_embed [154880, 6144]` → `x [B, T, 6144]`（bf16）。

`tie_word_embeddings=false`，LM Head 是独立权重（见 §8），Embedding 只在 Prefill 开头执行一次；Decode 每步只查 1 行。

# 3. 每层内部（78 层循环）

## 3.1 输入 RMSNorm

`rms_norm(x, γ∈[6144], eps=1e-5)`：`[B, T, 6144] → [B, T, 6144]`，逐 token 归一。无 bias（`attention_bias=false`）。

## 3.2 MLA：Q 路径（不缓存）

```text
x [B,T,6144] × W_dq  [2048, 6144]  → c_q   [B, T, 2048]    Q 潜变量
(合理推断) q-norm: rms_norm(c_q, γ_q∈[2048])  （DeepSeek-V3 同款）
c_q × W_uq [16384, 2048] → 拆头:
  Q_nope [B, T, 64, 192]   (64×192 = 12288 段)
  Q_rope [B, T, 64, 64]    (64×64  = 4096 段)
Q_rope 经 RoPE(theta=8e6) 旋转 → Q̃_rope [B, T, 64, 64]
```

## 3.3 MLA：KV 路径（压缩进 Cache 的部分）

```text
x [B,T,6144] × W_dkv [576, 6144] → 拆:
  c_kv  [B, T, 512]   ★KV 潜变量（缓存主体）
  k_rope_raw [B, T, 64]（解耦位置段）
(合理推断) kv-norm: rms_norm(c_kv, γ_kv∈[512])
k_rope_raw 经 RoPE(theta=8e6) → k_rope [B, T, 64]（单独缓存）
```

`W_dkv` 输出 576 = 512 + 64，一次投影同时产出潜变量与解耦位置键，这是 MLA 压缩 KV 的核心（动机见 [MLA动机](../../推理算法/自注意力模块/存储轴/MLA动机.md)，张量细节见 [MLA](../../推理算法/自注意力模块/存储轴/MLA.md)）。

## 3.4 DSA 索引器（选 token）

`indexer_types` 逐层标注，本 config 实测（已确认）：**21 层 full**（层 0,1,2,6,10,…,74，即前 3 层 + 之后每 4 层一次，对应 `index_topk_freq=4`）+ **57 层 shared** 复用相邻 full 层的索引（复用机制为合理推断，`index_share_for_mtp_iteration=true` 暗示索引可跨层/MTP 共享）。

```text
x [B,T,6144] × W_qidx [4096, 6144] → Q_idx [B, T, 32, 128]
x [B,T,6144] × W_kidx [4096, 6144] → K_idx [B, T, 32, 128]  (32 头×128 维)
head 平均打分: S = (1/128)·Σ_h Q_idx,h · K_idx,hᵀ ∈ [B, T, L]   (合理推断)
topk(S, k=min(L, 2048)) → 索引 I ∈ [B, T, 2048]                 (index_topk=2048)
```

L ≤ 2048 时无需稀疏，退化为全量因果注意力（`index_skip_topk_offset=3` 的语义尚待确认，数值恰好等于前 3 个 full 层）。共享层不重复执行以上投影，直接用 I。运行时语义（稀疏粒度、RoPE 位置感知、shared 复用细节、与 MTP 的索引共享）展开见 §6。

## 3.5 注意力计算：Prefill 与 Decode 两条路

**Prefill（T=S，先算后切）**——显式还原 K/V 再做标准注意力：

```text
c_kv [B,S,512] × W_uk [12288, 512] → K_nope [B, S, 64, 192]
c_kv [B,S,512] × W_uv [16384, 512] → V      [B, S, 64, 256]
Q = [Q_nope; Q̃_rope] [B, S, 64, 256]，K = [K_nope; k_rope 广播到 64 头]
score = Q·Kᵀ/√256 + (因果掩码 + 按 I 屏蔽)   ∈ [B, 64, S, min(S,2048)]
O = softmax(score)·V                        ∈ [B, S, 64, 256]
```

**Decode（T=1，权重吸收，不还原 K/V）**——已确认机制、形状为合理推断：

```text
吸收 K 侧:  Q_abs,h = Q_nope,h · W_uk,hᵀ        [192→512] → [B,1,64,512]
score = Q_abs,h · c_kvᵀ + Q̃_rope,h · k_ropeᵀ    (按 I gather 2048 行)
O_latent,h = softmax(score)·c_kv(gathered)        ∈ [B, 1, 64, 512]
吸收 V/O 侧: 输出 = Σ_h O_latent,h · (W_uv,h · W_o,h)   [512→6144/头]
```

吸收的收益：Decode 全程不出现 16384 维的展开 K/V，与 Cache 里的 512 维潜变量直接点积（详见 [MLA](../../推理算法/自注意力模块/存储轴/MLA.md) §4；RoPE 段因旋转的非线性无法吸收，单独保留——这是 `qk_rope_head_dim=64` 独立存在的原因）。

## 3.6 输出投影与残差

`O [B, T, 64, 256]` reshape `[B, T, 16384]` × `W_o [6144, 16384]` → `attn_out [B, T, 6144]`；残差：`x1 = x + attn_out`。

## 3.7 第二个 RMSNorm + FFN

**前 3 层 dense（已确认，`first_k_dense_replace=3`）**，SwiGLU：

```text
x1n [B,T,6144] × W_gate/W_up [12288, 6144] → G, U [B, T, 12288]
Y = (silu(G) ⊙ U) × W_down [6144, 12288]    → [B, T, 6144]
```

**后 75 层 MoE**（结构见 [MoE](../../推理算法/MLP模块/MoE/MoE.md)）：

```text
路由: x1n × W_route [256, 6144] (+b∈[256]) → logits [B,T,256]
     sigmoid → scores；topk-8 → 索引 [B,T,8] + 分数 [B,T,8]
     分数归一(norm_topk_prob) 后 × routed_scaling_factor=2.5     (已确认)
共享专家(每 token 必激活): x1n × [2048,6144]×2 + [6144,2048] → [B,T,6144]
路由专家(256 选 8): 同形状 SwiGLU，按 top-8 索引 gather 后分组 GEMM
Y_moe = 2.5·Σ_k p̄_k·Expert_k(x1n) + Shared(x1n)               → [B,T,6144]
```

`topk_method=noaux_tc`：路由 bias 只用于负载均衡、不参与打分（DeepSeek-V3 同款，合理推断）。`n_group=1 / topk_group=1`：DeepSeek-V3 的分组路由退化档（不分组、无组内筛选，即此二字段为占位值，已确认无实际作用）。单 token 每 FFN 的活跃中间维 = (8 路由 + 1 共享) × 2048 = 18432，对比 dense 层 12288——MoE 省的是**参数的稀疏激活**，不是单步 FLOPs（此处与直觉相反，值得注意）。

残差：`x_out = x1 + Y`，交下一层。

# 4. 78 层之后：出口

`final rms_norm`（`γ∈[6144]`）→ `× W_head [154880, 6144]` → **logits `[B, T, 154880]`**。Decode 每步只需最后一行 `[B, 1, 154880]` 做采样，其余行的 LM Head 计算可跳过（Prefill 通常也只算最后若干 token 的 logits）。

Decode 采样得到 `token_t` 后，最后一层 hidden `h_t [B, 1, 6144]` 与 `emb(token_t)` 一并送入 **MTP 层（第 79 层）**做 draft——这是投机解码在线上实际启用的路径，单独成节（§5）。

# 5. MTP draft 路径（第 79 层，投机解码）

config 证据（已确认）：`num_nextn_predict_layers=1`。机制骨架沿用 DeepSeek-V3 的 MTP/nextn 设计（合理推断），其中**权重共享部分已由线上 vLLM 加载日志实证**（来源见本节末）。推理算法目录暂无 MTP 专文，本节把基础与实例一并展开。

## 5.0 基础：为什么需要投机解码

Decode 的固有矛盾：每步只为 1 个 token 走完整 78 层 + LM Head（154880×6144 的巨型投影），算子并行度极低、访存占满带宽（§3.5 的 Decode 吸收路径已把算力压到最低，剩下的瓶颈是**访存**）。投机解码（speculative decoding）用两段式换吞吐：

1. **draft（便宜地猜）**：一个小过程连出 γ 个候选 token；
2. **verify（一次校验）**：主模型一次 forward 同时算 `[token_t, d⁽¹⁾, …, d⁽ᵞ⁾]` 共 1+γ 个位置——批内并行，摊薄了每 token 的权重访存——逐位比对，接受到第一个不匹配处。

关键性质：greedy 采样下逐位取 argmax 比对，**输出与不投机完全一致（无损）**；带温度采样时用拒绝采样修正分布，同样无损。代价只是 draft 的额外计算与 verify 时多算几个位置——接受率足够高时净赚。

MTP 作 draft 的独特之处：draft 模型不是独立小模型，而是主模型自带的 1 个「下一 token 预测层」，**与主模型共享 embedding 与 lm_head**——参数量约为主模型的 1/78，且训练目标就是预测下一 token，天然对齐。

## 5.1 MTP 模块结构（第 79 层）

```text
输入拼接:  concat[emb(token_t), h_t]  [B, 1, 12288]
           （共享主模型 W_embed 查表；h_t 为主模型最后层 hidden）
投影:      × W_comb [6144, 12288] → h' [B, 1, 6144]      (合理推断，DeepSeek-V3 记法
                                                          为两个 [6144,6144] 分乘后相加)
1 × Transformer 块（与主层同构：RMSNorm → MLA+DSA → RMSNorm → MoE）
共享主模型 final RMSNorm → 共享 LM Head W_head [154880, 6144] → draft logits [B, 1, 154880]
```

权重共享**实证**（OpenSearch paas 日志，cambricon-paas-2026.10.08，glm53-1m-500-8192 服务，vLLM `llm_base_proposer.py`）：

- `:1469 Detected MTP model. Sharing target model embedding weights with the draft model.`
- `:1545 Detected MTP model. Sharing target model lm_head weights with the draft model.`
- `:1569 Shared target model lm_head with MTP shared_head.head.`（给出权重命名：`MTP shared_head.head`）
- P、D 两侧每个 Worker（TP/DCP/EP 分组各进程）都会构建 proposer 并打印以上三行。

## 5.2 draft–verify 完整张量流（Decode 一个投机步）

以在线引擎实测 `num_speculative_tokens=2`（γ=2）为例：

```text
① 主模型 decode 一步:  h_t → logits → 采样 token_t
② draft（链式迭代 2 轮，单层复用）:
     轮1: concat[emb(token_t), h_t]   → MTP 层 → logits₁ → d⁽¹⁾
     轮2: concat[emb(d⁽¹⁾), h⁽¹⁾]     → MTP 层 → logits₂ → d⁽²⁾
③ verify（主模型一次 forward, T = 1+γ = 3）:
     输入 [token_t, d⁽¹⁾, d⁽²⁾] 走完整 78 层 → logits [B, 3, 154880]
④ 逐位校验（greedy）: 位置1的 argmax == d⁽¹⁾ ? 位置2的 argmax == d⁽²⁾ ?
     接受到第一个不匹配处，得接受长度 k（0 ≤ k ≤ γ）
⑤ 下一个 token 直接取 verify forward 第 k+1 行的采样结果——该步主模型免跑
```

一个投机步最多前进 `1+γ` 个 token（verify 校验本身产出的正确 token 计入），最少前进 1 个（全拒时退化为普通 decode，只多付 γ 个位置的 forward）。注意 ③ 中 T=3 的 forward 是 prefill 式批内并行——**这正是引擎把 `max_num_scheduled_tokens` 自动压到 128 的原因**（见 §5.4）。

单层 MTP 为何能链式出 γ 个 draft：每轮以「上一轮 draft token 的 embedding + 上一轮 MTP 输出 hidden」为输入再前向一次。config 的 `index_share_for_mtp_iteration=true` 即指这些迭代轮次间**共享 DSA 索引**（draft 轮次的 query 变了但复用已选好的 key 索引，省索引开销——合理推断）。

## 5.3 MTP 层的 KV Cache

MTP 层同样维护自己的 `c_kv [512]` / `k_rope [64]`（draft 轮次要读写历史；verify 接受的 token 也会在 MTP 层补写 KV）。核算口径 78→**79 层**，见 §7。

MTP 层的 indexer 类型**未知**：`indexer_types` 数组只有 78 项、未覆盖第 79 层（尚待确认；`index_share_for_mtp_iteration` 的字面含义支持「MTP 层复用主模型 full 层索引」的实现，但引擎实际行为未取证）。

# 6. DSA 索引器的运行时细节（§3.4 深化）

§3.4 给出了索引器张量流，这里补运行时语义。证据基础：config 字段（已确认）+ DeepSeek-V3.2 同款设计（合理推断）；**DSA 的引擎侧加载/执行日志未在 OpenSearch 命中**，以下机制性结论均按推断标注。

1. **稀疏粒度是 token 级，不是块级**。打分 `S ∈ [B, T, L]` 对「当前 token × 全部历史 token」逐对进行，topk 直接选出 2048 个 key **token**。这与块级稀疏（如 NSA 先选块再取块内 token）是两类设计——GLM 的 `index_topk=2048` 是无块对齐的逐 token 选择，代价是索引/gather 不规则，收益是选择精度。
2. **索引键带位置信息**。`indexer_rope_interleave=true`：索引器的 Q/K 施加 interleave 式 RoPE——打分能感知 query-key 距离（近处 token 天然倾向更高分），与主注意力的 `rope_interleave=true` 同款配对方式。位置感知的索引器本质上是个「学习出来的检索器」，RoPE 让它可以学到局部性先验。
3. **shared 层复用的具体内容**（合理推断）：shared 层没有自己的 indexer 权重，Q_idx/K_idx 投影与打分全部复用最近的前一个 full 层——即 57 个 shared 层既不重投影也不重打分，直接拿 full 层选好的索引 I 用在自己层的 MLA 注意力上。若此推断成立，`W_qidx/W_kidx` 全网只有 21 份（21 个 full 层各一），DSA 的「有效层数」是 21 不是 78。
4. **topk 的执行语义**：打分先加因果掩码（只对 L 个历史位置），再取 `k = min(L, 2048)`；L ≤ 2048 时退化为全量因果注意力（§3.4 已述）。`index_skip_topk_offset=3` 语义尚待确认——数值恰好等于前 3 个 full 层（层 0,1,2，同时是 3 个 dense 层），一种候选解释是「前 3 个 full 层跳过 topk 直通全量」，但 config 无文字佐证。
5. **与 MTP 的耦合**：`index_share_for_mtp_iteration=true`——draft 链式迭代轮次间共享索引（§5.2），避免每轮重投影 K_idx + 重打分。索引复用横跨两个维度：**层间**（shared 层，21 份索引服务 78 层）与**迭代间**（MTP 轮次），这解释了 GLM 敢把 index_topk 提到 2048 的成本底气。
6. **gather 的落点**：选出的索引 I 最终用在两处——Prefill 显式路径按 I 屏蔽 score（§3.5 上图），Decode 吸收路径按 I gather 2048 行 `c_kv` 潜变量直接点积（§3.5 下图）。注意力计算从 O(L) 降到 O(2048) 发生在**吸收路径之后**，与 MLA 权重吸收正交叠加。

# 7. KV Cache 落点与体积

进 Cache 的张量（bf16，2 B/元素）：

| 张量 | 形状/token/层 | 出现层 | 字节/token/层 |
|---|---|---|---|
| `c_kv`（kv-norm 后） | `[512]` | 全部 78 层 + MTP 层（§5.3） | 1024 B |
| `k_rope` | `[64]`（是否按头存属实现细节，合理推断单份） | 全部 78 层 + MTP 层 | 128 B |
| `K_idx`（索引键） | `[32, 128]` = `[4096]` | 仅 21 个 full 层（合理推断会缓存） | 8192 B |

核算（已确认代入、口径为合理推断）：

- MLA 主缓存：`(78+1) × 576 × 2 = 88.9 KB/token`（79 层口径，含 MTP 层）
- 索引缓存：`21 × 4096 × 2 = 168 KB/token`（MTP 层索引是否计入见 §5.3，未计入此数）
- 合计 **≈ 257 KB/token**；等价 MHA（64 头 × 256 维 K+V）为 `79 × 32768 × 2 = 4.93 MB/token`，压缩约 **19×**
- 每 1M token 上下文：约 245 GB——单卡不可容纳，1M 上下文必须依赖 PD 分离 + 多卡分 Cache（合理推断）

两个容易被忽略的体量事实：

1. **索引缓存比 MLA 主缓存还大**（168 vs 88.9 KB/token）。DSA 用 8 KB/token/层的代价把注意力算力从 O(S²) 降到 O(S·2048)，但索引键本身成为 Cache 第二大头——若引擎为省显存不缓存 `K_idx` 而 shared 层重算，则又牺牲算力，是部署上的真实权衡（尚待确认：serving 引擎的实际取舍）。
2. W4A8 量化不改形状，只改 kernel：专家权重 int4、其余权重与激活 int8（`only_expert_per_group=true`，已确认）。

# 8. 与 GLM-5.3 的关系及交叉关联

- 两份 config 仅异于 `moe_router_dtype: float32`（5.3 新增，路由打分升精度防 256 专家下 sigmoid 饱和，合理推断）、`transformers_version`、生成日期——**本文全部流程（含 MTP 与 DSA）对 GLM-5.3 同样成立**，模块级拆解见 [GLM-5.3 架构拆解](../GLM-5.3/GLM-5.3.md)。
- 逐轴深入：MLA 张量流 [存储轴/MLA](../../推理算法/自注意力模块/存储轴/MLA.md)；MoE 路由 [MLP模块/MoE](../../推理算法/MLP模块/MoE/MoE.md)；Prefill/Decode 两阶段与 Cache 的通用主线 [prefill_decode_kv_cache](../../推理算法/prefill_decode_kv_cache.md)。MTP 与 DSA 在推理算法目录尚无专文（路线图规划位 §7.2/§4.3），本文 §5/§6 为当前唯一实例展开。
- PD 视角：本文 §3.5 的两条注意力路径正是 Prefill 算力密集 / Decode 访存密集的根源；MTP（§5）只作用于 Decode 侧吞吐（TPOT），Prefill 侧加载 proposer 但不改变 TTFT 路径。衔接 [PD分离](../../其他细节/PD分离/PD分离.md)。
- PD 分离与 MTP 的叠加注意点（合理推断）：verify forward 的 KV 写入发生在 D 侧；P 侧若在 MTP 层写 KV，需与 KV connector 的传输对齐——线上 P 侧同样加载 proposer（5.1 实证）提示引擎在 P 侧也构建了 MTP 层，其在 P/D 协作下的 KV 一致性问题本文不展开。
