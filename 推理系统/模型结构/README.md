# 模型结构（infra 视角）

本文件夹从 **推理 infra / 系统** 的角度拆解各模型的内部模块：每个模块的结构、算法，以及它对**显存、KV Cache、访存、并行切分、量化**的实际影响。

## 与其他文件夹的分工

| 文件夹                               | 视角         | 关心什么                                                         |
| ------------------------------------ | ------------ | ---------------------------------------------------------------- |
| [推理算法](../推理算法/)              | 通用张量主线 | 单头/多头、Prefill/Decode、KV Cache 的张量怎么流                 |
| [自注意力模块](../推理算法/自注意力模块/) | 算法族分类   | 注意力三轴演进：MHA/MQA/GQA/MLA、RoPE                             |
| **模型结构（本文件夹）**       | 具体模型实例 | 某个真实模型里这些模块长什么样、参数是多少、对推理工程有什么影响 |
| [模型并行](../模型并行/)              | 多卡切分     | TP/EP/PP/CP/SP 怎么切                                            |

一句话：推理算法讲「张量怎么流的通用主线」，本文件夹讲「GLM-5.3 / DeepSeek-V3 / Qwen3 这些具体模型里，这些主线落到什么参数、什么结构、对推理部署意味着什么」。

## 条目

- [GLM-5.3](GLM-5.3.md) — `GlmMoeDsaForCausalLM`：MLA + DSA 稀疏索引注意力 + 256 专家 MoE + W4A8，78 层，1M 上下文
- [GLM-5.2](GLM-5.2/张量维度变化流程.md) — 与 GLM-5.3 同架构；从 token id 到 logits 的前向张量维度变化全流程（含 Prefill/Decode 两条注意力路径与 KV Cache 体积核算）

## 写作约定

- 每个模型一篇，按「整体层结构 → 逐模块拆解 → 推理 infra 影响汇总」组织。
- 参数值来自模型 `config.json` 等只读证据，标注 **已确认 / 合理推断 / 尚待确认**。
- 重点不是复述论文，而是回答 infra 问题：这个模块占多少显存？KV Cache 多大？切分点在哪？量化和长上下文怎么落地？
