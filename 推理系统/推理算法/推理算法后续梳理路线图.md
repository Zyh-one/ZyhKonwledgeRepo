# 推理算法后续梳理路线图

> 本文用于规划「推理算法」目录的后续建设顺序。重点不是按模型发布时间不断追加条目，而是先建立稳定的张量坐标系，再沿架构轴补齐机制，最后用代表模型验证这些机制能否组合成真实模型。
>
> 规划基准日期：2026-10-07。

---

# 1. 当前定位

当前目录已经较系统地覆盖了自回归 decoder-only Transformer 的基础张量主线：

- Token、Embedding、Transformer Layer 与 LM Head；
- Prefill、Decode 与 KV Cache；
- MHA、MQA、GQA 与 MLA；
- 基础 RoPE 与 MLA 的解耦 RoPE；
- 经典 MLP、GLU/SwiGLU 与基础 MoE；
- 注意力计算轴的概念分类。

因此，当前材料最准确的定位是：

> 已覆盖自回归 decoder-only Transformer 的基础张量流，并重点展开了注意力存储轴；下一阶段需要补齐统一张量口径、注意力计算轴和现代 Transformer Block 的结构变化。

目前不适合宣称“已覆盖所有开放权重模型架构”。主要缺口包括：

1. 标准注意力内部的完整计算步骤尚未展开；
2. 滑动窗口、稀疏索引、线性注意力仍停留在概念层；
3. Mamba/SSM 等非注意力序列混合器尚未覆盖；
4. Norm、Residual 和多分支残差尚未形成独立结构轴；
5. MoE 只覆盖了基础 top-k 骨架，尚未覆盖现代路由和推理调度；
6. MTP、条件记忆、多模态和扩散语言模型尚未进入当前主线。

---

# 2. 后续整理原则

## 2.1 先补坐标系，再补模型

后续不优先为每个新模型单独写一套完整结构，而是先回答：

```text
这个模型在注意力存储轴上选择了什么？
这个模型在注意力计算轴上选择了什么？
这个模型如何表达位置信息？
这个模型使用什么 MLP/MoE？
这个模型如何组织 Norm、Residual 和层间信息？
它是否增加了 MTP、条件记忆或多模态通路？
```

当通用机制完整后，具体模型文档只需要给出参数、组合方式和推理影响，不再重复解释基础算法。

## 2.2 张量流优先于名词罗列

每篇机制文档至少回答：

1. 输入张量是什么；
2. 新增了哪些权重和运行时中间量；
3. 每一步如何变换维度；
4. Prefill 与 Decode 是否走相同路径；
5. 跨 token 保存的状态是什么；
6. 相比基线节省了哪个量，又增加了哪个量；
7. 对 KV Cache、算力、带宽、并行和 kernel 有什么影响。

## 2.3 区分数学结构与工程布局

文档应明确区分：

- 数学形状：例如 `[B, Hq, Tq, Dqk]`；
- 逻辑布局：例如按 batch、head、sequence 观察；
- 物理布局：例如 packed tokens、paged blocks、head-major；
- kernel 融合：不改变数学结构，但改变中间张量是否物化；
- 模型架构：训练时已经定义的计算图；
- 推理优化：不改变数学结果的重排、吸收、量化和缓存。

## 2.4 使用“开放权重模型”而非笼统的“开源模型”

若只确认了权重、配置或推理代码公开，应称为“开放权重模型”。只有代码、许可证等满足对应开源定义时，才使用“开源模型”。

# 3. 第一阶段：统一张量坐标系

这是后续所有文档的前置任务。

## 3.1 新增《张量符号与推理阶段约定》

建议统一使用：

```text
B       : batch size
Tq      : Query token 数
Tkv     : 当前可见的 KV token 数
Hq      : Query head 数
Hkv     : KV head 数
Dqk     : Q/K head dimension
Dv      : Value head dimension
D       : residual stream / hidden size
P       : packed token 总数
L       : Transformer 层数
E       : 专家总数
K       : 每个 token 激活的专家数
W       : 滑动窗口宽度
R       : 递归状态或低秩潜变量维度
```

标准注意力统一写成：

```text
Q : [B, Hq, Tq,  Dqk]
K : [B, Hkv,Tkv, Dqk]
V : [B, Hkv,Tkv, Dv]

Score  : [B, Hq, Tq, Tkv]
Weight : [B, Hq, Tq, Tkv]
Output : [B, Hq, Tq, Dv]
```

必须明确 Prefill 与 Decode 的区别：

```text
Prefill:
Tq ≈ Tkv = 当前 Prompt 长度

Decode:
Tq = 1
Tkv = 历史长度 + 当前 token
```

## 3.2 补充真实推理布局

在数学形状之外，增加一节 packed/ragged/paged 表示：

```text
X             : [P, D]
cu_seqlens     : [B + 1]
slot_mapping   : [P]
block_table    : [B, max_blocks_per_sequence]
KV Cache       : [num_blocks, block_size, Hkv, Dqk/Dv]
```

这一节只解释数学张量如何映射到推理框架，不在此处展开 PagedAttention 的 block 分配策略。

## 3.3 阶段验收标准

- 后续文档不再用同一个 `S` 同时表示 Query 长度和 KV 长度；
- MHA、MQA、GQA、MLA 都能映射到 `Hq/Hkv/Dqk/Dv`；
- Prefill 与 Decode 的 Attention Score 形状可直接比较；
- 能解释普通 batch、packed batch 和 paged KV Cache 三种观察口径。

# 4. 第二阶段：完成注意力计算轴

注意力计算轴是下一阶段的核心主线，建议按由简单到复杂的顺序完成。

## 4.1 标准 Dense Attention 的完整计算

新增《标准注意力完整计算》；补齐当前 MHA 文档未展开的步骤：

```text
Q/K/V projection
→ optional QK-Norm
→ position transform
→ Q × K^T
→ scale
→ mask
→ optional logit softcap / sink
→ Softmax(dim=Tkv)
→ Weight × V
→ optional output gate
→ output projection
```

重点说明：

- `1/sqrt(Dqk)` 的来源和位置；
- Softmax 沿 `Tkv` 维计算；
- causal、padding、prefix、sliding-window mask 的区别；
- `Dqk` 和 `Dv` 不必相等；
- QK-Norm 不改变维度，但改变进入点积的数值；
- logit softcap、attention sink 与 output gating；
- Prefill 的 `[Tq,Tkv]` 和 Decode 的 `[1,Tkv]`；
- 哪些中间张量在 FlashAttention 中不会完整物化。

## 4.2 滑动窗口与 Local/Global Attention

新增《滑动窗口与局部全局注意力》：

```text
Dense Attention:
每个 Query 看全部 Tkv 个位置

Sliding Window:
每个 Query 只看最近 W 个位置

Local/Global Alternation:
多数层只看局部，少数层恢复全局访问
```

重点说明：

- causal sliding window 的可见区间；
- Prefill 从逻辑 `[T,T]` 变成带状稀疏矩阵；
- Decode 每步最多读取 `W` 个历史位置；
- rolling KV Cache 与仅减少 Attention 计算的区别；
- attention sink 为什么需要保留特殊位置；
- 模型按窗口训练与推理时强行截断并不等价；
- local/global 层如何组合全局信息。

代表模型：Mistral、Gemma、gpt-oss。

## 4.3 学习型稀疏索引注意力

新增《学习型稀疏索引注意力》，用统一框架覆盖 NSA、DSA、QSA、MoBA：

```text
Query / Hidden State
→ lightweight indexer
→ candidate score
→ top-k token/block indices
→ gather selected K/V
→ 对选中位置执行精确 Attention
```

统一张量示例：

```text
IndexScore : [B, Tq, Ncandidates]
TopKIndex  : [B, Tq, K]
K_selected : [B, Hkv, Tq, K, Dqk]
V_selected : [B, Hkv, Tq, K, Dv]
Score      : [B, Hq,  Tq, K]
```

重点说明：

- token-level、block-level 与混合选择；
- 索引器自身的计算成本；
- top-k 是固定预算，不代表索引过程免费；
- shared index、跨层复用和索引频率；
- Prefill 和 Decode 的索引路径差异；
- gather/scatter 带来的非连续访存；
- 稀疏 Attention 与 MLA/GQA 可以叠加，二者分别减少“读取位置数”和“每个位置的字节数”。

代表模型：DeepSeek DSA、GLM DSA、Qwen QSA、Kimi MoBA。

## 4.4 线性注意力通用框架

新增《线性注意力与递归状态》；先讲共同结构，再拆 Gated DeltaNet、KDA、Lightning Attention：

```text
q/k/v       : [B, H, T, D]
state       : [B, H, Dk, Dv]
decay/gate  : [B, H, T] 或 [B, H, T, Dk]
beta        : [B, H, T]
```

必须分别展开两条执行路径：

```text
Prefill:
整段序列
→ chunkwise parallel state update
→ 每个位置的输出
→ 最终 recurrent state

Decode:
当前 token + previous state
→ decay/read/write
→ 当前输出
→ new state
```

核心对比：

```text
Softmax Attention 保存逐 token 的 KV Cache；
线性注意力保存对历史进行压缩后的固定形状矩阵状态。
```

复杂度描述必须带限定：状态相对序列长度 `T` 为常数，但仍随 batch、层数、头数和 `Dk×Dv` 增长；Prefill 总计算仍随序列长度线性增长。

代表模型：Qwen3-Next、Qwen3.8、Kimi Linear/Kimi K3、MiniMax。

## 4.5 Mamba 与 SSM

新增《Mamba与状态空间模型》，不要直接把 SSM 等同于线性注意力：

```text
X
→ input projection
→ causal convolution
→ input-dependent SSM parameters
→ selective scan / recurrent update
→ gate
→ output projection
```

重点比较：

| 结构              | 跨 token 历史载体    | Decode 状态      |
| ----------------- | -------------------- | ---------------- |
| Softmax Attention | 逐 token KV          | 随上下文增长     |
| Linear Attention  | 矩阵递归状态         | 对上下文长度固定 |
| Mamba/SSM         | 卷积状态 + SSM state | 对上下文长度固定 |

代表模型：Mamba、Mamba-2、Jamba/Jamba2、Codestral Mamba。

## 4.6 阶段验收标准

- 能从 Dense Attention 推导出滑窗和 top-k 稀疏 Attention；
- 能区分“稀疏选择历史位置”与“把历史压成递归状态”；
- 能分别写出线性注意力的 Prefill 与 Decode 张量流；
- 能解释 Mamba state 与 KV Cache 的不同；
- 能用存储轴、位置轴、计算轴组合解释真实模型。

# 5. 第三阶段：补齐 Transformer Block 结构轴

注意力和 MLP 之外，Norm、Residual 与层间信息流已经成为独立架构变量。

## 5.1 Norm 与经典残差

新增《归一化与残差连接》：

- LayerNorm 与 RMSNorm；
- Pre-Norm 与 Post-Norm；
- Sandwich Norm；
- QK-Norm；
- residual scaling；
- 串行 Attention→MLP；
- parallel Attention/MLP。

统一基线：

```text
Pre-Norm:
y = x + F(Norm(x))

Post-Norm:
y = Norm(x + F(x))
```

## 5.2 多分支和跨层残差

新增《多分支残差与跨层信息流》：

- Gated Residual；
- Hyper-Connections / mHC；
- Attention Residuals；
- 多 residual stream 的 read/write；
- 跨 block 历史表示的选择和混合。

统一抽象：

```text
R_l : [B, T, M, D]       M 条残差分支
  → read/mix
x_l : [B, T, D]
  → F(x_l)
  → gated write/scatter
R_{l+1} : [B, T, M, D]
```

代表模型：Kimi K3、Qwen3.8-Flash-Next、GLM-5.3-Flash。

## 5.3 阶段验收标准

- 不再把 Norm/Residual 仅描述为“不改变形状”；
- 能比较单残差流与多残差流的状态量；
- 能标出 Attention、MLP 从哪条残差流读取、写回哪里；
- 能说明结构创新与 kernel fusion 的边界。

---

# 6. 第四阶段：深化 MoE

当前 MoE 文档已经覆盖基础的 `router → top-k → experts → combine`，后续分为算法篇和系统篇。

## 6.1 《MoE路由与负载均衡》

覆盖：

- Softmax routing 与独立 Sigmoid routing；
- top-1、top-2、top-4、top-8、top-16 等配置差异；
- routed experts 与 shared experts；
- fine-grained expert segmentation；
- auxiliary loss；
- auxiliary-loss-free correction bias；
- group-limited、node-limited routing；
- 路由选择权重与最终合并权重是否相同；
- capacity factor 与 token dropping。

不要再把 `k=2` 表述为当前统一主流值。`K` 是模型配置，当前开放权重模型存在多种取值。

## 6.2 《MoE推理张量与专家并行》

覆盖：

```text
Token hidden       : [P, D]
Router score       : [P, E]
TopK expert ids    : [P, K]
TopK weights       : [P, K]
Dispatch 后        : 每专家 [P_e, D]
Expert output      : 每专家 [P_e, D]
Combine 后         : [P, D]
```

重点说明：

- `P_e` 是运行时动态形状；
- token permutation、gather、scatter；
- grouped GEMM；
- Expert Parallel all-to-all；
- shared expert 与 routed expert 的并行路径；
- 权重显存、激活计算和通信量分别由什么决定；
- Stable LatentMoE 等专家前后共享投影结构。

## 6.3 阶段验收标准

- 能解释不同模型为何同为 MoE，却有完全不同的路由和通信行为；
- 能从 `[P,E]` 路由分数追踪到每个专家的动态 `[P_e,D]`；
- 能区分算法上的稀疏激活与系统上的 EP/Grouped GEMM。

# 7. 第五阶段：前沿独立模块

这些机制不应强行塞入 Attention 或 MLP，需要建立独立目录。

## 7.1 条件记忆与 N-gram 查表

新增 `条件记忆/`：

```text
token / n-gram ids
→ hash/index
→ memory table lookup
→ optional projection/gate
→ 与 hidden state 融合
```

覆盖：

- N-gram Embedding；
- Engram；
- Per-Layer Embedding；
- 查表参数为何能在较小计算量下增加容量；
- table offload、prefetch 与缓存；
- 条件记忆与 MoE 条件计算的区别。

## 7.2 Multi-Token Prediction

新增 `MTP/`：

```text
h_t : [B, D]
→ MTP module 1 → logits_{t+1} : [B, V]
→ MTP module 2 → logits_{t+2} : [B, V]
→ ...
→ target verification / accepted length
```

区分：

- MTP 训练目标；
- 模型内的 MTP module/head；
- 将 MTP 用作 speculative decoding draft；
- proposal 与 verification 的张量；
- 接受率、额外权重与实际吞吐收益。

## 7.3 多模态输入张量流

新增 `多模态/`，先覆盖三种架构：

```text
A. modality encoder → projector → modality tokens → LLM
B. modality encoder → cross-attention → text decoder
C. encoder-free / unified projection → shared backbone
```

基础张量：

```text
Image       : [B, C, Himg, Wimg]
Patch token : [B, Nv, Dv]
Projected   : [B, Nv', D]
Text token  : [B, Nt, D]
Merged      : [B, Nv' + Nt, D]
```

后续专题：

- variable resolution；
- visual token compression/resampler；
- 2D/3D/M-RoPE；
- 视频时间轴；
- 音频帧与 codec token；
- Thinker/Talker 等理解与生成分支。

## 7.4 非自回归与扩散语言模型

新增 `非自回归生成/`：

```text
带 mask 的完整候选序列 [B, T]
→ 双向 Transformer
→ 所有 mask 位置 logits [B, T, V]
→ 选择部分 token 解 mask / remask
→ 多轮迭代直到完成
```

重点比较：

- 自回归 next-token factorization；
- masked diffusion objective；
- 固定长度与长度预测；
- 并行解 mask；
- 为什么传统 KV Cache 不能直接复用；
- block diffusion 与缓存优化。

代表模型：LLaDA/iLLaDA 及其 MoE、多模态变体。

---

# 8. 位置轴的后续补充

当前已有基础 RoPE，后续按以下顺序深化：

1. absolute learned/sinusoidal position embedding；
2. relative position bias；
3. ALiBi；
4. partial RoPE；
5. 不同层使用不同 RoPE theta；
6. YaRN、LongRoPE、dynamic NTK 等长度扩展；
7. NoPE；
8. 2D/3D/M-RoPE；
9. 线性注意力/SSM 如何通过递推和卷积携带顺序。

位置轴文档必须区分：

- 是否改变张量形状；
- 是否增加运行时计算；
- 是否改变 KV Cache 中保存的内容；
- 是否支持长度外推；
- 是否与 MLA 权重吸收兼容。

# 9. 用代表模型验证架构轴

通用机制完成后，用模型组合矩阵检查是否存在分类缺口：

| 模型族           | 存储轴                   | 计算轴                    | 位置轴                | MLP/MoE             | Block/其他                    |
| ---------------- | ------------------------ | ------------------------- | --------------------- | ------------------- | ----------------------------- |
| LLaMA/Qwen Dense | GQA                      | Dense                     | RoPE                  | SwiGLU Dense        | RMSNorm + Pre-Norm            |
| Gemma/gpt-oss    | GQA                      | Local/Global              | RoPE                  | Dense 或 MoE        | QK-Norm/Softcap 等            |
| DeepSeek/GLM     | MLA                      | Dense/DSA                 | 解耦 RoPE             | Shared + Routed MoE | MTP 等                        |
| Qwen Next 系列   | GQA/标准头               | Gated DeltaNet + Full/QSA | Partial RoPE/递归顺序 | 超稀疏 MoE          | Gated Attention/Residual、MTP |
| Kimi Linear/K3   | MLA                      | KDA + periodic MLA        | NoPE/递归顺序         | Shared/Latent MoE   | AttnRes、条件化结构           |
| Jamba            | GQA                      | Attention + Mamba         | RoPE + SSM 顺序       | Dense/MoE           | 混合层调度                    |
| 多模态模型       | 继承语言主干             | Self/Cross/Hybrid         | M-RoPE 等             | 继承语言主干        | Encoder/Projector/Unified     |
| LLaDA            | 不使用传统自回归 KV 主线 | 双向 Dense Attention      | 位置编码              | Dense/MoE           | Masked diffusion sampling     |

验收方法：

1. 每个模型是否都能由已有“架构轴”组合出来；
2. 如果某结构无法归入任何轴，判断它是新架构轴还是实现细节；
3. 模型文档是否只需要填写具体参数和组合关系；
4. 是否能够从模型配置推导主要张量形状与推理状态。
