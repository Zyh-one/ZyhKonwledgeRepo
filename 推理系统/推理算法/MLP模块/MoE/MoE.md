# MoE：稀疏专家（Mixture of Experts）

> 本文是「MLP」系列的第 3 篇（轴二），描述 MoE 层的模块构成与张量流：**包含哪些模块、相对稠密 SwiGLU 层哪些是新增的、输入输出维度是否不变、张量如何逐级转换**。核心结论先行：输入输出仍恒为 `[S, H]`；新增的是路由器与加权合并；最大的张量变化是——**中间维度第一次出现了「随路由结果动态变化」的形状**。
>
> 关联：[GLU 门控变体](../GLU/GLU.md)（每个专家的内部结构）；[MLP变体概述](../MLP变体概述.md) §4 轴二；[经典MLP](../经典MLP.md)（基线）。

---

# 0. 符号约定

```text
S        : 序列长度，即 MLP 输入 [S, H] 的第一维
H        : 隐藏维度（hidden_size）
d_ff     : 单个专家的中间维度（专家内部就是一篇 SwiGLU，常取 ≈ 8H/3 或更小）
N        : 专家（expert）个数
k        : 每个 token 激活的专家数（top-k，k ≪ N）
W_r      : 路由器权重，形状 [H, N]（新增模块）
E_i      : 第 i 个专家，即一份完整的 SwiGLU MLP（W_gate/W_up/W_down 各 [H,d_ff]/[d_ff,H]）
S_i      : 本次前向中被路由到专家 i 的 token 数（动态，Σ S_i = k·S）
w_i(s)   : token s 路由到专家 i 的路由权重（softmax+top-k 得到的标量，运行时算出、非参数，见 §3.1/§3.3）
```

---

# 1. 动机：容量与单 token 计算解耦

稠密 MLP（经典或 SwiGLU）扩容只有加宽 `d_ff`、加深层数两条路，参数量与每个 token 的计算量**同涨**。MoE 的解法是把一层的 MLP 复制成 N 份**专家**，再由一个**路由器**为每个 token 只挑 k 个专家计算：知识容量装在 N 份专家里（全部驻留显存），单 token 只付 k 份的计算成本。容量与计算就此解耦——这是轴二区别于轴一（改激活）的本质：**改的不是「怎么算一个 token」，而是「N 份矩阵怎么排布、谁来用」**。

---

# 2. 模块构成：有哪些、哪些是新增的

一个 MoE 层相对稠密 SwiGLU 层的模块清单：

| 模块               | 参数形状                         | 相对稠密层                                    |
| ------------------ | -------------------------------- | --------------------------------------------- |
| **路由器**   | `W_r : [H, N]`（一个线性层）   | **新增**——MoE 的标志性模块            |
| **N 个专家** | 每个专家 3 个矩阵（SwiGLU 全套） | 结构**不是新的**：一份 SwiGLU 复制 N 份 |
| **加权合并** | 无参数（逐 token 加权求和算子）  | **新增**——把 k 份专家输出合成一份     |
| 共享专家（可选）   | 1 份额外 SwiGLU，每 token 必走   | 变体加法（DeepSeek 系），非 MoE 必备          |

三个要点：

1. **「新增」的准确范围**：真正的新结构只有路由器（一个小线性层）和合并算子（无参数）。专家本身没有新结构——把 [GLU 门控变体](../GLU/GLU.md) 那套 `W_gate/W_up/W_down` 复制 N 份就是全部专家。MoE 的复杂度不在任何一个模块内部，而在模块之间的**调度关系**上。
2. **路由器是逐 token 决策的**：它对每个 token 独立打分、独立选专家——不同 token 走不同专家组，这是「稀疏」的来源，也是负载不均问题的来源。
3. **共享专家**（可选）：DeepSeek-V2/V3 的做法——除了 N 个路由专家，再加一个所有 token 必经的共享专家，吸收共性知识，让路由专家专注差异化知识。结构上它就是第 N+1 个专家，只是不参与路由。

# 3. 张量流：路由 → 专家 → 合并

## 3.1 输入与路由：`[S, H]` → `[S, N]` → 每 token 的 top-k

MoE 层的输入仍是 `Z : [S, H]`（Attention + Residual 的输出，接法与稠密层完全一致）。第一步路由器打分：

```text
R = Z × W_r   →   [S, H] × [H, N]   →   [S, N]
```

`R[s, i]` 是 token s 对专家 i 的原始打分。随后按行（每个 token 独立）做 `softmax`，再取 **top-k**：

```text
P = softmax(R, 按行)          [S, N] → [S, N]    每 token 对 N 个专家的归一化得分
top-k                        → 索引 I : [S, k]，取值 V : [S, k] = P[s, I[s]]
（可选）对 k 个取值重归一化    → 路由权重 w : [S, k]（每行和为 1）
```

`w_i(s)` 即 `P[s, i]` 中被 top-k 选中保留的那 k 个标量。至此张量上出现了两类新中间量：打分矩阵 `[S, N]`（token 维 × 专家维的二维表，稠密 MLP 里不存在的形状）与路由权重 `[S, k]`（或等价的每行仅 k 个非零的稀疏 `[S, N]`）。

**注意 `w` 是运行时从数据算出的权重系数，不是参数**——MoE 新增的参数矩阵只有路由器的 `W_r : [H, N]`。它之于 MoE，如同 `softmax(Q·Kᵀ)` 之于 Attention：前者是 `[S, k]` 的路由分布，后者是 `[S, S]` 的注意力分布，都是中间量而非模型权重。

## 3.2 专家计算：`[S_i, H]` → `[S_i, d_ff]` → `[S_i, H]`

按路由结果把 token **分组发往各专家**（gather）：专家 i 收到属于它的 token 子集：

```text
Z_i : [S_i, H]  
  ↓ 过一遍 SwiGLU（同 GLU 篇 §2，逐 token 独立）
G_i = Z_i × W_gate_i        [S_i, H] × [H, d_ff] → [S_i, d_ff]
A_i = SiLU(G_i) ⊗ (Z_i × W_up_i)                  → [S_i, d_ff]
Y_i = A_i × W_down_i        [S_i, d_ff] × [d_ff, H] → [S_i, H]
```

**这是 MoE 张量流最大的新性质：专家内部形状的第一维 `S_i` 不再固定。** 它由路由结果决定——同一次前向中各专家的 `S_i` 互不相同（理想均衡时 `S_i ≈ k·S/N`，失衡时可相差数倍），不同推理 step 之间也不同。稠密 MLP 的中间形状 `[S, d_ff]` 是静态可预知的，MoE 的专家形状是**运行时动态**的。专家内部的第二维转换则完全照抄 SwiGLU，无任何新东西。

## 3.3 加权合并：k 份 `[1, H]` 加权和成一份

对单个 token 而言，流程非常简单：它被路由送进 k 个专家，拿回 **k 份输出**（每份 `[1, H]`）和 **k 个路由权重**（各一个标量）。合并就是「每份乘上自己的权重再相加」：

```text
Y[s] = w_1 · y_1(s) + w_2 · y_2(s) + … + w_k · y_k(s)   →   [1, H]
```

其中 `y_j(s)` 是 token s 经第 j 个选中专家输出的 `[1, H]` 向量，`w_j` 是 §3.1 路由器给它的标量权重（运行时算出、非参数）。整步只有标量乘向量再求和，无矩阵乘法，H 维全程不变。

每个 token 独立做一次上述加权和，按位置拼回即得整层输出 `Y : [S, H]`——与稠密层无异，继续做残差进入下一层。

**为什么加权而不等权**：`w` 是路由器的置信度，k 个专家按比例投票而非平均投票；且 `w` 带梯度，路由偏好可反传，路由器才能被训练。

## 3.4 整体张量流

```text
Z : [S, H]
  ↓ × W_r [H, N]                    路由打分
  → R : [S, N]
  ↓ softmax + top-k（逐 token）
  → 每 token k 个 (专家编号, 权重)
  ↓ 按专家 gather
  → Z_i : [S_i, H]  （i = 1..N，Σ S_i = k·S，S_i 动态）
  ↓ 各专家独立过 SwiGLU：[S_i, H] → [S_i, d_ff] → [S_i, H]
  → Y_i : [S_i, H]
  ↓ scatter 回原位置 + 逐 token 加权求和
  → Y : [S, H]
```

回答标题里的问题：**输入输出维度保持不变**——MoE 层对外仍是一个 `[S, H] → [S, H]` 的黑盒，Layer 结构、残差接法、与 Attention 的分工全部照旧；变的全在内部。

# 4. 参数与计算账

```text
参数总量   ：N × 3·H·d_ff + H·N（路由器可忽略）        —— 全部驻留显存
激活参数量 ：k × 3·H·d_ff（每 token 实际流过的权重）    —— 计算成本
激活比例   ：k / N
```

实例：Mixtral 8×7B 取 `N = 8, k = 2`——总参数 46.7B，每 token 激活约 13B（≈ 28%）；DeepSeek-V3 走「细粒度专家 + 共享专家」路线，`N = 256, k = 8`，总参数 671B、激活约 37B。注意单专家 `d_ff` 不必对标稠密模型：细粒度方案用「更多更小的专家」在同等激活算力下换取更灵活的知识划分。

# 5. 配套问题：负载均衡与推理侧视角

## 5.1 训练侧：负载均衡

路由器是学出来的，若放任训练，它容易坍缩到少数几个专家（强者愈强，其余专家得不到梯度）。所以 MoE 训练都要配**负载均衡约束**——早期用辅助损失（aux loss）惩罚失衡，DeepSeek-V3 改用 loss-free 的动态偏置调权。这一点不必深入，记住因果即可：**路由自由 → 必须配套均衡机制**，否则 N 份专家形同虚设。

## 5.2 推理侧视角

算法侧到此为止；MoE 对推理系统的冲击远大于 GLU，列出问题、划归系统主线：

1. **显存-计算解耦的代价**：N 份专家全驻显存，计算却只碰 k 份——权重显存占用与计算强度不成比例，decoding 场景下专家权重的**加载带宽**成为瓶颈；
2. **专家并行（EP）**：单卡放不下 N 份专家时跨卡切分，token 需要跨卡路由（all-to-all 通信）；
3. **负载不均**：`S_i` 动态且分布倾斜，多卡 EP 时热点专家拖慢整层（与 §5.1 训练侧均衡问题是同一件事的推理侧投影）；
4. **动态形状的算子**：gather/scatter、`S_i` 不可预知，对算子调度和显存分配都是新形态——稠密层「静态形状、顺序执行」的假设在 MoE 层失效。

---

# 6. 小结

```text
MoE 输入 Z : [S, H]                    维度口径与稠密层完全一致
  × W_r [H, N] + softmax + top-k       路由（新增模块）
  → 每 token 选 k 个专家及权重
  按专家 gather → [S_i, H]             ← 中间形状第一次动态化
  每专家过 SwiGLU → [S_i, H]           专家内部 = 系列第 2 篇原封不动
  scatter + 加权求和（新增算子）
MoE 输出 Y : [S, H]
```

MoE 的本质：**保持 `[S, H]` 黑盒口径不变，把「一份 SwiGLU」换成「N 份 SwiGLU + 路由器 + 加权合并」，用 N 份全驻显存的参数容量换取每 token 只付 k 份计算。** 模块层面几乎没有新结构（专家就是 SwiGLU 的复制），全部复杂度集中在路由带来的**动态性**上——`[S, N]` 打分、动态 `S_i`、负载均衡，算法与系统两侧的新问题都源于此。
