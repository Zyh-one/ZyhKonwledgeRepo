# GLU 门控变体：从逐元素激活到 SwiGLU

> 本文是「MLP」系列的第 2 篇，追踪 GLU（Gated Linear Unit，门控线性单元）家族相对经典 MLP 的张量流变化。改动只有两处——**激活环节换形态、`d_ff` 调比**——「升维 → 非线性 → 降维」三步骨架与 `[S, H]` 输入输出完全不变（对比明细见 §8）。
>
> 关联：[经典MLP](../经典MLP.md)（基线，本文沿用其张量主线逐步展开）；[MLP变体概述](../MLP变体概述.md) §3 轴一。

---

# 0. 符号约定

```text
S        : 序列长度，即 MLP 输入 [S, H] 的第一维
H        : 隐藏维度（hidden_size）
d_ff     : MLP 中间维度，门控变体常取 d_ff ≈ 8H/3（推导见 §6）
W_gate   : 门控支升维权重，形状 [H, d_ff]（新增于经典 MLP）
W_up     : 值支升维权重，形状 [H, d_ff]（同经典 MLP 的 W_up）
W_down   : 降维权重，形状 [d_ff, H]（同经典 MLP）
⊗        : 逐元素相乘（Hadamard 积），不改变张量形状
SiLU     : x·sigmoid(x)，SwiGLU 的门控激活（见 §5）
```

---

# 1. 动机：激活曲线是固定的

回顾 [经典MLP](../经典MLP.md) §2.2：激活 `σ(U[s,j])` 逐元素裁剪中间表示，每个分量的去留**只取决于该分量自身的数值**，与「当前 token 是什么内容」无关——等于用同一把全局固定曲线裁所有 token 的所有特征。激活函数演进线 `ReLU → GELU → SiLU` 换的是更好的尺子，但「尺子固定」这件事从未改变。

GLU 的想法是把「裁谁」的决定权交给模型：从 `H` 维**再投影出一份门控分支**，与值分支逐元素相乘。门控分支就是一张**学出来的、逐 token 自适应的掩码**——同一层对不同 token 可以裁出完全不同的特征组合。

---

# 2. 张量变换的步骤

记 MLP 的输入为 `Z : [S, H]`（即 Attention + Residual 的输出，与 [经典MLP](../经典MLP.md) §1 的口径一致）。门控变体同样走「升维 → 非线性 → 降维」，只是升维一次投出**两份**分支、非线性环节换成**门控相乘**。

## 2.1 升维：H → d_ff（两份分支）

第一步用两个形状相同的升维权重，把每个 token 的 Hidden State 从 `H` 维投影到 `d_ff` 维：

```text
G = Z × W_gate   →   [S, H] × [H, d_ff]   →   [S, d_ff]    门控支
U = Z × W_up     →   [S, H] × [H, d_ff]   →   [S, d_ff]    值支
```

`G` 与 `U` 来自同一个 `Z`、经两份不同权重各自投影：**门控支负责「决定留什么」，值支负责「提供被留的内容」**。两份投影都是纯线性，此时尚未引入任何非线性。

## 2.2 门控激活：逐元素相乘、不改维度

升维后对门控支施加 `SiLU`，再与值支逐元素相乘：

```text
A = SiLU(G) ⊗ U   →   [S, d_ff] ⊗ [S, d_ff]   →   [S, d_ff]
```

**这是门控变体唯一引入非线性的环节。** 关键的张量性质是：

- **逐元素（element-wise）**：`A[s, j] = SiLU(G[s, j]) · U[s, j]`，每个分量独立计算，分量之间互不影响；
- **不改变张量形状**：输入 `[S, d_ff]`，输出仍 `[S, d_ff]`，没有任何矩阵乘法、没有维度变化。

非线性来源有两处合成：`SiLU` 的曲线本身，以及**两份线性投影的逐元素相乘**——线性 × 线性按元素乘即引入非线性，这正是门控相对「单分支 + 固定曲线」的增量所在。

**命名约定注记**：`SiLU` 套在门控支还是值支只是两支的命名互换，数学形态完全对称。本文按 LLaMA 代码惯例 `SiLU(gate) ⊗ up` 书写（Shazeer 2020 原式则把激活放在另一支）；[MLP变体概述](../MLP变体概述.md) §3 的式子取的是对称命名，两者等价。

## 2.3 降维：d_ff → H

门控相乘后用降维权重把 `d_ff` 维投影回 `H` 维：

```text
Y = A × W_down   →   [S, d_ff] × [d_ff, H]   →   [S, H]
```

`W_down : [d_ff, H]` 同为结构参数。至此输出回到 `[S, H]`，与输入维度一致，可以继续做残差连接 `Z + MLP(Z)` 并进入下一层。

# 3. 整体张量流

把步骤串起来：

```text
Z : [S, H]
  ↓ × W_gate [H, d_ff]     门控支升维
  → G : [S, d_ff]
  ↓ × W_up   [H, d_ff]     值支升维
  → U : [S, d_ff]
  ↓ SiLU(G) ⊗ U            逐元素门控相乘
  → A : [S, d_ff]
  ↓ × W_down [d_ff, H]     降维
  → Y : [S, H]
```

输入输出恒为 `[S, H]`，中间在 `[S, d_ff]` 上做门控非线性变换。全程不出现 `[S, S]`——每个 token 独立过 MLP，不在 token 之间混合信息，这一点与经典 MLP 完全一致。

---

# 4. 家族谱系：门控激活 `f` 的选型

门控结构里套哪个激活 `f`，决定家族成员（谱系同出自 Shazeer 2020 *GLU Variants Improve Transformer*）：

| 变体             | 门控激活`f`                 | 备注                                          |
| ---------------- | ----------------------------- | --------------------------------------------- |
| **GLU**    | `sigmoid`                   | Dauphin 2017 原始版，门控思想来源             |
| **ReGLU**  | `ReLU`                      | 家族对照项，实际少用                          |
| **GeGLU**  | `GELU`                      | 沿用经典期激活做门                            |
| **SwiGLU** | `SiLU`（`x·sigmoid(x)`） | **当前事实标准**，LLaMA/DeepSeek/GLM 等 |

需要澄清的是「GLU」一词的双重含义：它既指 Dauphin 2017 那个 sigmoid 原始版，也常被用作整个家族的统称（LLaMA 代码里这个模块就被直接叫 GLU）。严格义的 GLU 几乎没有被 Transformer 直接采用——实际谱系是从经典 MLP 直接跳到 **SwiGLU**，GeGLU/ReGLU 只是对照项。

---

# 5. SiLU：激活演进线的当前终点

SwiGLU 名字里的 **Sw** 即 SiLU（又称 Swish）。承接 [经典MLP](../经典MLP.md) §2.2 的选型表，把演进线补全：

| 激活函数 | 公式              | 负值附近行为                       | 出处/定型                |
| -------- | ----------------- | ---------------------------------- | ------------------------ |
| ReLU     | `max(0, x)`     | 硬截断为 0                         | 原始 Transformer（2017） |
| GELU     | `x·Φ(x)`      | 平滑过渡，允许小幅负值             | BERT / GPT 定型          |
| SiLU     | `x·sigmoid(x)` | 平滑，负值区保留一个浅谷（非单调） | 现代门控标配             |

三者的张量行为完全一致——逐元素、保 `[S, d_ff]` 形状——差异只在曲线形状。SiLU 与 GELU 曲线形态非常接近（都有「近 0 保留、深负趋 0、微负小幅下探」的轮廓），因此 SwiGLU 相对 GeGLU 的收益主要来自门控结构本身，而非曲线差异。

---

# 6. 参数账：`d_ff = 8H/3` 的由来

矩阵从 2 个变 3 个（`W_gate / W_up / W_down`），同 `d_ff` 下参数 +50%。令门控变体与经典 MLP **总参数量相等**：

```text
经典：2 × H × d_ff = 2 × H × 4H = 8H²
门控：3 × H × d_ff = 8H²  →  d_ff = 8H/3 ≈ 2.67H
```

实例：LLaMA-7B 取 `H = 4096`，`8H/3 ≈ 10923`，对齐后取 `d_ff = 11008`。附带一笔中间激活账：per-token 中间元素量从 `4H` 变为 `2 × d_ff ≈ 5.33H`（约 +33%），量级不变，工程上无感。

---

# 7. 推理侧落地

对推理系统，GLU 门控**没有引入任何新计算范式**——仍是 GEMM + 逐元素操作，但有三处可见痕迹：

1. **权重命名**：LLaMA 系 checkpoint 中即 `gate_proj / up_proj / down_proj`，分别对应 `W_gate [H, d_ff]`、`W_up [H, d_ff]`、`W_down [d_ff, H]`；
2. **融合 GEMM**：`W_gate` 与 `W_up` 形状相同，常沿输出维拼成 `[H, 2·d_ff]` 一个大矩阵，一次 GEMM 得 `[S, 2·d_ff]` 再切两半——与 QKV fused 同一招；
3. **`d_ff` 不再是 `4H` 整数倍**（`8H/3` 需取整对齐，如 11008），对 GEMM 的 tiling/对齐有少许讲究，仅此而已。

Decode 视角下每个 token 仍是「两次（融合后一次）GEMM + SiLU + 逐元素乘 + 一次 GEMM」，形状与经典 MLP 无范式差异。

---

# 8. 附：与经典 MLP 的对比

把基线与门控变体逐项对齐（基线详见 [经典MLP](../经典MLP.md)）：

**激活环节的式子对照**：

```text
经典：  A = σ(Z × W_up)
门控：  A = SiLU(Z × W_gate) ⊗ (Z × W_up)
```

反向看退化关系：若把门控相乘退回「单分支 + 固定曲线」`σ(U)`，就回到经典 MLP——门控的全部增量浓缩在**第二份升维分支与逐元素相乘**上。

**不变清单**（改动不大的确切含义）：

- 输入输出恒为 `[S, H]`，在 Layer 中的位置、残差/Norm 接法不变；
- 仍是 `升维 → 非线性 → 降维` 三步，非线性仍**全部来自逐元素操作**；
- 仍是 position-wise：全程无 `[S, S]`、无 token 间混合；
- 与 Self-Attention 的职责分工照旧：Attention 跨位置混合，MLP 跨维度重组，门控改变的只是每个 token 内部「裁特征」的方式。

**改动清单（仅两处）**：激活环节换形态（§2.2）；`d_ff` 从 `4H` 调到 `8H/3`（§6）。

---

# 9. 小结

```text
MLP 输入 Z : [S, H]
  × W_gate  [H, d_ff]      门控支升维（d_ff ≈ 8H/3）
  → G : [S, d_ff]
  × W_up    [H, d_ff]      值支升维
  → U : [S, d_ff]
  SiLU(G) ⊗ U              逐元素门控相乘，保形状
  → A : [S, d_ff]
  × W_down  [d_ff, H]      降维
  → Y : [S, H]
MLP 输出 Y : [S, H]
```

GLU 门控变体的本质：**把经典 MLP「夹在两次线性投影之间的固定激活曲线」替换为「两份升维分支的逐元素相乘门控」，再以 `d_ff = 8H/3` 补偿多出的一个矩阵。** 骨架三步与 `[S, H]` 口径完全不变，系统侧只增加一个可融合的 GEMM。

后续第 3 篇 [MoE](../MoE/MoE.md)（轴二）改的是矩阵的排布：把这一对门控 MLP 复制成 N 份专家加路由——届时本文的门控 MLP 就是每个专家的内部结构。
