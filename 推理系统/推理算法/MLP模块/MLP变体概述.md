# MLP 变体概述：经典 MLP → SwiGLU / MoE

> 本文是「MLP」系列的开篇。它不深入每个变体的张量细节，只回答四个问题：**MLP 变体是什么、为什么会出现、沿哪几条轴演化、它们和经典 MLP 基线是什么关系。**
>
> 各变体的详细张量流将放在本目录后续单独文档中。系列基线是 [经典MLP](经典MLP.md)（系列第 1 篇）。

---

# 1. 起点：经典 MLP 基线与历史定位

先交代一段历史定位，避免术语混淆：**MLP**（Multilayer Perceptron，多层感知机）在历史上泛指「多个全连接层堆叠、层间夹激活函数」的网络结构，诞生远早于 Transformer。Transformer 取的是其中最简的一种形态——**单隐层、逐 token 独立作用**（position-wise）——作为每层的 FFN 子模块。本系列讨论的「MLP」都指后者，即 Transformer Layer 里与 Self-Attention 交替的那个子模块。

[经典MLP](经典MLP.md) 已把基线的张量流写透，这里只留骨架：

```text
Z : [S, H]
  ↓ × W_up   [H, 4H]        升维
  ↓ σ（逐元素激活）           ReLU / GELU
  ↓ × W_down [4H, H]        降维
Y : [S, H]
```

三步骨架 `升维 → 激活 → 降维`、输入输出恒为 `[S, H]`——这是所有 MLP 变体的公共不变量，变体改动的只是其中某一步的实现方式。

---

# 2. 基线的两处「不自由」

对照 [注意力模块演进](../自注意力模块/注意力模块演进.md) 的问法——注意力模块的演化沿存储/位置/计算三条正交轴展开——MLP 的演化则沿**两条正交的轴**展开，它们分别源于基线的两处局限：

**局限一：激活曲线是固定的。** `σ` 是训练前就定死的一条全局曲线（ReLU、GELU），每个分量的去留只取决于该分量自身的数值，与「当前 token 是什么内容」无关——相当于用同一把尺子裁所有 token 的所有特征。激活函数演进线 `ReLU（原始 Transformer）→ GELU（BERT/GPT 定型）→ SiLU` 一直在换更好的尺子，但「尺子固定」这件事本身没变。

**局限二：容量是稠密的。** 模型表达力只能靠加宽 `d_ff`、加深层数来扩，参数量与每个 token 的计算量**同涨同跌**——想要更大的知识容量，就必须给每个 token 都付全部计算成本。

于是两条演化轴分别是：让「裁特征」这件事从固定曲线升级为学出来的门控（§3），让「容量」与「单 token 计算」解耦（§4）。

---

# 3. 轴一：激活 → 门控（GLU 家族）

这条轴改的是**「激活」这一步**：不再对单份 `U : [S, 4H]` 逐元素施加固定曲线，而是**升维出第二份分支充当门控，两份逐元素相乘**：

```text
经典：  A = σ(Z × W_up)
门控：  A = (Z × W_gate) ⊗ f(Z × W_up)
```

区别的本质：经典激活 `σ(U[s,j])` 只看分量自身的值；门控的裁剪由**同一 token 的另一份投影**决定——「裁谁」从固定曲线升级成了**逐 token 自适应、可学习的掩码**。

门控分支里那个 `f` 取什么激活，决定家族成员（同出自 Shazeer 2020 *GLU Variants Improve Transformer*）：

| 变体             | 门控函数`f`                 | 备注                                              |
| ---------------- | ----------------------------- | ------------------------------------------------- |
| **GLU**    | `sigmoid`                   | Dauphin 2017 原始版，门控思想来源                 |
| **ReGLU**  | `ReLU`                      | 家族对照项，实际少用                              |
| **GeGLU**  | `GELU`                      | 沿用经典期的激活做门                              |
| **SwiGLU** | `SiLU`（`x·sigmoid(x)`） | **当前事实标准**，LLaMA/DeepSeek/GLM 等均用 |

参数账也随之变化：矩阵从 2 个变 3 个（`W_gate / W_up / W_down`），为保持总参数量，`d_ff` 从 `4H` 调到约 `8H/3 ≈ 2.67H`——这正是 [经典MLP](经典MLP.md) §4 埋的伏笔。张量流细节见 [GLU 门控变体](GLU/GLU.md)。

---

# 4. 轴二：稠密 → 稀疏专家（MoE）

这条轴改的是**「升维/降维矩阵」的排布**：把一整对 `W_up/W_down` 复制成 N 份（N 个专家），再加一个路由器决定每个 token 走哪几个：

```text
Z : [S, H]
  → 路由器：Z × W_r [H, N] → softmax → 每 token 选 top-k 个专家及权重
  → 被选中的 k 个专家各自做一遍「升维 → SwiGLU → 降维」
  → 按路由权重加权求和
Y : [S, H]
```

动机是**容量与单 token 计算解耦**：N 个专家的权重全部驻留显存（知识容量 ∝ N），但每个 token 只流过 k 个（k=1 为 Switch Transformer，k=2 为 Mixtral 及主流选择）。代价是给推理系统带来新问题——专家并行（EP）、负载均衡、显存与带宽的权衡——这些属于推理系统侧主线，算法篇只讲结构与张量流，见 [MoE](MoE/MoE.md)。

---

# 5. 两轴交汇：现代主流形态

两条轴不互斥，而是**叠装**：现代主流大模型（Mixtral、DeepSeek-V2/V3、GLM 系列）的每个专家内部用的正是 SwiGLU——轴一的成果被装配进轴二的结构里。所以现代一层 Transformer Block 的典型形态是：

```text
Self-Attention（MHA 变种）
MoE 层：路由器 + N 个 SwiGLU 专家，每 token 激活 k 个
```

单看激活函数，时间线收敛为 `ReLU → GELU → SiLU（SwiGLU）`；单看结构排布，时间线收敛为 `稠密 MLP → 稀疏 MoE`。两条线各取终点后叠装，就是当下推理系统所服务的模型形态。
