# 计算轴概述：每步看多少 token

> 本文是计算轴的**总览**，对标 [注意力模块演进](../注意力模块演进.md) 在模块层的角色：说清这条轴的问题从哪来（满注意力的两堵墙）、削减手段沿哪几条路线发展、各路线现在走到了哪一步、轴内还有哪些篇目。张量与机制细节留给轴内各机制篇。

---

# 1. 产生原因：满注意力的两堵墙

[自回归生成](<../../0-Transformer%20自回归生成的最小闭环.md>) 里注意力分数是 `Q×K^T → [S, S]`——每个 token 都和所有 token 算一次分。2017 年序列不过 512，这堵「平方墙」没人觉得是问题；当上下文从 2k 走到 128k 再到 1M，它在两个阶段分别显形：

## 1.1 Prefill 墙：算力

Prefill 要一次性算完整个 `[S, S]` 分数矩阵。代入 GLM-5.3 的量级（见 [GLM-5.3](../../../模型结构/GLM-5.3/GLM-5.3.md)）：`S=1M` 时单头单层就是 `1e12` 个分数，再乘 64 头 × 78 层，到达 `1e16` 量级——**平方墙是硬上限，压存储救不了它**：MLA 把每个 token 的 KV 压薄了（存储轴），但分数矩阵还是 `S×S`，一个都少不了。

## 1.2 Decode 墙：访存

Decode 每生成 1 个 token，都要把全部 `S` 个 KV 读一遍、算一遍分——单步代价 `O(S)`，**上下文越长，每步越慢**。存储轴让每 token 的字节变小（MLA 压到约 `r_kv` 量级），但「要读的 token 个数」一个没少。

## 1.3 共同根源

注意力矩阵是**满**的。计算轴的全部工作就是把它变稀疏，手段分两大类：**删配对**（保留 `点积+Softmax` 公式，但只对一小部分 token 对算）与**换公式**（连 `点积+Softmax` 都换掉，把历史压成固定大小的状态）。前者按「谁来决定删哪些」又分两档，合成三条路线。

# 2. 目前内容：三条路线地图

| 路线 | 本质 | 复杂度 | 代表 | 选择规则需学习 |
| ---- | ---- | ------ | ---- | -------- |
| ① 硬编码稀疏 | 人规定看哪里 | `O(S·w)` | 滑动窗口（Mistral）、local:global 交替（Gemma、gpt-oss） | 否（但模型需按该 mask 训练） |
| ② 学习型稀疏索引 | 模型自己选 top-k | `O(S·k)` | NSA、DSA（DeepSeek-V3.2、GLM-5.3） | 是（NSA） |
| ③ 线性注意力 | 换公式，历史压成固定状态 | 每 token `O(d²)`，与 S 无关 | Gated DeltaNet、KDA、Lightning Attention | 不适用（公式本身需训练） |

## 2.1 路线①：硬编码稀疏——人规定看哪里

最朴素也最古老：不看全部，只看**最近 w 个 token**（滑动窗口，`O(S·w)`）；或按层交替——多数层只看局部，少数层看全局（Gemma 3 约 5:1，gpt-oss 为 1:1）。窗口和层类型是人指定的，不需要额外学习索引器；但模型仍应当在该 attention mask 下训练。流式淘汰已有 KV 时，attention sink 又说明「删哪些位置」会影响稳定性，但 sink 并不是原生滑窗的必备组成。单层机制见 [滑动窗口注意力](滑动窗口注意力.md)，多层编排见 [局部与全局层交替](局部与全局层交替.md)。

## 2.2 路线②：学习型稀疏索引——模型自己选看谁

硬编码的形状是死的，长程该看谁因内容而异。这一路线加一个**索引器**先跑一遍粗筛，选出 top-k 个值得看的 token，再对它们做完整注意力，复杂度降到 `O(S·k)`。GLM-5.3 的 DSA 即此路：`index_topk=2048`，对 `S=1M` 而言差三个数量级——与 MLA 的显存基础互补，**这是 GLM-5.3 能开 1M 上下文的算力基础**（见 [GLM-5.3](../../../模型结构/GLM-5.3/GLM-5.3.md) §4；机制篇 [DSA](DSA.md)）。

## 2.3 路线③：线性注意力——干脆换掉「点积+Softmax」

前两条路线都保留注意力公式本身；这一条把注意力改写成 **RNN 递推**：维护一个**固定大小的状态矩阵**，每来一个 token 用 `O(d²)` 把它的信息「记账」进状态，而不是回头翻全部历史——KV Cache 从 `O(S)` 变 `O(1)`，decode 单步与上下文长度无关。代价是固定状态装不下精确历史，大海捞针式检索弱于满注意力，所以主流模型都不敢全换，而是「线性层为主 + 每 3-4 层一个全注意力层兜底」的混合形态（Qwen3-Next、Kimi K2 Thinking、MiniMax-M1 都是这个模式）。

# 3. 发展脉络：两条源流的汇合

三条路线不是一条河，是**两条独立源流**各自演进、最后汇成同一种混合形态。

## 3.1 源流一：稀疏化——保留公式，删配对

这条源流的目标一直是「别算那么多分数」，每一代都在解决上一代的死板：

- **固定模式**（2019-2020）：Sparse Transformer 的局部窗口 + 少量固定全局位，Longformer 的 dilated 滑窗，BigBird 再补随机边并证明稀疏可近似满注意力的表达力。模式全是**人拍板**的，与内容无关；
- **滑窗进主流**（2023）：Mistral-7B 把滑窗当默认注意力开进开源基座——训练时就稀疏，省得最干净；同年 StreamingLLM 说明，对已训练模型做流式 KV 淘汰时，保留少量 sink token 可避免简单截断导致的退化；
- **让模型自己选**（2024-2025）：固定窗口看不见内容相关的长程依赖，于是索引器登场——MoBA 用门控路由按块选 token，NSA 把「训练与推理一致」和块稀疏硬件对齐做扎实，DSA 干脆**用注意力自身的权重当索引器**，索引开销压到最低。

## 3.2 源流二：状态化——换公式，RNN 复兴

这条源流的野心更大：不是少算几个分数，而是**让历史不占线性空间**：

- **公式化**（2020）：linear attention 把 Softmax 换成 kernel 相似度，注意力立刻可写成递推——但无界累加的状态精度差，长期被当玩具；
- **修正与 scale**（2023-2024）：Mamba/RWKV 证明状态化混合器能训到 B 级参数；DeltaNet/Gated DeltaNet 引入衰减与门控，让状态「会遗忘」而不是无界累加；
- **进一线**（2025）：KDA、Qwen3-Next 的 GDN 把线性层开进主力开源模型，以混合形态落地。

## 3.3 汇合点：交替

两条源流殊途同归——都不敢全换，都收敛到「**便宜机制占多数层，全局/全注意力层少量兜底**」（详见 §4）。2024 年之后的开放权重模型里，纯满注意力（Dense）和纯状态化都成了少数派。

# 4. 交替：现代模型的通用设计语言

把三条路线放在一起看，会发现一个反复出现的模式——**关键层保真、其余层省钱**：

- Gemma 3：5 层局部 : 1 层全局；
- gpt-oss：滑窗层与全注意力层 1:1 交替；
- DSA：`index_topk_freq=4`——1 层 full 索引 + 3 层 shared 复用（GLM-5.3 config）；
- 线性混合：约 3:1 的线性:全注意力（Qwen3-Next 等）；
- MoE：前 3 层 dense，其余 75 层稀疏专家（GLM-5.3 `first_k_dense_replace=3`）。

局部的、便宜的机制占多数层，全局的、昂贵的机制少量插入兜底——这个「交替」模式横跨计算轴三条路线，甚至蔓延到 MLP 侧。记住它，看到任何新架构的层配置都能秒懂一半。

---

# 5. 与前两条轴的正交性

三条轴改的是三个独立量，可乘法叠加，GLM-5.3 是完整实例：

- **存储轴**：MLA 压薄**每个 token 的 KV 字节数**（`S` 个、每个更小）；
- **计算轴**：稀疏索引减少**要看 token 的个数**（`k` 个）；
- **位置轴**：RoPE 只作用于解耦的 `q_rope/k_rope` 小段，与「谁被选中」无关。

有效注意力代价 ≈（要读的 token 数）×（每 token 字节数）——前两条轴各压一个因子，互不掣肘。

# 6. 发展时间线

```text
2017     Transformer 原始论文        —— 满注意力 O(S²) 成为默认；序列不过 512，平方墙无痛
2019     Sparse Transformer          —— 稀疏模式系统化：局部窗口 + 少量固定全局位（删配对）
2020     Longformer / BigBird        —— 滑窗 + dilated + 随机边；证明稀疏可保表达力
2020     线性注意力公式化            —— 「Transformers are RNNs」：kernel 化换掉 Softmax（换公式）
2023     Mistral-7B / StreamingLLM   —— 滑窗进主流开源基座；attention sink：稀疏不能随便删
2023     Mamba / RWKV                —— 状态化混合器 scale 到 B 级参数，换公式路线成型
2024     MoBA / Jamba                —— 门控式稀疏路由；「线性为主 + 全局兜底」混合层成型
2025-02  NSA（DeepSeek）             —— 可学习稀疏索引 + 块稀疏硬件对齐
2025-09  DSA（V3.2 / GLM-5.3）       —— 注意力自身当索引器，full/shared 层交替
2025-09  KDA / Qwen3-Next            —— 线性注意力混合进入一线开放权重模型
```

整体趋势：**从「每步看全部」走向「每步看少量」——删配对与换公式两条源流并行演进，最后都收敛到交替混合形态。**

# 7. 小结与轴内阅读路线

- 满注意力的两堵墙：Prefill 的 `O(S²)` 算力墙、Decode 的 `O(S)` 单步墙，共同根源是注意力矩阵是满的；
- 三条削减路线：**硬编码稀疏**（人定形状）、**学习型稀疏索引**（模型选 top-k）、**线性注意力**（换公式、固定状态）；
- 通用设计语言：交替（关键层保真、多数层省钱）。
