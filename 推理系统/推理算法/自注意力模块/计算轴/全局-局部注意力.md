# 全局-局部注意力（Global-Local Attention）

> 主题：固定模式稀疏注意力中的 **token 级全局-局部混合**——同一层内，普通 token 用局部窗口，少数特殊位置拥有全局连边。重点梳理全局连边的三种形态（全局 Key 列 / 全局 Query 行 / 双向全局 token）、代表工作（Longformer / ETC / BigBird 及其前身）的准确边界，以及推理时连接规则、KV Cache 与 attention sink 三个概念的区分。
>
> 阅读前提：已理解 [滑动窗口注意力](滑动窗口注意力.md)（纯局部的单层机制）、[局部与全局层交替](局部与全局层交替.md)（层间编排）。本文与它们同属计算轴路线①硬编码稀疏，详见 [计算轴概述](计算轴概述.md)。

## 1. 定位：从层级编排回到层内混合

滑窗篇讲单层纯局部，层交替篇讲多层分工。本篇回到**单个注意力层内部**：不是所有 token 一视同仁，而是普通 token 之间用局部窗口，少数被指定的特殊位置承担跨区域通信。系列四篇的关系：

| 篇目                    | 核心问题                       | 设计维度         |
| ----------------------- | ------------------------------ | ---------------- |
| 计算轴概述              | 稀疏化有哪些路线？             | 方法分类         |
| 滑动窗口注意力          | 单层如何限制可见范围？         | 局部连接         |
| 局部与全局层交替        | 不同层如何分配计算？           | 层间编排         |
| 全局-局部注意力（本篇） | 同层内如何组织局部与全局连接？ | token 级连接拓扑 |

两个维度（层内 token 级、层间编排）在实现上**可组合**——一个模型既可以让某些层局部/全局交替，也可以在局部层里引入特殊全局 token。它们是不同的设计轴，不是互斥的模型类别。

阅读全文前先固定三个容易混淆、后文反复用到的概念：

- **连接模式（connectivity）**：哪些 query 能读哪些 key/value？由注意力的 mask 决定。
- **信息传播路径（information flow）**：经过一层或多层后，两个位置能否间接交换信息？连接模式是单层的，传播路径是跨层的。
- **推理时缓存策略（cache policy）**：生成时哪些 token 的 K/V 继续保留？由推理系统决定。

例如纯滑窗在单层内读不到窗口外，但多层堆叠后信息可逐层传到远处；反过来，一个 token 即使有全局连接，也不意味着它的 KV 必须永久驻留在所有推理系统的缓存里。**连接的定义 ≠ 信息的到位 ≠ 缓存的保留**。

## 2. 全局连边的三种形态

沿用滑窗篇的矩阵约定：注意力矩阵行是 Query、列是 Key，$A_{ij}=\operatorname{Attention}(q_i,k_j)$。设序列长度 $S$，普通 query 的局部窗口宽 $w$，特殊全局位置共 $g$ 个，$g\ll S$ 且 $w,g$ 不随 $S$ 增长。

### 2.1 全局 Key 列：所有 query 都能读的位置

连接规则：对指定的全局位置 $j$，所有 query 都可读取该位置的 K/V（该列整列开放）。直观理解：**特殊位置是全序列共享的信息入口**——普通 token 无须互相直连，可以通过这些共享位置获取信息。

以下为因果局部 + 全局 Key 列的示意（橙色为额外开放的全局 Key 位置），与纯滑窗对比见 [滑动窗口注意力](滑动窗口注意力.md) §7。注意它**不是**双向 Longformer 全局注意力的完整复现：

![因果局部加全局Key示意](../../../../source/推理系统/推理算法/自注意力模块/计算轴/滑动窗口注意力/local_global.png)

一个必须注明的细节：固定的全局 Key 列**不等于**全局信息汇聚。某个位置能被所有 query 读取，不代表它的表示已经在当前层汇总了全序列信息——它是否有全局语义，还取决于它自己的 Query 连接、输入表示和前序层计算。若它的 Query 仍是普通局部连接，它只是一个所有人都能读、但本身内容未必全局的共享锚点。

### 2.2 全局 Query 行：能读全序列的位置

连接规则：对指定的全局 query $i$，它可以读取全部 $S$ 个位置的 K/V（该行整行开放）。直观理解：**特殊位置承担全局信息汇聚的角色**，把分散在各局部区域的信息聚合进自己的表示。

代价：$g$ 个全局 query 各产生 $O(S)$ 连接，共 $O(gS)$。注意若只加全局 Query 行而没有对应的全局 Key 列，普通 token 在**同层内**读不到这些位置的新表示——全局信息要等下一层、或经由其他连接才能被利用。

### 2.3 双向全局 token：行与列同时开放

Longformer 式 global attention 是让指定 token 同时拥有两者：

- 作为 query，读取所有 token；
- 作为 key/value，被所有其他 token 读取。

三种形态对比：

| 连接设计        | 普通 token 能否读全局 token | 全局 token 能否读全部普通 token | 典型用途                      |
| --------------- | --------------------------- | ------------------------------- | ----------------------------- |
| 仅全局 Key 列   | 能                          | 不保证                          | 共享的全局信息入口            |
| 仅全局 Query 行 | 不保证                      | 能                              | 全局汇聚、摘要                |
| 双向全局连接    | 能                          | 能                              | Longformer 式任务级全局注意力 |

### 2.4 复杂度

三种形态与局部窗口结合后，注意力边数都是：

$$
\boxed{O(S\,w+S\,g)=O(S)\quad(w,g\ \text{固定})}
$$

对比标准全注意力的 $O(S^2)$，这就是「线性注意力边数」的含义。两个工程注记与滑窗篇相同：其一，这是**结构层面**的边数，实际耗时还取决于稀疏 kernel 是否真正跳过被屏蔽位置、内存布局与硬件利用率——理论上 $O(S)$ 不自动保证比优化良好的稠密注意力（FlashAttention）快。其二，混合 mask 的实现若仍计算完整 $S\times S$ 分数矩阵再加 mask，乘法量并不减少。

## 3. 历史脉络：因式分解与中继节点

### 3.1 Sparse Transformer（2019）：不是全局 Key 列

Sparse Transformer 的核心是**因式分解注意力（factorized attention）**：把注意力拆成多个稀疏步骤，让任意位置经由短路径间接交换信息。两类经典模式：

- **Strided（跨步）**：一个步骤读局部连续位置，另一个步骤按固定步长采样（步长约 $\sqrt{S}$ 量级）；
- **Fixed（固定）**：把序列分块，由部分位置汇总前面块的信息，再让后续位置读这些汇总位。

两步方案的复杂度量级为 $O(S\sqrt{S})$，而非 $O(S)$。它的远距离通信靠**连接路径的组合**达成，不是让一小组固定 token 在每层充当所有 query 共享的全局 Key。Fixed 模式中虽有跨块汇总位置，形式上接近全局 Key 列，但也不能与 Longformer 的对称全局 token 混同。本篇把它作为历史背景与对照，而非全局 token 机制的标准范例。

### 3.2 Star Transformer（2019）：中继节点

Star Transformer 把普通节点连局部邻居，同时通过共享的 **relay node（中继节点）**建立长距离通路，把全连接的二次复杂度降到线性。中继节点是星形拓扑的组成部分，其连接方式与状态更新属于架构本身，不等价于「给某个 token 开全注意力」。它同样适合作为结构对照，而非与 Longformer 的 global attention 并列为同一机制。

## 4. 三个代表架构

### 4.1 Longformer（2020）：对称的、任务级的 global attention

Longformer = 局部滑动窗口 + **task-motivated global attention**（可加 dilated 膨胀窗口）。

- **Global attention 是对称的双向连接**：指定位置 $i$ 作为 query 可读所有位置，其 K/V 也被所有位置读取。这是它与「只让 [CLS] 汇总、却不让普通 token 读回其表示」的单向汇聚机制的关键区别。
- **哪些位置成为 global 由任务决定**：分类任务指定分类 token，问答任务指定问题 token；同一架构在不同下游任务中全局位置可以不同。
- **「双向」指全局边的对称性，不指模型免于因果约束**。编码器任务可用双向窗口与双向全局边；字符级自回归语言建模版本必须保留因果掩码，global 位置不能读未来。另延伸出 Longformer Encoder-Decoder（LED），把该机制用于长文档序列到序列生成。
- **膨胀窗口（dilated window）**是另一种局部模式：借鉴膨胀卷积，在邻接数量不增的前提下跳过部分近邻、访问更远位置。它与全局 token 是可组合的两种稀疏模式，不是同一机制。

### 4.2 ETC（2020）：global/local 双流架构

ETC（Encoding Long and Structured Inputs）把输入显式分为两组：

- **Global tokens**：全局记忆/结构化摘要位置；
- **Long tokens**：普通长序列 token，主要做局部交互（L2L 用局部窗口）。

注意力交互组织成四种类型：G2G、G2L、L2G、L2L——涉及 global 的交互支持全局信息传递。与 Longformer 的关系一句话：**思想相近，但 ETC 把 global/local 分流、结构化相对位置编码与全局 token 的预训练方式纳入了更完整的架构设计**，两者不是先后替代关系。两点值得单独记：ETC 不只是减少连接数量，还用相对位置编码与灵活 mask 显式表达结构关系；全局 token 的作用可由 **CPC（Contrastive Predictive Coding）预训练**学习，而不只由下游任务指定。

### 4.3 BigBird（2020）：window + random + global 及其理论

BigBird 组合三类边：**局部窗口**、**指定全局 token**、**随机边**。随机边用于建立跨区域的通信路径，本身不等于全局 token。在固定窗口、固定随机预算、常数个全局 token 下，边数随 $S$ 线性增长。

理论结论须**分开且带条件**地表述，不能合并成「稀疏注意力等价于全注意力」：

- **通用逼近**：在其特定结构与理论假设下，BigBird 可逼近连续的序列到序列函数，且只需 $O(S)$ 级内积运算；
- **图灵完备**：在标准精度等假设下具有图灵完备性。

三个限定：结论针对 BigBird 定义的结构，任意稀疏图不能直接继承；表达力是理论性质，不等于训练容易或实际任务表现必然与全注意力相同；理论 $O(S)$ 不保证所有硬件实现获得同比例加速。

### 4.4 对比总表

| 工作               | 局部部分            | 全局/跨区域部分                 | 复杂度          | 备注                        |
| ------------------ | ------------------- | ------------------------------- | --------------- | --------------------------- |
| Sparse Transformer | 局部连续            | 跨步采样 / 跨块汇总（因式分解） | $O(S\sqrt S)$ | 靠多步路径，非全局 token    |
| Star Transformer   | 相邻连接            | 共享中继节点                    | $O(S)$        | 星形拓扑的一部分            |
| Longformer         | 滑窗（可膨胀）      | 对称、任务级 global token       | $O(Sw+Sg)$    | 全局位置由任务指定          |
| ETC                | long token 局部窗口 | global token 双流四交互         | $O(Sw+Sg)$    | 结构化位置 + CPC 预训练     |
| BigBird            | 局部窗口            | 全局 token + 随机边             | $O(S)$        | 通用逼近/图灵完备（有条件） |

## 5. 边界：哪些工作不属于本篇机制

- **Reformer**：用 LSH 把相似 query/key 分桶做近似注意力，是**内容相关**的稀疏化，位置不预先固定——属计算轴路线②学习型稀疏索引，与本篇的固定全局位置不同类。
- **Routing Transformer**：局部注意力 + 基于 online k-means 的内容路由，复杂度 $O(S^{1.5})$。哪些位置交互由 query/key 内容决定，同样不是固定全局 token 方案，是通往路线②的对照。
- **层交替**（Gemma 3、gpt-oss）：全局能力由**特定层**提供，不依赖一组特殊 token；见 [局部与全局层交替](局部与全局层交替.md)。可与本篇机制叠加。

## 6. Prefill / Decode 与 KV Cache：连接规则 ≠ 缓存策略

这是本篇最容易写错的部分，先给三分表：

| 概念           | 回答的问题                                    | 是否必然永久保留            |
| -------------- | --------------------------------------------- | --------------------------- |
| 全局 Key 列    | 哪些 token 可被所有 query 读取？              | 否——它是连接定义          |
| KV Cache       | 推理时保存哪些 token 的 K/V？                 | 由实现与缓存策略决定        |
| Attention sink | 哪些早期 token 吸收大量注意力、稳定流式推理？ | StreamingLLM 一类策略中保留 |

### 6.1 Prefill 与 Decode 的行为

- **Prefill**：整个输入序列同时可用，各位置算出 K/V 并按当前层的连接规则前向。全局 Key 列照常被所有 query 读到。
- **Decode**：新 token 只算自己的 Q/K/V，读缓存中的历史。若采用固定全局 token 机制：作为全局 Key 的位置会被后续 query 持续读取；作为全局 Query 的位置要读允许范围内的全部历史。自回归模型中**所有连接仍受因果约束**——位置是 global 不代表可以访问未来 token。

关键句：**注意力图决定可访问性，缓存策略决定可用的历史 K/V 是否还在。**

### 6.2 「全局列永不淘汰」的正确表述

「全局列永不淘汰」不是普遍规律，应写成：对采用固定全局 Key 的稀疏注意力实现，**若系统要继续支持后续 query 读取这些全局位置，就必须在缓存中保留其 K/V，或提供等价的重算、压缩或外部记忆机制**。原因是「全局」只是连接定义，不是强制缓存策略：

- 长文档编码器中，输入整体可用，计算结束后可直接释放 K/V；
- 生成式模型里，若设计允许丢弃或压缩这部分历史，那执行的就不再是原本定义的注意力图——删掉某个仍需被读取的全局位置的 K/V，等价于改变了连接规则本身。

固定 $g$ 个全局 token 的缓存开销是常数级的，但它是**需要专门处理的实现约束**，不是免费的全局连接。

### 6.3 Attention sink：功能相似，概念不同

- **固定全局 token**：由架构或任务 mask 指定，目的是建立显式的跨区域连接；
- **Attention sink**：模型运行中对某些 token 出现强注意力、并依赖其稳定 softmax 计算的**现象**，不要求这些 token 有全局语义。

StreamingLLM（2023/2024）在滚动 KV Cache 中保留少量初始 sink token + 最近窗口，缓解纯滚动淘汰造成的性能骤降（细节见 [滑动窗口注意力](滑动窗口注意力.md) §5.4）。它与 Longformer 式全局 token 有交集——都要求某些位置被广泛访问或长期保留——但原因不同：前者是行为/缓存稳定性现象，后者是显式连接设计。sink token、初始 token、全局 token 三者可能重合，不是同一概念。

## 7. 现状：为什么生成式大模型很少直接用固定全局 token

把「观察到的趋势」与「确定的因果解释」分开：

- **固定位置不一定是价值最高的位置**。预先指定 [CLS]、问题 token 做全局节点，隐含任务先验；开放式生成中，长距离依赖随内容和生成阶段变化，固定枢纽未必合适。
- **长期保留有实现成本**（§6.2）。
- **全局节点不覆盖所有通信需求**。不经过指定位置的依赖仍需局部传播、多层组合或随机/路由连接。

在**长文档 Encoder 任务**中它仍然自然：输入完整已知、可同层双向交互；分类/问答可把任务 token 设为全局位；结构化文档可用全局摘要 token 组织句子/段落节点。Longformer 与 ETC 的任务设置都体现了这一点——重点不是 Encoder 天然适合稀疏注意力，而是**输入完整、任务结构明确时，固定的任务级全局位置容易定义、也容易解释**。

更准确的总结是：在生成式大模型的长上下文设计中，固定全局 token 并非唯一或普遍的选择——局部窗口、层间编排、内容路由、专门缓存策略各自解决不同问题，可替代也可组合；固定全局 token 机制在长文档编码、结构化输入与任务级信息汇聚场景中仍有明确用途。不宜写成「已被层交替和学习型索引取代」这种过于整齐的演进叙事。

## 8. 常见误区

1. **「Sparse Transformer 用全局 token 实现线性复杂度」**：错。其经典方案是局部+跨步的因式分解（$O(S\sqrt S)$），靠多步路径通信；Fixed 模式的汇总位也不是 Longformer 式对称全局 token。
2. **「Longformer 的 global attention 只做汇聚 / 整个模型必然双向」**：错。全局边在连接定义上对称；但任务不同全局位置不同，自回归版本仍受因果掩码约束。全局边的对称性与模型是否双向是两件事。
3. **「ETC 就是 Longformer 加几个全局 token」**：错。ETC 有 global/local 双流、四种交互类型、结构化相对位置编码与 CPC 预训练的完整设计。
4. **「BigBird 证明了任意稀疏注意力等价于全注意力」**：错。通用逼近与图灵完备针对其特定结构与假设，不保证训练/推理效果等同，也不可推广到任意稀疏图。
5. **「全局 token 必然是 attention sink、必须永久保留 K/V」**：错。全局 token 是连接设计，sink 是运行时现象，KV Cache 保留是存储策略；三者可能重合但概念独立。

## 9. 一句话总结

> **全局-局部注意力不是单一算法，而是同一层内组合局部连接与跨区域通信路径的一类设计：全局 Key 列提供共享入口，全局 Query 行提供汇聚，双向全局 token（Longformer）、双流结构（ETC）、随机边（BigBird）以不同方式补齐长程通道，把边数压到 $O(Sw+Sg)$；而层间编排与 KV Cache 属于另外两个设计维度，不能与连接模式混为一谈。**
