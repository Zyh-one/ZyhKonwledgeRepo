# DSA：DeepSeek 稀疏注意力（学习型稀疏索引）

> 主题：计算轴路线②「学习型稀疏索引」的机制篇，拆解 DSA（DeepSeek Sparse Attention）。重点梳理**索引器打分与 Top-k 的张量流、与 MLA 组合后的完整注意力路径（Prefill/Decode 两条）、full/shared 层交替、索引缓存的显存账、训练-推理一致性**。谱系（MoBA→NSA→DSA）只作定位用，演进时间线见 [计算轴概述](计算轴概述.md) §3、§6。
>
> 阅读前提：[MHA](../存储轴/MHA.md)、[MLA](../存储轴/MLA.md)（本文大量复用其压缩-还原与权重吸收记法）、[滑动窗口注意力](滑动窗口注意力.md)（路线①对照）。

---

# 1. 定位与核心结论

DSA 属于**学习型稀疏索引**：保留 `点积+Softmax` 的注意力公式，但让模型**自己决定每个 Query 看哪些 token**——用一个轻量索引器先打分选 top-k，再对选中的 token 做完整 MLA 注意力。与路线①（滑动窗口）的本质区别在选择权的归属：

|            | 滑动窗口（路线①）     | DSA（路线②）               |
| ---------- | ---------------------- | --------------------------- |
| 谁定可见集 | 人（固定最近 w 个）    | 模型（按内容打分选 top-k）  |
| 长程依赖   | 只能靠多层传播间接触达 | 可直接选中远端关键 token    |
| 额外开销   | 无                     | 索引器投影 + 打分 + Top-k   |
| 复杂度     | `O(S·w)`            | `O(S·k)`，k 为 topk 上限 |

复杂度账：Prefill 的注意力配对从 `O(S·L)`（全长）降到 `O(S·k)`；Decode 单步从 `O(L)` 降到 `O(k)`——**每步代价不再随上下文增长**（注意索引器自身仍要扫全长，见 §3.3/§8）。代入 GLM-5.3 实例 `k=2048`：对 `S=1M` 而言，主注意力配对数差三个数量级。

```text
全长:    Q×K^T 逐对算分        [S, L]      O(S·L)
DSA:     索引器粗筛 → I        [S, 2048]   只对 I 上的配对做完整注意力
```

# 2. 谱系定位：MoBA → NSA → DSA

三代同属「模型自己选」，差异在选择粒度与开销：

- **MoBA**：门控网络按**块**选 token——粒度粗、显存粒度粗糙；
- **NSA**（DeepSeek，2025-02）：三分支并行——**压缩分支**（块内池化给全局低频视野）、**选中分支**（门控选 top-n 块）、**滑窗分支**（保局部连续语义），端到端可训练、块稀疏对齐硬件；
- **DSA**（DeepSeek-V3.2，2025-09）：砍掉压缩分支与三流并行链路，收敛为**「索引 top-k + anchor 兜底」两件事**——token 级选择、索引开销压到最低，与 MLA 低秩路径协同。

一句话：NSA 用三个分支换表达力，DSA 发现「一个足够好的索引器 + MLA」就够了。DSA 与存储轴的 MLA 完全正交：MLA 压**每个 token 的字节**（通道轴），DSA 压**要看 token 的个数**（序列轴），乘法叠加（见 [计算轴概述](计算轴概述.md) §5）。

# 3. 索引器机制

## 3.1 打分：轻量投影 + 多头均值

两个版本的差异值得分开记（易混点）：

- **DeepSeek-V3.2 原版**：索引打分**复用主注意力的 Q/K 投影权重组合**，不引入新参数——这是它「训练开销极低」的直接原因（据 V3.2 技术报告）；
- **GLM-5.3/5.2**：config 的 `index_n_heads=32`、`index_head_dim=128` 表明配了**独立索引投影** `W_qidx`/`W_kidx [4096, 6144]`（字段已确认，权重形状为合理推断；两个版本差异尚待 GLM 官方实现确认）。

打分流程（以 GLM 为例，合理推断）：

```text
X_norm [S, 6144] × W_qidx [4096, 6144] → Q_idx [S, 32, 128]
X_norm [S, 6144] × W_kidx [4096, 6144] → K_idx [L, 32, 128]
score = (1/(32·128)) · Σ_h Q_idx,h · K_idx,h^T  →  [S, L]    （头间求均值，一套全局索引）
I = topk(score, k=min(L, 2048))                →  [S, 2048]
```

注意头均值的意义：产出的是**全体头共享的一套索引**，不为主注意力 64 头各生成一套——索引器头数（32）与主头数（64）解耦，是 config 已确认的独立超参。

## 3.2 Top-k 与 anchor：动态选 + 静态保底

- **动态 top-k**：按 3.1 的分数沿 L 轴选 `k=2048` 个位置；
- **anchor**：序列**开头固定数量的 token 无条件入选**（`I = I_anchor ∪ I_topk`）。动机：开头沉淀 System Prompt/任务定义等全局信息；且 Softmax 分母需要 sink 吸收残余权重（呼应 [滑动窗口注意力](滑动窗口注意力.md) §5.4 的 attention sink）。DeepSeek-V3.2 论文口径 anchor 取开头 2048 个 token（与 topk 同值）；GLM 的 anchor 数量未从 config 证实（尚待确认）。

`L ≤ k` 时 topk 退化为全量因果注意力——DSA 的收益只在 `L` 显著超过 `k` 后出现（见 §8 误区一）。

## 3.3 索引器自身的开销

- 推理：一次 `[S, 6144]×[6144, 4096]` 投影 + 全长打分 `[32, S, L]` + Top-k 排序。Decode 单步对全长 L 扫描（`[1,4096]×[4096,L]` 点积 + top-2048 排序），**主注意力省了，索引器没省**——但索引维度远小于主注意力，且 full/shared 交替再把这开销摊薄 3/4（§5）；
- 训练：DeepSeek 原版零新增参数、开销极低；GLM 独立投影的训练开销尚待确认（原版口径不应直接套用）。

# 4. 与 MLA 的组合张量流（GLM-5.3/5.2 实例）

DSA 不改动 MLA 的任何投影——它只在「注意力看多少 token」这一维上动刀。全程符号：`S`/`L` 同 §3，MLA 侧记法沿用 [MLA](../存储轴/MLA.md)。config 已确认：nope=192、rope=64、V=256、`r_kv=512`、64 头。

```text
X_norm [S, 6144]
 ├─ 索引器: W_qidx/W_kidx [4096,6144] → Q_idx/K_idx [·,32,128] → score [S,L] → I [S, 2048]
 └─ MLA KV: W_dkv [576,6144] → c_KV [L, 512] ★落 Cache
            W_kr  [64,6144]  → k_rope [L, 64]  ★落 Cache（已旋转）
 主注意力只对 I 选中的 2048 个位置的 c_KV / k_rope 进行
```

**Prefill**——显式还原或稀疏 kernel 两条实现路径：

```text
方式A 显式 gather:  c_KV[I] → [S, 2048, 512] → W_uk [12288,512] → K_nope [S,2048,64,192]
                    k_rope[I] → [S, 2048, 64]
方式B 块稀疏 kernel: 不物化 gather 结果，算子内按 I 动态加载 c_KV 瓦片计算
随后标准 MLA 注意力: score = (Q_nope·K_nope + Q_rope·k_rope)/√256 ∈ [S,64,2048]
                    O = softmax(score)·V ∈ [S,64,256] → × W_o → [S,6144]
```

（`W_uv [16384,512]` 还原 V 的路径同 [MLA](../存储轴/MLA.md) §2，此处省略。）

**Decode**——权重吸收 + 按 I gather（与 [张量维度变化流程](../../../模型结构/GLM-5.2/张量维度变化流程.md) §3.5 完全同一条路，仅 KV 侧换成 gather 出的 2048 行）：

```text
Q_abs,h  = Q_nope,h · W_uk,h^T                    192→512    [1, 64, 512]
score    = Q_abs,h · c_KV[I]^T + Q_rope,h · k_rope[I]^T      [1, 64, 2048]
O_lat,h  = softmax(score) · c_KV[I]                            [1, 64, 512]
输出     = Σ_h O_lat,h · (W_uv,h · W_o,h)                      512→6144/头
```

要点：DSA 的稀疏化落在 **gather 的行数**上——MLA 吸收路径里所有形状的 `L` 全部替换为 `2048`，其余一字不变。这就是「正交叠加」的具体含义。

# 5. Prefill/Decode 时序与 full/shared 层交替

## 5.1 时序：先索引，后注意力

每层严格执行 `RMSNorm → 索引器打分/选点 →（gather）→ MLA 主注意力`。Decode 单步时间线：

```text
[RMSNorm] → [Q_idx 投影] → [与 K_idx 缓存点积 1×L] → [top-2048] → [gather KV] → [MLA 吸收路径]
```

## 5.2 full/shared 交替（GLM-5.3 config 已确认）

`index_topk_freq=4`：**1 层 full + 3 层 shared 循环**。全网 78 层实测 21 层 full（层 0,1,2,6,10,…,74——前 3 层连续 full，此后每 4 层一次）+ 57 层 shared。

```text
Layer 0 [full]:   W_qidx/W_kidx 投影 + 打分 → 生成 I_0 → 稀疏 MLA
Layer 1-3 [shared]: 跳过索引计算，直接复用 I_0 → 稀疏 MLA
Layer 4 [full]:   重新打分 → I_4
...
```

为什么可以共享（合理推断，定性）：深层表征虽然逐层变化，但**关注的上下文对象**（关键实体、指代先行词、任务前提）在相邻 3-4 层间变化缓慢——同一批 token 值得看，换一套索引收益小、重算代价大。共享把索引开销直接摊薄 75%。这正是 [计算轴概述](计算轴概述.md) §4「交替」设计语言的又一实例（与 Gemma 局部:全局交替、MoE 前 3 层 dense 同构）。

# 6. KV Cache：索引缓存的反超账

每 token 进 Cache 的张量（bf16，2 B/元素）：

| 张量       | 形状/token/层 | 出现层           | 字节/token/层 |
| ---------- | ------------- | ---------------- | ------------- |
| `c_KV`   | `[512]`     | 全 78 层         | 1024 B        |
| `k_rope` | `[64]`      | 全 78 层         | 128 B         |
| `K_idx`  | `[32,128]`  | 仅 21 个 full 层 | 8192 B        |

- MLA 主缓存：`78 × 576 × 2 = 87.75 KB/token`
- 索引缓存：`21 × 4096 × 2 = 168 KB/token`，合计 **≈ 255.75 KB/token**

三个值得记住的账（更细的推导见 [张量维度变化流程](../../../模型结构/GLM-5.2/张量维度变化流程.md) §5）：

1. **索引缓存比 MLA 主缓存还大**（168 vs 87.75 KB）——MLA 把潜维压到 512，索引器却要 4096 维保区分度；DSA 省的是算力，**没有省 Cache**；
2. **不共享的代价**：若 78 层全 full，索引缓存 `78×8 = 624 KB/token`，加主缓存约 712 KB/token——长上下文显存不可承受。shared 层复用索引的本质收益之一就是**免存 K_idx**；
3. 引擎若为省显存不缓存 K_idx，shared 层须重算索引——算力与显存的真实现场权衡（尚待确认：serving 引擎的实际取舍）。

# 7. 训练与推理一致性

推理时硬截断 top-k 而训练时看全长，会造成分布偏移：Softmax 分母从全量 token 的累加骤缩到 2048 个，残余权重分布被强行改变；模型在稠密训练下学会的「背景 token 分摊注意力」的补偿机制也随之失效。所以稀疏方案应当在**训练时就走 top-k 路径**。

不必从零重训：DeepSeek-V3.2 报道从稠密预训练权重出发，**千步级微调**（约 1k 步）即恢复甚至超越原稠密模型的长文本表现——注意力矩阵天然存在稀疏聚集倾向，模型适应归一化环境变化很快。GLM-5.3 是否走同样路径尚待确认。

# 8. 常见误区

1. **「短序列用 DSA 也更快」**：`L ≤ 2048` 时 topk 退化为全量注意力，白付索引器开销，端到端略慢于纯 MLA；
2. **「shared 层没有稀疏索引」**：shared 层同样是稀疏的，只是索引**复用** full 层结果，不是稠密层也不是局部层；
3. **「DSA 与 MLA 二选一」**：正交——MLA 压通道（每 token 字节）、DSA 压序列（看几个 token），GLM-5.3 两者叠加才有 1M 上下文；
4. **「DSA 省显存」**：省的是算力与带宽；K_idx 索引缓存实测比 MLA 主缓存还大，无 shared 交替时反而加剧 Cache 压力；
5. **「索引打分零开销」**：索引器每步仍对全长 L 点积 + top-k 排序（Decode 单步 `O(L)`），只是维度小、且 3/4 层被 shared 摊薄；
6. **「索引头数须对应主头数」**：解耦——32 个索引头头均值出一套全局索引，主注意力 64 头共用。

# 9. 一句话总结

> **DSA 用一个轻量索引器（复用或独立于 MLA 投影）对全长打分选 top-2048 + anchor 兜底，让 MLA 注意力只在选中的 token 上执行，把复杂度从 O(S·L) 压到 O(S·k)；full/shared 层交替把索引开销摊薄 3/4，代价是一份比主缓存还大的 K_idx 索引缓存。它与存储轴的 MLA 正交叠加，共同构成 GLM-5.3 1M 上下文的算力与显存基础。**
