# 局部与全局层交替

> 单个滑窗层只能直接读取最近 `w` 个 token。为了在节省大部分计算的同时保留长程信息通道，一些模型把多数层设为局部滑窗层，少数层设为全注意力层。本文专门讲这种**层级交替**；单层机制见 [滑动窗口注意力](滑动窗口注意力.md)。

---

# 1. 先分清「局部」和「全局」

在本文中：

- **局部层（local/sliding layer）**：层内每个 query 最多看最近 `w` 个 token；
- **全局层（global/full layer）**：层内使用普通 causal attention，每个 query 能看所有更早位置。

一个简化的层序列可以是：

```text
L  L  L  L  L  G  L  L  L  L  L  G ...
└─五个局部层─┘  ↑
                  全局层
```

它改的是模型的 `L`（层）维编排，不是在单层内发明第三种注意力公式：局部层仍是滑窗，全局层仍是标准 causal attention。

## 1.1 与 token 级「全局注意力」的区别

「局部—全局注意力」这个名称有歧义。Longformer 一类方法可以在**同一层**内让普通 token 使用局部窗口，而少数特殊 token 拥有全局连边。本文讲的不是这种 token 级混合，而是**整层交替**。

---

# 2. 为什么不全部使用滑窗

在一个局部层里，当前位置无法直接与距离超过 `w` 的历史位置交互。叠加多层确实可以通过邻近 token 中继传递信息，但传递路径变长，也不再是对远端原始 KV 的直接读取。

全局层提供定期的全序列会合点：

```text
局部层：便宜地处理附近信息
    ↓
全局层：让每个位置直接汇总所有历史位置
    ↓
局部层：继续加工已混入长程信息的表示
```

因此，窗口大小 `w` 和全局层频率是两个独立旋钮：

- `w` 越小，局部层越便宜，但对全局层的依赖通常越强；
- 全局层越密，长程信息通道越频繁，但计算和 cache 代价也越高。

---

# 3. 两类层的张量流没有粘在一起

设局部层数为 `L_local`，全局层数为 `L_global`。每层都有自己的 Q/K/V 投影和 KV Cache：

```text
第 l 层输入 X_l
  ├─ local 层  → 只在窗口内做 attention → X_{l+1}
  └─ global 层 → 对全部历史做 attention → X_{l+1}
```

两类层通过残差流 `X_l → X_{l+1}` 传递表示，但不共享同一份 K/V。因此全局层需要全历史，并不意味着局部层也必须保留全历史。

---

# 4. 计算量与 KV Cache 总账

## 4.1 Prefill

忽略头数和头维等常数：

```text
纯全注意力:  O((L_local + L_global) · S²)
交替模型:      O(L_local · S·w + L_global · S²)
```

只要仍有全局层，整体渐进式中仍含 `S²` 项；但全局层数减少后，实际常数可以显著下降。

## 4.2 Decode

每生成一个 token，attention 需读取的 KV 数量约为：

```text
L_local · w + L_global · S
```

因此它不会像纯滑窗模型那样完全与上下文长度解耦；随 `S` 增长的代价被压缩到少数全局层上。

## 4.3 KV Cache

KV Cache 按层保存。如果推理框架对局部层使用 sliding/rolling cache，则总体序列维规模约为：

```text
L_local · w + L_global · S
```

而不是「因为存在全局层，所有层都必须保留 `S`」。实际是否获得这部分显存收益，仍取决于推理框架是否实现了混合的按层 cache。

---

# 5. 两个典型例子

## 5.1 Gemma 3：五个局部层，一个全局层

Gemma 3 的文本配置使用 `sliding_window_pattern: 6`，对应每 6 层中 5 个滑窗层和 1 个全局层。例如 4B 配置的局部窗口为 `1024`。

```json
{
  "sliding_window": 1024,
  "sliding_window_pattern": 6
}
```

## 5.2 gpt-oss：滑窗层与全局层 1:1 交替

gpt-oss 的窗口为 `128`，注意力层在 banded/sliding 与 full attention 之间逐层交替，而不是「3 个局部层 + 1 个全局层」。

```json
{
  "sliding_window": 128,
  "layer_types": [
    "sliding_attention",
    "full_attention",
    "sliding_attention",
    "full_attention"
  ]
}
```

---

# 6. 如何从 config.json 判读

| 字段 | 作用 | 注意 |
| --- | --- | --- |
| `sliding_window` | 局部层的窗口大小 | 不足以单独说明哪些层是局部层 |
| `layer_types` | 显式列出每层类型 | 可直接统计 local/full 比例 |
| `sliding_window_pattern` | 用周期规则生成层类型 | 需结合对应模型代码确认周期内的排列 |
| `cache_implementation` | 推理 cache 策略提示 | 字段语义依赖框架版本 |

判读时应按以下顺序：

1. 先看是否有 `sliding_window`，确认模型是否声明了局部窗口；
2. 再看 `layer_types`、`sliding_window_pattern` 或模型实现，判断是全部层滑窗还是局部/全局交替；
3. 最后查推理框架的 cache 实现，不要从模型结构字段直接推断实际显存分配。

---

# 7. 小结

- 局部/全局交替是层级架构，不是新的单层 attention 公式；
- 局部层降低多数层的计算与访存，全局层定期提供直接长程信息通道；
- 它的 Prefill、Decode 和 Cache 代价都可分解为局部层项与全局层项；
- KV Cache 按层管理，全局层保留全历史不会在原理上迫使局部层也保留全历史。

固定窗口和固定交替的共同上限是：「看哪里」由人预先规定，不会随内容改变。让模型按内容选择历史 token，就进入计算轴的下一条路线：学习型稀疏索引。
