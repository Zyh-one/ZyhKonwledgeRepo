# 计算轴概念：每步看多少 token

> 承接 [注意力模块演进](../注意力模块演进.md) §2：存储轴（KV Cache 怎么变小）与位置轴（token 顺序怎么进入分数）都没有动一件事——**注意力每步看全序列**，复杂度始终 `O(S²)`。本文是计算轴的**概念篇**：说清 `O(S²)` 到底卡在哪、削减它的三条路线各自的本质是什么；三篇机制篇（滑动窗口、稀疏索引、线性注意力）将在本目录逐一展开。

---

# 1. 问题：满注意力的两堵墙

[自回归生成](<../../0-Transformer%20自回归生成的最小闭环.md>) 里注意力分数是 `Q×K^T → [S, S]`——每个 token 都和所有 token 算一次分。序列一长，这堵「平方墙」在两个阶段分别显形：

## 1.1 Prefill 墙：算力

Prefill 要一次性算完整个 `[S, S]` 分数矩阵。代入 GLM-5.3 的量级（见 [GLM-5.3](../../../模型结构/GLM-5.3.md)）：`S=1M` 时单头单层就是 `1e12` 个分数，再乘 64 头 × 78 层，到达 `1e16` 量级——**平方墙是硬上限，压存储救不了它**：MLA 把每个 token 的 KV 压薄了（存储轴），但分数矩阵还是 `S×S`，一个都少不了。

## 1.2 Decode 墙：访存与算力

Decode 每生成 1 个 token，都要把全部 `S` 个 KV 读一遍、算一遍分——单步代价 `O(S)`，**上下文越长，每步越慢**。存储轴让每 token 的字节变小（MLA 压到约 `r_kv` 量级），但「要读的 token 个数」一个没少。

## 1.3 两堵墙的共同根源

注意力矩阵是**满**的。计算轴的全部工作就是把它变稀疏，手段分两大类：**删配对**（保留 `点积+Softmax` 公式，但只对一小部分 token 对算）与**换公式**（连 `点积+Softmax` 都换掉，把历史压成固定大小的状态）。前者按「谁来决定删哪些」又分两档，合成三条路线。

# 2. 三条路线地图

| 路线 | 本质 | 复杂度 | 代表 | 需要训练 |
| ---- | ---- | ------ | ---- | -------- |
| ① 硬编码稀疏 | 人规定看哪里 | `O(S·w)` | 滑动窗口（Mistral）、local:global 交替（Gemma、gpt-oss） | 否 |
| ② 学习型稀疏索引 | 模型自己选 top-k | `O(S·k)` | NSA、DSA（DeepSeek-V3.2、GLM-5.3） | 是（NSA） |
| ③ 线性注意力 | 换公式，历史压成固定状态 | 每 token `O(d²)`，与 S 无关 | Gated DeltaNet、KDA、Lightning Attention | 是 |

## 2.1 路线①：硬编码稀疏——人规定看哪里

最朴素也最古老：不看全部，只看**最近 w 个 token**（滑动窗口，`O(S·w)`）；或按层交替——多数层只看局部、少数层看全局（Gemma-2/3 的 local:global ≈ 5:1，gpt-oss 约 1/4 层全局）。不引入任何训练，改动只在 kernel 与调度。但有个著名教训：**稀疏不是随便删**——把开头的「sink」token 删掉，Softmax 分布会塌（attention sink / StreamingLLM），窗口必须给它们留位。

## 2.2 路线②：学习型稀疏索引——模型自己选看谁

硬编码的形状是死的，长程该看谁因内容而异。这一路线加一个**索引器**先跑一遍粗筛，选出 top-k 个值得看的 token，再对它们做完整注意力，复杂度降到 `O(S·k)`。GLM-5.3 的 DSA 即此路：`index_topk=2048`，对 `S=1M` 而言差三个数量级——与 MLA 的显存基础互补，**这是 GLM-5.3 能开 1M 上下文的算力基础**（见 [GLM-5.3](../../../模型结构/GLM-5.3.md) §4，机制按 config 字段推断，细节待确认）。

## 2.3 路线③：线性注意力——干脆换掉「点积+Softmax」

前两条路线都保留注意力公式本身；这一条把注意力改写成 **RNN 递推**：维护一个**固定大小的状态矩阵**，每来一个 token 用 `O(d²)` 把它的信息「记账」进状态，而不是回头翻全部历史——KV Cache 从 `O(S)` 变 `O(1)`，decode 单步与上下文长度无关。代价是固定状态装不下精确历史，大海捞针式检索弱于满注意力，所以主流模型都不敢全换，而是「线性层为主 + 每 3-4 层一个全注意力层兜底」的混合形态（Qwen3-Next、Kimi K2 Thinking、MiniMax-M1 都是这个模式）。

# 3. 交替：现代模型的通用设计语言

把三条路线放在一起看，会发现一个反复出现的模式——**关键层保真、其余层省钱**：

- Gemma-2/3：5 层局部 : 1 层全局；
- gpt-oss：约 1/4 层全局，其余滑窗；
- DSA：`index_topk_freq=4`——1 层 full 索引 + 3 层 shared 复用（GLM-5.3 config）；
- 线性混合：约 3:1 的线性:全注意力（Qwen3-Next 等）；
- MoE：前 3 层 dense，其余 75 层稀疏专家（GLM-5.3 `first_k_dense_replace=3`）。

局部的、便宜的机制占多数层，全局的、昂贵的机制少量插入兜底——这个「交替」模式横跨计算轴三条路线，甚至蔓延到 MLP 侧。记住它，看到任何新架构的层配置都能秒懂一半。

---

# 4. 与前两条轴的正交性

三条轴改的是三个独立量，可乘法叠加，GLM-5.3 是完整实例：

- **存储轴**：MLA 压薄**每个 token 的 KV 字节数**（`S` 个、每个更小）；
- **计算轴**：稀疏索引减少**要看 token 的个数**（`k` 个）；
- **位置轴**：RoPE 只作用于解耦的 `q_rope/k_rope` 小段，与「谁被选中」无关。

有效注意力代价 ≈（要读的 token 数）×（每 token 字节数）——前两条轴各压一个因子，互不掣肘。

---

# 5. 小结与后续

- 满注意力的两堵墙：Prefill 的 `O(S²)` 算力墙、Decode 的 `O(S)` 单步墙，共同根源是注意力矩阵是满的；
- 三条削减路线：**硬编码稀疏**（人定形状）、**学习型稀疏索引**（模型选 top-k）、**线性注意力**（换公式、固定状态）；
- 通用设计语言：交替（关键层保真、多数层省钱）。

机制篇按依赖顺序展开：[滑动窗口]（待写，路线①）→ 稀疏索引（待写，路线②，NSA/DSA）→ 线性注意力（待写，路线③）。
