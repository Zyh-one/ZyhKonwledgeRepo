# 注意力模块的演进与学习路线

> 本文是「注意力模块演进」系列的总览与学习路线。起点是 [自回归生成](<../0-Transformer%20自回归生成的最小闭环.md>) 里的**单头 Self-Attention**——全系列唯一的「无变体」基准：单头、无位置编码、无 Cache 优化。从它出发，注意力模块沿三条正交的轴演进：**存储**（KV Cache 怎么变小）、**位置**（token 顺序怎么进入分数）、**计算**（每步看多少 token）——每一代都在解决上一代留下的问题。本文不深入张量细节，只给演进地图与阅读顺序；各变体的张量流在本模块的轴子目录中单独展开。

---

# 1. 问题：单头 Self-Attention 只能提取单一维度特征

在 [自回归生成](<../0-Transformer%20自回归生成的最小闭环.md>) 中，为了突出主线，我们把 Self-Attention 简化为**单头**：一组 `Wq/Wk/Wv`，投影出一组 `Q/K/V`，算一次 Attention。

但单头有一个根本局限：**它只能学出一组 Q/K/V 投影，意味着只能在「一个」语义子空间里建立 token 与 token 之间的关联。** 而一段 Prompt 中 token 间的关系是多维度的——有的关联来自语法结构、有的来自共指/指代、有的来自长程语义依赖、有的来自位置邻近。一组投影很难同时刻画这些彼此正交的关联维度。

既然一组投影不够，自然的想法就是**用多组投影并行**——这就是「分头」的动机。

---

# 2. 三条演进轴

注意力模块的演进落在三条**正交的轴**上——每条轴回答一个上一代结构留下的问题：

| 轴   | 回答的问题             | 走过的路                            |
| ---- | ---------------------- | ----------------------------------- |
| 存储 | KV Cache 怎么变小      | MHA → MQA → GQA / MLA             |
| 位置 | token 顺序怎么进入分数 | RoPE（MHA 原地旋转 / MLA 解耦旁路） |
| 计算 | 每步看多少 token       | 滑动窗口 → 稀疏索引 → 线性注意力   |

三条轴相互独立、可以叠加——GLM-5.3 就同时叠了 MLA（存储）+ RoPE 解耦（位置）+ DSA（计算），见 [GLM-5.3](../../模型结构/GLM-5.3.md)。

## 2.1 存储轴：K/V 存几份、存多小

一句话概括：**K/V 这组投影，是每个头各有一份，还是所有头共用一份，还是折中地分组共用，还是压成一份低维潜变量。**

一个容易搞反的印象：**这条轴上，只有 MHA 不是以「减少 KV 存储」为设计目标的**——MQA/GQA/MLA 诞生时针对的都是 KV Cache 的容量与带宽瓶颈（MQA 2019 直指 Decode 访存、GQA 2023 的动机就是 memory-bandwidth、MLA 2024 冲着长上下文 KV Cache 而来），区别只在压缩手段（共享份数 vs 压维度）；MHA 为表达力而生，在这条轴上只充当**未压缩的对照基准**，而不是演进方向的一站。

| 变体                                         | K/V 投影份数           | KV Cache 体积（相对 MHA）   | 代表模型                       |
| -------------------------------------------- | ---------------------- | --------------------------- | ------------------------------ |
| **MHA**（Multi-Head Attention）        | 每个头各一组           | 1×（基准）                 | GPT、LLaMA 等多数基座          |
| **MQA**（Multi-Query Attention）       | 所有头共用 1 组        | 1/N                         | PaLM、StarCoder 等             |
| **GQA**（Grouped-Query Attention）     | 分成 G 组，每组内共用  | G/N                         | LLaMA-2(部分)/LLaMA-3、Mistral |
| **MLA**（Multi-head Latent Attention） | 一份与头数无关的潜变量 | ≈ r_kv/N·d，可比 MQA 更小 | DeepSeek-V2/V3、GLM-5.3        |

- **MHA**：每个头独立持有 `Wk/Wv`，表达力最强，但 KV Cache 体积最大。
- **MQA**：所有头共用同一组 `Wk/Wv`，KV Cache 缩到 1/N，Decode 最省，但表达力损失较明显。
- **GQA**：介于两者之间——把 N 个头分成 G 组，组内共享 `Wk/Wv`。`G=1` 退化为 MQA，`G=N` 退化为 MHA，是目前主流的折中选择。
- **MLA**：不走共享投影，而是把 KV 压成一份低维潜变量再还原——**减少的是维度而非份数**，保留每头独立 K/V 的表达力。张量流见 [MLA.md](存储轴/MLA.md)，为什么这么设计见专题篇 [MLA动机](存储轴/MLA动机.md)。

这条轴上两条主流思路：**共享投影**（MQA/GQA，省份数）与**低秩压缩**（MLA，省维度），MHA 是它们共同的对照基准。

## 2.2 位置轴：RoPE 怎么注入

主流程 `Q×K^T → Softmax → ×V` 对 token 顺序不敏感（交换两个 token，分数不变），位置信息必须注入 Q/K——RoPE 用「按位置旋转」解决，机制见 [rope](位置轴/rope.md)。它在这条轴上的落点随存储轴的选择而**分岔**：

- **MHA/MQA/GQA**：算分数前对每头 Q/K **原地旋转**，形状全程不变，RoPE 对张量流零影响（[rope](位置轴/rope.md) §4）；
- **MLA**：低秩压缩与原地旋转不可兼得（[MLA](存储轴/MLA.md) §3.1），位置信息改走「**解耦 RoPE**」小维旁路——K 拆 nope/rope 两段、`k_rope` 转好单独缓存（[MLA](存储轴/MLA.md) §3.2）。

## 2.3 计算轴：每步看多少 token

前两条轴都没有动「注意力每步看全序列」这件事，复杂度仍是 `O(S²)`。长上下文（1M token）下，第三条轴改的是**计算范围**：滑动窗口（Mistral）、Sparse Transformer，直到 2024-2025 的稀疏索引一代（NSA、DSA、MoBA）——每层只对索引选出的 top-k token 做注意力，把 `O(S²)` 降到 `O(S·k)`。GLM-5.3 的 DSA（`index_topk=2048`）即此路（[GLM-5.3](../../模型结构/GLM-5.3.md) §4，机制待确认）。三条路线的全景见 [计算轴概述](计算轴/计算轴概述.md)；固定稀疏的机制篇已拆为 [滑动窗口注意力](计算轴/滑动窗口注意力.md) 和 [局部与全局层交替](计算轴/局部与全局层交替.md)，**稀疏索引、线性注意力两篇待写。**

# 3. 发展时间线

```text
2017  MHA    ——  Transformer 原始论文（Attention is All You Need）
                  每个头独立 K/V，作为标准结构沿用至今
2019  MQA    ——  Shazeer《Fast Transformer Decoding》
                  极端共享：所有头共用一组 K/V，Decode 显存大幅下降
2021  RoPE   ——  RoFormer
                  旋转位置编码：相对位置从旋转的合成中掉出来（位置轴）
2023  GQA    ——  Google《GQA: Training Generalized Multi-Query ...
                  Transformer Models from Multi-Head Checkpoints》
                  分组共享，在表达力与显存间取折中，成为新一代基座主流
2024  MLA    ——  DeepSeek-V2
                  低秩压缩 KV，另一条削减 KV Cache 的路线（存储轴）
2025  NSA/DSA ——  DeepSeek NSA、GLM DSA 等
                  稀疏索引：每层只看 top-k token，长上下文的算力路线（计算轴，待写）
```

整体趋势：**从「每个头各存一份」走向「少存（存储轴）、带位置（位置轴）、少算（计算轴）」，同时尽量不损失表达力。**
