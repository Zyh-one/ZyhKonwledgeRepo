# 注意力变种：头间如何共享 K/V

> 承接 [MHA](MHA.md)：多头为表达力而各持一组 K/V 后，工程代价随之浮现。本文是存储轴的**概念篇**——定义什么是「注意力变种」、说清它为什么而生；各变体的张量流见同目录 MHA / MQA / GQA / MLA 各篇，三条演进轴的全景与学习路线见 [注意力模块演进](../注意力模块演进.md)。

---

# 1. 什么是「注意力变种」

多头成立后，一个新问题浮现：**这些头之间的 K/V 投影，是各自一份，还是共享？** 对这个问题的不同回答，就构成了**注意力变种**。

换句话说，注意力变种改的不是自回归生成里那条「Q×K^T → Softmax → ×V」的主流程，而是**K/V 在「头」这个维度上的排布方式**——主流程不变，变的只是 K/V 张量在头维度上的形状与体积。MHA（每个头各持一组 K/V）是其中最基础的一种，MQA/GQA 则是让多个头共享 K/V 的变体。

---

# 2. 变体的动因：在并行背景下削减 KV Cache

既然多头为表达力而各持一组 K/V，为什么又要共享？因为多头带来了一个工程后果：KV Cache 随头数 N 线性膨胀。自回归生成中单头 KV Cache 是：

```text
K Cache: [S, H]
V Cache: [S, H]
```

变成 MHA 后，每一层、每一步都成为：

```text
K Cache: [N, S, head_dim]
V Cache: [N, S, head_dim]
```

这本身并不致命。真正让「削减 KV Cache」成为显式动机的，是**当多头与多卡并行（TP 切分头）结合后**：每个头各存一份 K/V，使 Decode 阶段的访存量与显存占用成为瓶颈（memory-bound），长上下文与多卡部署的压力被放大。

MQA/GQA 正是在这一背景下出现的变体——**在 MHA 已成立、表达能力已满足的前提下**，通过让多个头共享 K/V 投影来削减 KV Cache 的份数，省显存、加速 Decode、让单卡装下更长上下文。也就是说，减少 KV Cache 是变体的直接目的，但它仍是「多头之上」的附带优化，而非多头本身存在的根因。

一句话区分：**多头为表达力而生，变体为工程效率而生。** 至于 MLA 为什么不共享、改走低秩压缩，见 [MLA动机](MLA动机.md)。
