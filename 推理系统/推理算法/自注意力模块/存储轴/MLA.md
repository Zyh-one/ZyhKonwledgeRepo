# MLA：多头潜注意力（Multi-head Latent Attention）

> 本文是「注意力变种」系列的第 4 篇，也是「低秩压缩」路线的代表（DeepSeek-V2 提出）。前三种变体靠**共享 K/V 投影**削减 Cache，MLA 则走另一条路：**把 KV 压缩成一个低维潜变量再还原**。先总览 MLA 对 MHA 四个权重矩阵的改写，再从 `X : [S, H]` 出发逐步走完一次完整的自注意力计算（含 Q 侧），随后看 RoPE 的解耦注入方式与 KV Cache 的削减机理。本文是**机制篇**——只讲「怎么运转」；「为什么这么设计」（共享下投影的动机、MQA/GQA 困境与低秩分解的思想谱系）见 [MLA动机](MLA动机.md)。
>
> 关联：[MLA动机](MLA动机.md)（动机篇）、[MHA](MHA.md)（张量流写法的共同基准）、[rope](../位置轴/rope.md)（RoPE 本体）、[注意力模块演进](../注意力模块演进.md) §2。

# 0. 符号约定

```text
S       : 序列长度
H       : 隐藏维度
N       : 头数
d       : 每头维度，d = H / N
r_kv    : KV 低秩潜维度（= kv_lora_rank）
r_q     : Q 低秩潜维度（= q_lora_rank）
d_rope  : RoPE 解耦头维（K/Q 位置部分的小维，见 §3）
```

> **命名约定（防混淆）**：`r_*` 与 `d_*` 是两个语义族，互不耦合。`r_kv`/`r_q` 是低秩分解的**秩**（潜维）——跨头共享、独立超参，直接对应 config 的 `kv_lora_rank`/`q_lora_rank`，与 `d = H/N` 没有任何数值或推导关系；`d`/`d_rope` 才是**头维**（每头一份）。三者都取小，但买到的东西不同：`r_kv ≪ N·d` 买到 Cache 压缩；`r_q` 买到 Q 侧参数/算力的低秩化（Q 不进 Cache，与存储无关）；`d_rope` 是解耦 RoPE 的新增开销、刻意取小。

MHA 的 KV Cache 是 `[N, S, d]`，总量 `2·N·S·d`。MLA 的目标是：**每层只缓存一个 `[S, r_kv]` 的潜变量，且 `r_kv ≪ N·d`**，从而把 Cache 压到远小于一组的体量。

---

# 1. MLA 的权重矩阵：MHA 四矩阵被拆成下/上投影

MLA 引发了自注意力权重矩阵的结构性变化：MHA 原本四个独立矩阵 `Wq/Wk/Wv/Wo`，其中 `Wq/Wk/Wv` 各被拆成「**下投影（降维）+ 上投影（升维）**」一对，`Wo` 仍保留为输出投影。先总览每个矩阵在 MLA 下的形态与形状（用 §0 的符号表示）：

| MHA 矩阵 | MLA 下的形态                                                 | 形状                                                                                  |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| `Wq`   | 下`W_dq` + 上 `W_uq`                                     | `W_dq:[H, r_q]`；`W_uq:[r_q, N·(d+d_rope)]`（每头 nope `d` + rope `d_rope`） |
| `Wk`   | 共享下`W_dkv` + 上 `W_uk`（nope）+ 直连 `W_kr`（rope） | `W_dkv:[H, r_kv]`（与 `Wv` 共享）；`W_uk:[r_kv, N·d]`；`W_kr:[H, d_rope]`    |
| `Wv`   | 共享下`W_dkv` + 上 `W_uv`                                | `W_dkv` 同上（与 `Wk` 共享）；`W_uv:[r_kv, N·d]`                               |
| `Wo`   | 仍是输出投影                                                 | `Wo:[N·d, H]`                                                                      |

结构要点：

- **`Wk` 与 `Wv` 共享下投影 `W_dkv`**——这是 MLA 把 K、V 缓存合一的关键：Cache 里只有一份 `c_KV`，而非 MHA 的两份 K/V。为何共享、思路从哪来，见 [MLA动机](MLA动机.md)。
- **`Wk` 多出一条直连 `W_kr`**，用于 RoPE 解耦的位置部分，不经潜变量、与 `W_dkv` 路径并列（机制见 §3）。
- **上投影 `W_uk`/`W_uv` 在推理时是否物化**，取决于「权重吸收」，留到 §4 详述；此处只需知道它们存在于权重文件中、是还原 K/V 的计算路径。

下面先走完「压缩-还原 + 完整注意力」主线（§2），再看「RoPE 解耦」如何在这条主线上为位置信息开旁路（§3）。

---

# 2. 压缩-还原：从 X 走完一次完整自注意力

MHA 里 `X → Q/K/V` 是三步独立投影、一步到位（[MHA](MHA.md) §1-§2）；MLA 的核心改动在 K/V 这条路上——**K/V 共享一个下投影 `W_dkv`，把 KV 压缩成一份低维潜变量 `c_KV` 存储**，即「共享下投影压缩、减少 KV 存储」。Q 侧则对称地做一次同构的压缩-还原。

本节从 `X` 出发，按 ①-⑥ 逐步走完一次完整的 MLA 自注意力计算，**暂不讨论位置编码**——RoPE 在 MLA 里的注入方式特殊，单独放在 §3。

输入：

```text
X : [S, H]
```

**① 压缩：K/V 共享下投影到潜变量**。把 `H` 维压到 `r_kv` 维：

```text
c_KV = X × W_dkv   →  [S, H] × [H, r_kv]  →  [S, r_kv]
```

`r_kv` 是与头数 N 无关的**秩超参**（潜维，不是头维，见 §0 命名约定），且**只有 `c_KV` 落 Cache**——K 与 V 合用这一份，「按头存储」从此改成「按潜变量存储」，MLA 削减 KV 存储的落点全在这一步。

**② 还原：上投影回 N·d 维**。两个上投影分别把 `c_KV` 撑回多头 K、V：

```text
K_raw = c_KV × W_uk   →  [S, r_kv] × [r_kv, N·d]  →  [S, N·d]
V_raw = c_KV × W_uv   →  [S, r_kv] × [r_kv, N·d]  →  [S, N·d]
```

**③ Q 的压缩-还原：与 K/V 同构但不缓存**。Q 走一条对称的两段路：下投影 `W_dq` 压到 `r_q` 维潜变量，再上投影 `W_uq` 还原回多头 Q：

```text
c_Q   = X × W_dq     →  [S, H] × [H, r_q]   →  [S, r_q]
Q_raw = c_Q × W_uq   →  [S, r_q] × [r_q, N·d]  →  [S, N·d]
```

**Q 不参与 Cache**：每步的 Q 都只来自当前 token 的 `X`，不存在跨 token 可复用的历史，所以 `c_Q` 现算现用、不落 Cache。

**④ 分头：与 MHA 完全一致**。reshape 最后一维 `N·d → (N, d)`，再 transpose 头维到最前：

```text
Q_raw / K_raw / V_raw : [S, N·d]  →  reshape (N, d)  →  Q / K / V : [N, S, d]
```

**⑤ 每头内的注意力：与 MHA 一字不差**。对第 `i` 个头（`i = 0..N-1`），取出 `Q_i, K_i, V_i : [S, d]`：

```text
Score_i  = Q_i × K_i^T       →  [S, d] × [d, S]  →  [S, S]
Weight_i = Softmax(Score_i)   →  [S, S]
O_i      = Weight_i × V_i     →  [S, S] × [S, d]  →  [S, d]
```

**⑥ 拼回 + 输出投影：与 MHA 完全一致**。N 个头的输出拼回 `[S, H]`，过输出投影 `Wo`：

```text
O : [N, S, d]  →  transpose + reshape  →  [S, H]
Y = O × Wo     →  [S, H] × [N·d, H]  →  [S, H]
```

至此一次完整的 MLA 自注意力从 `X` 走到 `Y`。①-⑥ 中**只有 ① 的 `c_KV` 与 Cache 有关**：⑤ 用的 K/V 是 ② 的计算结果。

这一步有四个结构要点：

- **MLA 的核心：K/V 共享下投影压缩**。`Wk`、`Wv` 在 MHA 里是两个独立矩阵，MLA 让它们**共用同一个下投影 `W_dkv`**，Cache 里只存一份 `c_KV`，K 与 V 的差异推迟到读取时的两个上投影（「存一份、读多路」）——减少 KV 存储的全部机理就落在这处共享上。为何共享、思路从哪来，见 [MLA动机](MLA动机.md)。
- **压缩-还原是一次低秩分解**：MHA 的 `Wk:[H, N·d]` 被拆成 `W_dkv × W_uk`（两段 matmul 等价于一个秩为 `r_kv` 的矩阵），`Wv` 同理拆成 `W_dkv × W_uv`。这不是训练后再做的近似压缩，而是**从第一轮梯度起就按这个参数化端到端学**（详见 [MLA动机](MLA动机.md)）。
- **Q 与 K/V 对称但角色不同**：Q 也拆成下/上投影，但 Q 从不进 Cache——Q 侧的压缩只为对称与控制计算量，与 Cache 削减无关；RoPE 给 Q 带来的拆段（q_rope）见 §3。

# 3. 解耦 RoPE：位置信息的旁路

§2 的流程里没有位置信息——注意力对 token 顺序不敏感的问题依旧存在。实际的 MLA 模型（DeepSeek-V2/V3、GLM-5.3 等）都用 RoPE 注入位置，但**不能像 MHA 那样对还原后的 K 原地旋转**，于是位置走了一条绕开潜变量的小维旁路——「解耦 RoPE」。本节先讲为什么照搬不了（§3.1），再仿照 §2 的写法、从 `X` 出发完整演绎带解耦 RoPE 的张量维度转换（§3.2）。

## 3.1 为什么不能照搬 MHA 的 RoPE

补充-zyh：这一部分“为什么不能照搬”，目前我没有完全清楚，后续在思考

MHA 的做法（[rope](../位置轴/rope.md) §2、§4）：算分数前，对每个头内的 `d` 维按 token 位置原地旋转 `φ_i(m) = m·θ_i`，形状全程不变。放到 §2 的流程上，两条「天然」的插入位置都不成立：

- **在还原后的 K 上旋转**：`K' = RoPE(W_uk·c_KV)`。旋转矩阵 `R_m` 随每个 token 的位置变化，进入点积后夹在中间成为 `W_uq^T · R_m · W_uk`——`R_m` 不是静态矩阵、折不进权重，§4 的吸收断掉；Decode 每步都得把全部 Cache 还原成 `[N, S, d]` 再旋转，Cache 省了、算力没省。
- **在潜变量 c_KV 上旋转**：RoPE 作用在**头内 `d` 维的二维对**上（每对配一个频率 `θ_i`），而 `c_KV` 的 `r_kv` 维是跨头混合的潜空间维度，两套维度语义对不上——旋转与上投影不可交换，`RoPE(c_KV)·W_uk ≠ RoPE(c_KV·W_uk)`，点积里相对位置相消的性质（[rope](../位置轴/rope.md) §3.3）被破坏。

结论：**低秩压缩与位置编码在同一条路径上不可兼得**，MLA 的答案是给位置单独开一条路。

## 3.2 完整演绎：MLA + 解耦 RoPE 的张量维度转换

§2 是剥掉位置编码的「干净版」，本节把它换成真实版——从 `X` 出发逐步走完带解耦 RoPE 的完整张量流，**维度变化全部以 §2 为基准标注**（每步括号里标对应关系）。先给一张总览，三个易混点一次看清——**k_rope 与 c_KV 无关、RoPE 不碰压缩-还原、旋转发生在投影之后**：

```text
K 的生成 ──┬─ 内容路（nope）：X → W_dkv → c_KV【落 Cache，从不旋转】→ W_uk → k_nope  ← §2 主线
          └─ 位置路（rope）：X → W_kr  → 立刻 RoPE【落 Cache，已转好】= k_rope    ← 绕开 c_KV 的旁路

Q 的生成 ──┬─ q_nope：X → W_dq → c_Q → W_uq → q_nope（每头 d 维）
          └─ q_rope：每头 d_rope 维，现算现转（同样出自 c_Q × W_uq 的拆段）
```

> 记号说明：§2 的 `K_i/Q_i` 是 `[S, d]` 的**整头矩阵**（含序列维）；本节小写 `k_i/q_i` 指**单个 token、第 i 个头**的向量（`score_i(m, n)` 按位置对 m、n 逐对描述）。另注：本文以统一的 `d` 表示 nope/V 每头维度；真实配置中 nope 与 V 的头维可以不同、也不再满足 `d = H/N`（GLM-5.3：H=6144、N=64、nope=192、V=256），不影响本节推导的结构。

**解耦 RoPE 发生在哪个阶段？** 总原则是「投影之后、算分数之前」，但 K/Q 时机不同，对齐到下面的 ①-⑦：

- **K 侧：生成该 token 的那一刻，转一次（②）**。Prefill/Decode 每算出一个新 token 的 K，顺序都是 `X × W_kr → 立刻旋转 → 落 Cache`——属于**生成期一次性动作**，此后任何一步都不再转 K（旋转角只依赖 K 自己的位置，与谁来查询无关）；
- **Q 侧：每步现算时转一次，具体就发生在 ④ 的拆段处**——`c_Q × W_uq` 的输出拆出 `Q_rope_raw`（⑤ 分头之前），按当前 token 的位置旋转一次，转完即用即弃、不缓存。即 Q 的旋转不在投影 matmul（`W_dq/W_uq`）之内、也不在 ⑥ 之内，而是**夹在 ④ 拆段与 ⑥ 点积之间的独立小步**（下文 ④ 里「按位置旋转」的标注即此处）；
- **注意力计算阶段（⑥，对应 §2 ⑤）：什么都不转**——拿到的 k_rope/q_rope 都是已旋转的成品，直接做两段点积相加。

输入：

```text
X : [S, H]
```

**① K/V 压缩（同 §2 ①，不变）**。`c_KV` 未旋转、照常落 Cache：

```text
c_KV = X × W_dkv   →  [S, H] × [H, r_kv]  →  [S, r_kv]        ← Cache：未旋转
```

**② K 位置旁路（新增，与 ① 并行）**。`W_kr:[H, d_rope]` 从原始 X 一步直连投影，**投影完立刻按位置旋转**：

```text
k_rope = RoPE(X × W_kr)   →  [S, H] × [H, d_rope]  →  [S, d_rope]   ← Cache：已转好
```

注意 `k_rope` **没有头维**——是 `[S, d_rope]` 而非 `[N, S, d_rope]`，跨头共享一份。转一次存成品：旋转角只依赖 K 自己的位置，未来任意 Q 与它点积，相对位置由「Q 现转 + K 已转」的旋转合成自动给出（[rope](../位置轴/rope.md) §3.3 的同频相消），Decode 不再旋转。

**③ K/V 还原（同 §2 ②，但 K 只还原出 nope 段）**。`W_uk` 只管内容、不带位置：

```text
K_nope_raw = c_KV × W_uk   →  [S, r_kv] × [r_kv, N·d]  →  [S, N·d]   ←维度同 §2 ②
V_raw      = c_KV × W_uv   →  [S, r_kv] × [r_kv, N·d]  →  [S, N·d]   ←完全不变
```

**④ Q 的压缩-还原（同 §2 ③，输出多出 rope 段——维度变化）**。`W_uq` 的每头输出是 `d + d_rope`（nope 段 + rope 段，一次 matmul 拼着出来；实例见 [GLM-5.3](../../../模型结构/GLM-5.3.md) §3.1）：

```text
c_Q   = X × W_dq   →  [S, H] × [H, r_q]             →  [S, r_q]           ←不变
Q_raw = c_Q × W_uq  →  [S, r_q] × [r_q, N·(d+d_rope)]  →  [S, N·(d+d_rope)]     ←§2 是 [S, N·d]
```

拆段后，rope 段现算现转（Q 不缓存，转完即用即弃）：

```text
Q_raw → Q_nope_raw : [S, N·d]    （不旋转）
      → Q_rope_raw : [S, N·d_rope]  （按位置旋转）
```

注意 `q_rope` 出自 Q 侧潜变量 `c_Q` 的还原路径，与 `c_KV` 无关。

**⑤ 分头（同 §2 ④）**。nope/rope 段各自分头；`k_rope` 无头维、保持原样：

```text
q_nope : [N, S, d]      ←Q_nope_raw 分头
q_rope : [N, S, d_rope]    ←Q_rope_raw 分头
k_nope : [N, S, d]      ←K_nope_raw 分头（推理时被 §4 吸收）
k_rope : [S, d_rope]       ←无头维，跨头共享
V      : [N, S, d]      ←同 §2
```

**⑥ 每头内的注意力（同 §2 ⑤，分数 = 两段点积相加）**。对第 `i` 个头，有效头维 `d + d_rope`：

```text
Score_i  = q_nope_i × k_nope_i^T  +  q_rope_i × k_rope^T
         →  [S, d]×[d, S]  +  [S, d_rope]×[d_rope, S]  →  [S, S]    ←分数形状不变
Weight_i = Softmax(Score_i)                      →  [S, S]
O_i      = Weight_i × V_i                        →  [S, d]    ←不变
```

逐 token 写开（m 查询位置、n 被查位置）：`score_i(m, n) = q_nope_i(m)·k_nope_i(n) + q_rope_i(m)·k_rope(n)`。对拼接向量 `[q_nope_i | q_rope_i] · [k_nope_i | k_rope]` 做整体点积与这两段相加**严格等价**（点积的线性性）——所以「`k_nope` 与 `k_rope` 拼成每头 `[d + d_rope]` 的 K」在数学上成立；但物理上 K 的两段头维结构不同（nope 每头独立、rope 跨头共享），**并不真拼**，Q 侧才是物理拼接。前一半可由权重吸收用潜变量直接算（§4），后一半用单独缓存的 `k_rope` 算。

**⑦ 拼回 + 输出投影（同 §2 ⑥，不变）**：

```text
O : [N, S, d]  →  transpose + reshape  →  [S, N·d]
Y = O × Wo     →  [S, N·d] × [N·d, H]  →  [S, H]
```



与 §2 干净版相比，**维度上只有下表几处变化**（`d_rope` 远小于 `d`，DeepSeek-V2、GLM-5.3 均取 64）：

| 项                               | §2（无 RoPE）     | 带 RoPE（本节）                                          |
| -------------------------------- | ------------------ | -------------------------------------------------------- |
| `W_uq`                         | `[r_q, N·d]`    | `[r_q, N·(d+d_rope)]`，每头多出 rope 段               |
| `W_kr`                         | 不存在             | `[H, d_rope]`，新增直连                                |
| `Q_raw`                        | `[S, N·d]`      | `[S, N·(d+d_rope)]`（拆 nope/rope 两段）              |
| K                                | `[S, N·d]` 一份 | `k_nope:[S, N·d]` + `k_rope:[S, d_rope]` 两份，不拼 |
| Cache                            | `c_KV:[S, r_kv]` | 多存`k_rope:[S, d_rope]`                               |
| `W_uk/W_uv/Wo`、V、Score、O、Y | —                 | 全部不变                                                 |

**对 c_KV 的影响：零**。`c_KV` 照 §2 ① 原样生成、落 Cache 时**从未被旋转**，② 的还原与 §4 的吸收照常——Cache 里是「未旋转的 `c_KV` + 已旋转的 `k_rope`」两种形态并存，各转各的。这正是「解耦」买来的东西：压缩-还原主干对 RoPE 完全无感，两条机制互不越界。

# 4. 关键工程技巧：权重吸收，避免还原

上投影还原（§2 ②）看似在 Decode 时每步都要把 `c_KV` 乘 `W_uk/W_uv` 还原成 `[N, S, d]`，那样 Cache 虽小、计算却没省。MLA 的关键工程技巧是**权重吸收**：

- 由于 Attention 只关心 `Q × K^T` 与 `× V`，可以把上投影矩阵 `W_uk` 吸收进 Q 的投影权重、`W_uv` 吸收进输出投影 `Wo`；
- 吸收后，**推理路径不再显式还原出 K/V**，而是直接用潜变量 `c_KV` 参与计算，把上投影的代价折进 Q/Wo 这一步；
- 因此 Decode 阶段既不需要存完整 K/V，也不需要每步重算上投影。

> 说明：位置编码（RoPE）无法被吸收——旋转角 `m·θ` 依赖 token 位置、折不进静态权重矩阵（注意不是「非线性」的问题：旋转本身是线性算子，卡住的是**位置依赖**）。MLA 的处理即「RoPE 解耦」：K 拆成不带位置的 nope 段（走 `c_KV` 路径，可吸收）与单独缓存的小维 rope 段（不可吸收），让「吸收」与「位置信息」同时成立，机制见 §3。

## 4.1 推理时哪些矩阵真正物化

吸收之后，§1 列出的四组矩阵在推理路径上的落点：

| 矩阵      | 推理物化情况                                   |
| --------- | ---------------------------------------------- |
| `W_dq`  | 物化（产出`c_Q`，不缓存）                    |
| `W_dkv` | 物化且**落 Cache**（产出 `c_KV`）      |
| `W_kr`  | 物化（RoPE 不可吸收，单独存，见 §3）          |
| `W_uq`  | 融合`W_uk^T` 后物化                          |
| `W_uk`  | **不物化**，被吸收进 `W_uq`            |
| `W_uv`  | **不物化**，被吸收进 `Wo`              |
| `Wo`    | 物化（融合`W_uv` 后，生效矩阵 `W_uv·Wo`） |

也就是说，`Wk`、`Wv` 作为独立矩阵在推理时已不存在——下投影 `W_dkv` 落 Cache、上投影 `W_uk`/`W_uv` 分别折进 `W_uq`/`Wo`，这正是「拆成下/上投影 + 吸收」带来的彻底改写。真正物化的是：`W_dq`、`W_dkv`（落 Cache）、`W_kr`、融合后的 `W_uq·W_uk^T`、融合后的 `W_uv·Wo`。

# 5. KV Cache 形状：压到 r_kv

吸收之后，每层真正需要缓存的只有潜变量（外加一个很小的 RoPE 解耦部分）：

```text
c_KV Cache : [S, r_kv]          （主部分）
(+ k_rope : [S, d_rope]，解耦 RoPE 部分，见 §3，量级远小于 N·d·S)
```

对比：

```text
MHA : [N, S, d] × 2            总量 2·N·S·d
MQA : [S, d] × 2               总量 2·S·d
GQA : [G, S, d] × 2            总量 2·G·S·d
MLA : [S, r_kv] (+ 小量)        总量 ≈ S·r_kv
```

当 `r_kv < d` 时，MLA 的 Cache 甚至比 MQA 还小，且**不依赖共享 K/V、保留了完整的多头 K/V 还原能力**——这是它与共享投影路线的本质区别。

# 6. 小结

```text
权重矩阵（§1）：  Wq→W_dq+W_uq；Wk→W_dkv+W_uk+W_kr；Wv→W_dkv+W_uv；Wo 保留
压缩-还原（§2）：  X × W_dkv → c_KV:[S, r_kv]              ← K/V 共享下投影，只缓存这个
                  c_KV × W_uk/W_uv → K/V:[N, S, d]        ← 计算路径，吸收后不显式发生
                  Q 对称：X×W_dq → c_Q × W_uq → Q:[N,S,d] ← 现算现用，不落 Cache
                  每头 Q_i×K_i^T → Softmax → ×V_i → 拼回 × Wo → Y（与 MHA 一致）
解耦RoPE（§3）：  K/Q 拆 nope+rope 两段（§3.2 ①-⑦ 全演绎）
                  W_uq → [r_q, N·(d+d_rope)]；新增 W_kr:[H, d_rope] 直连、转好落 Cache
                  分数 = q_nope·k_nope + q_rope·k_rope 两段相加，Score/O/Y 形状不变
吸收（§4）：      W_uk/W_uv 折进 W_uq/Wo，推理不显式还原 K/V
Cache（§5）：     [S, r_kv] + [S, d_rope]（解耦 RoPE）          ← 远小于 [N,S,d]
```

MLA 的本质：**用「K/V 共享下投影的低秩压缩」代替「共享投影」**——共享投影路线（MQA/GQA）是减少 K/V 的份数，MLA 则是减少 K/V 的维度：K/V 共用一个下投影压成一份与头数无关的低维潜变量，把每层的 KV Cache 压到远小于一组的体量，同时靠权重吸收让还原几乎零代价。它代表了削减 KV Cache 的另一条主流思路。
