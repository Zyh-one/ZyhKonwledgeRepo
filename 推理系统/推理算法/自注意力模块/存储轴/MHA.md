# MHA：多头注意力（Multi-Head Attention）

> 本文是「注意力变种」系列的第 1 篇，详细追踪 MHA 的张量维度转换。MHA 是其余变体（MQA/GQA/MLA）的共同基准，先把它的张量流讲清楚，后续变体只需对比「K/V 在头维度上的差异」即可。
>
> 关联：[自回归生成](<../../0-Transformer%20自回归生成的最小闭环.md>) §3.1 的单头 Q/K/V，本文把它从单头扩展到多头；[注意力模块演进](../注意力模块演进.md) §2。

---

# 0. 符号约定

```text
S        : 序列长度（Prefill 为 Prompt 长度，Decode 时为 KV Cache 长度）
H        : 隐藏维度（hidden_size）
N        : 头数（num_heads）
d        : 每头维度（head_dim），d = H / N
Wq/Wk/Wv : 各头投影权重，形状 [H, H] = [H, N·d]
Wo       : 输出投影权重，形状 [H, H]
```

本文沿用自回归生成的张量主线，只把「单头」换成「多头」，主流程 `Q×K^T → Softmax → ×V` 不变。

---

# 1. 从 X 到 Q/K/V：投影 + 分头

输入：

```text
X : [S, H]
```

三个权重矩阵分别投影：

```text
Q_raw = X × Wq   →  [S, H] × [H, H]  →  [S, H]
K_raw = X × Wk   →  [S, H] × [H, H]  →  [S, H]
V_raw = X × Wv   →  [S, H] × [H, H]  →  [S, H]
```

此时 `Q_raw` 还是「所有头拼在一起」的 `[S, H]`，需要**分头**：把最后一维 `H` 拆成 `N × d`，再转置让头维度在前，便于按头独立计算：

```text
Q_raw : [S, H]
       ↓ reshape 最后一维 H → (N, d)
       [S, N, d]
       ↓ transpose 头维度到最前
Q     : [N, S, d]
```

K、V 同理：

```text
K : [N, S, d]
V : [N, S, d]
```

关键点：**分头是逻辑视角，不是必须单独执行的物理步骤，也不引入新参数、不改变总数据量。** 它本质上是把 `Wq/Wk/Wv` 的 `[H,H]=[H,N·d]` 按列看成 N 个 `[H,d]` 的子块——第 `0..d-1` 列属头 0，第 `d..2d-1` 列属头 1，依此类推。因此 `X×Wq` 这个 matmul 的形状与单头完全一致，分头在张量层面只是把结果 `[S,H]` 重新看成 `[N,S,d]`（reshape + transpose，元素不变）。本文用「先投影成 `[S,H]` 再 reshape+transpose」表达分头，等价于另一种写法：直接按列切 `Wq` 成 N 块、各自算 `q_i=X×Wq_i→[S,d]`，全程不出现整块 `[S,H]` 的 Q——两者数学完全等价。相比单头，真正变化的不是 Q/K/V 的 matmul 形状，而是三处：(1) 权重内部按列分成 N 组子空间（但 matmul 形状不变）；(2) 注意力按头在各自 `d` 维子空间独立算 `Q_i×K_i^T→Softmax→×V_i`，这才是新增的计算结构；(3) N 个头输出拼回 `[S,H]` 再过 `Wo` 重组。这一步对应 [演进 §1](../注意力模块演进.md) 的核心理念——从 N 个不同维度去关注 token 间关联。

---

# 2. 每个头内的 Attention 计算

对第 `i` 个头（`i = 0..N-1`），取出：

```text
Q_i : [S, d]
K_i : [S, d]
V_i : [S, d]
```

Attention 计算与自回归生成 §3.2 完全一致，只是维度从 `H` 缩小到 `d`：

```text
Score_i = Q_i × K_i^T        →  [S, d] × [d, S]  →  [S, S]
Score_i + CausalMask
Weight_i = Softmax(Score_i)  →  [S, S]
O_i = Weight_i × V_i         →  [S, S] × [S, d]  →  [S, d]
```

N 个头并行各算一次，每个头都会得到一个`[S, d]`矩阵，下面开始进行拼接

---

# 3. 拼回头维度 + 输出投影

把 N 个头的输出拼回 `[S, H]`：

```text
O : [N, S, d]
       ↓ transpose 头维度回中间
       [S, N, d]
       ↓ reshape (N, d) → H
       [S, H]
```

再做一次输出投影 `Wo`：

```text
Y = O_concat × Wo   →  [S, H] × [H, H]  →  [S, H]
```

为什么要这一步 `Wo`？它有两个作用：(1) **混合头间信息**——N 个头各算一份 `O_i:[S,d]`，拼回 `[S,H]` 只是按列堆叠，各头输出仍停留在自己的 `d` 维子空间、彼此独立不交流，`Wo:[H,H]` 让它们互相组合，否则多头退化成「N 个独立小模型并列」，表达力大打折扣；(2) **投影回统一残差流空间**——残差连接 `x + Attn(x)` 要求两边同维同空间，各头输出在各自子空间里，`Wo` 把它们映射回共享的 `[S,H]` 表示空间，让残差相加在语义上（不只维度上）成立。一句话：分头让模型「并行看到多个维度」，`Wo` 让这些维度「汇成一句话」。这一点在所有注意力变体中都不变：`Wo` 住在注意力的**输出侧**，而 MQA/GQA/MLA 改的是**输入侧的 K/V 排布**，两者正交——MQA/GQA 只是 K/V 存几份变了，Q 仍有 N 个头 → N 份注意力输出 → 拼回 `[S,H]` → `Wo` 不可省；MLA 更典型，它的权重吸收技巧恰恰是把上投影 `W_uv` 吸收进 `Wo`，证明 `Wo` 在 MLA 里不仅存在、还是吸收操作的落点。所以族内不变量是：**输入侧的 K/V 怎么变都行，输出侧的「concat → Wo」始终不变**——变体动的是「K/V 在头维度上存几份」，`Wo` 动的是「N 个头输出怎么合回去」，是两件事。（某些实现会把 `Wo` 与后续投影融合以省一次访存，但概念上 `Wo` 一直都在。）

至此回到自回归生成的 `[S, H]` 主线，后续 MLP、LM Head 不变。

---

# 4. KV Cache 形状

MHA 下，每层缓存所有头的 K/V：

```text
K Cache : [N, S, d]
V Cache : [N, S, d]
```

Decode 每生成一个 Token，追加该 Token 在 N 个头上的 `k/v`，Cache 在 S 维上增 1，头维度 `N` 始终保留。

容量上有一个容易误判的点：MHA 的 KV Cache 总量 `2·N·S·d`，代入 `d=H/N` 得 `2·S·H`——与单头自回归生成的 `[S,H]×2` 元素数完全一致。**MHA 并未因「多头」而增大 Cache 容量，只是把 `[S,H]` 重排成 `[N,S,d]`（reshape + transpose，元素不变）**，变化的只是维度视图：从「一组 H 维」看成「N 组 d 维」。在 `d=H/N`（H 固定）的口径下 `N·d=H` 是常数，Cache 只随序列长度 S 增长、不随头数 N 增长；真正随头数膨胀并被 MQA/GQA 削减的，是 K/V 的头数副本（在固定 `d` 的前提下从 N 份降到 1/G 份），那是另一套口径，见后续变体文档。

---

# 5. 小结

```text
X:[S,H]
  × Wq/Wk/Wv:[H,H]  →  Q/K/V_raw:[S,H]
  reshape+transpose →  Q/K/V:[N,S,d]
  每头 Attention     →  O:[N,S,d]
  transpose+reshape  →  [S,H]
  × Wo:[H,H]         →  Y:[S,H]

KV Cache: [N,S,d] × 2
```

MHA 的本质：**Q/K/V 各自分成 N 份独立计算，每份各持一组投影权重，KV Cache 也按头各存一份。** 后续变体的改动，全部落在「K/V 这一边按头存几份」上。
