# 注意力变种概述：MHA / MQA / GQA

> 本文是「注意力变种」系列的开篇。它不深入每种变体的张量细节，只回答四个问题：**什么是注意力变种、为什么会出现、常用类型有哪些、它们和 [01 自回归生成](../01_transformer_token_autoregressive_generation.md) 是什么关系。**
>
> 各变体的详细张量流将放在本目录后续单独文档中。

---

# 1. 什么是注意力变种

在 [01 自回归生成](../01_transformer_token_autoregressive_generation.md) 中，为了突出主线，我们把 Self-Attention 简化为**单头**：一组 `Wq/Wk/Wv`，得到一组 `Q/K/V`，算一次 Attention。

真实模型并不止一个「头」。「头」是 Self-Attention 的并行计算单元，每个头用各自独立的 `Wq/Wk/Wv` 投影出各自的 `Q/K/V`，独立做一次 Attention，最后拼回去。**注意力变种，就是对「这些头之间如何共享 K/V 投影」做不同安排得到的几种变体。**

换句话说，注意力变种改的不是 01 里那条「Q×K^T → Softmax → ×V」的主流程，而是**K/V 在「头」这个维度上的排布方式**。主流程不变，变的只是 K/V 张量在头维度上的形状与体积。

---

# 2. 为什么会有注意力变种

直接动机来自 [01 文档第 6 节建立的 KV Cache](../01_transformer_token_autoregressive_generation.md) 与 Decode 阶段。

01 中单头场景下，KV Cache 形状是：

```text
K Cache: [S, H]
V Cache: [S, H]
```

一旦变成多头（MHA，`num_heads = N`，`head_dim = H/N`），KV Cache 在每一层、每一步都变成：

```text
K Cache: [N, S, head_dim]
V Cache: [N, S, head_dim]
```

层数越多、序列越长、头数越多，KV Cache 体积越爆炸。在 Decode 阶段，每生成一个 Token 都要从显存里把整段历史 KV Cache 读出来做 Attention——**此时算力往往不是瓶颈，KV Cache 的显存占用与访存带宽才是瓶颈**，这被称为 **memory-bound**。

注意力变种的出现，就是为了在「保持模型表达能力」的前提下，**减少 KV Cache 中重复存储的份数**，从而省显存、加速 Decode、并让单卡能装下更长的上下文。它是算法侧对系统工程瓶颈的直接回应。

---

# 3. 常用类型

三种主流变体的区别，可以一句话概括：**K/V 这组投影，是每个头各有一份，还是所有头共用一份，还是折中地分组共用。**

| 变体 | K/V 投影份数 | KV Cache 体积（相对 MHA） | 代表模型 |
|------|------------|--------------------------|---------|
| **MHA**（Multi-Head Attention） | 每个头各一组 | 1×（基准） | GPT、LLaMA 等多数基座 |
| **MQA**（Multi-Query Attention） | 所有头共用 1 组 | 1/N | PaLM、StarCoder 等 |
| **GQA**（Grouped-Query Attention） | 分成 G 组，每组内共用 | G/N | LLaMA-2(部分)/LLaMA-3、Mistral |

- **MHA**：每个头独立持有 `Wk/Wv`，表达力最强，但 KV Cache 体积最大。
- **MQA**：所有头共用同一组 `Wk/Wv`，KV Cache 缩到 1/N，Decode 最省，但表达力损失较明显。
- **GQA**：介于两者之间——把 N 个头分成 G 组，组内共享 `Wk/Wv`。`G=1` 退化为 MQA，`G=N` 退化为 MHA，是目前主流的折中选择。

> 补充：DeepSeek-V2 提出的 **MLA**（Multi-head Latent Attention）走的是另一条路——不靠共享 K/V，而是把 KV 压缩到一个低维潜变量再还原，同样为削减 KV Cache。它属于另一类思路，本文不展开。

# 4. 发展时间线

```text
2017  MHA   ——  Transformer 原始论文（Attention is All You Need）
                 每个头独立 K/V，作为标准结构沿用至今
2019  MQA   ——  Shazeer《Fast Transformer Decoding》
                 极端共享：所有头共用一组 K/V，Decode 显存大幅下降
2023  GQA   ——  Google《GQA: Training Generalized Multi-Query ...
                 Transformer Models from Multi-Head Checkpoints》
                 分组共享，在表达力与显存间取折中，成为新一代基座主流
2024  MLA   ——  DeepSeek-V2
                 低秩压缩 KV，另一条削减 KV Cache 的路线
```

整体趋势：**从「每个头各存一份」走向「尽量少存」，同时尽量不损失表达力。**

---

# 5. 与 01 自回归生成文档的关联

注意力变种并不推翻 01 的张量主线，而是对其中两处做「头维度」上的细化：

1. **K/V 的形状不同了。** 01 中 `K: [S, H]` 是单头视角；引入变种后，`K/V` 多出一个「头」维度，且不同变体在这个维度上的长度不同（MHA 是 N、MQA 是 1、GQA 是 G）。但 Q 仍然按 N 个头独立投影，主流程 `Q×K^T → Softmax → ×V` 在每个头内不变。

2. **KV Cache 的体积不同了。** 01 第 6 节建立的 KV Cache、Decode 第 1 节的「k5/v5 追加进 Cache」，在变种下追加的份数变少——这正是变种存在的意义：Decode 阶段访存与显存压力下降，而 01 描述的「新 q 访问整段历史 Cache」逻辑完全成立，只是 Cache 变薄了。

3. **Prefill/Decode 两阶段的瓶颈侧重被放大了。** 01 第 4 节提到「Prefill 建立 KV Cache 是计算所有 token 的关键」；在变种视角下，Prefill 仍是计算密集（要算所有头），Decode 则因 KV Cache 变薄而更偏 memory-bound。这为后续 [PD 分离](../其他细节/PD分离/PD分离.md)、[PagedAttention](../其他细节/PagedAttention.md) 等系统设计提供了动机。

一句话：**01 讲的是「单头下 Token 怎么流」，注意力变种讲的是「多头下 K/V 怎么省」——前者是骨架，后者是对骨架中 KV Cache 这一环的优化。**
