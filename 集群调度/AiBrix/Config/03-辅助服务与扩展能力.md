# 辅助服务与扩展能力

[返回总览](./README.md)

## `metadata/`

该目录包含：

- Metadata Service Deployment 和 Service；
- ServiceAccount、ClusterRole 和 ClusterRoleBinding；
- Redis Deployment 和 Service；
- Batch Job 模板 ConfigMap；
- S3/TOS 对象存储可选 Patch。

Metadata Service 管理用户、配额、Batch Job 和对象存储相关元数据。默认使用集群内 Redis，需要对象存储时可启用对应 Patch。

## `gpu-optimizer/`

包含 GPU Optimizer Deployment、Service 和 RBAC。该服务根据模型 Profiling 和 GPU 资源信息提供容量规划或异构 GPU 部署优化，不属于 Gateway 请求转发的必经链路。

## `job/`

包含 Job 相关的 ServiceAccount、Role 和 RoleBinding，供 Batch Job 或相关场景按需组合，不是 `default/` 的直接组成部分。

## `webhook/`

定义 `MutatingWebhookConfiguration`、`ValidatingWebhookConfiguration`、Webhook Service 和 Kustomize 引用转换配置。

Webhook 逻辑通常由 Controller Manager 中的 Webhook Server 执行：Mutating Webhook 补全默认值，Validating Webhook 拒绝非法资源配置。

## `internalcert/`

提供 Webhook Server 使用的 TLS Secret，使 Kubernetes API Server 可通过 HTTPS 调用 Admission Webhook。生产环境也可替换为 cert-manager 或平台证书方案。

## `prometheus/`

当前主要包含 Controller Manager 的 `ServiceMonitor`。它依赖集群已安装 Prometheus Operator，因此在 `default/` 中默认未启用。

完整的 Envoy、Gateway 和模型服务可观测性配置还可能位于 `observability/` 或特定的 `deployment/` 目录中。
