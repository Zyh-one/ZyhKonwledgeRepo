- K8s，挂载，PV，PVC

    - hostPath：Pod直接挂到当前节点的某个目录，不通过PV和PVC

        - 问题：Pod在不同节点上调度，挂载内容会随之变化

    - PV，PVC，StorageClass（动态创建PV，自动关联PV和PVC）

    - NFS（Network File System）

        - NFS协议

        - 多台机器共享同一份文件

        - 在读取其他节点的NFS文件时，依赖网络传输

- PV：静态供给和动态供给

    - 静态供给：管理员提前准备，手动创建PV

    - 动态供给：用户只创建PVC，k8s自动创建对应的PV

- **发现StorageClass的职能和作用其实随着PV的不同供给方式有所不同**

- StorageClass：这个概念，我很早就接触过，但是我一直没有清晰地理解

    - k8s中的一种资源；集群级别

    - 描述一类存储资源；规范如何创建PV

    - StorageClass为PV和PVC提供“类型标识”，并非PV和PVC的中间体（PV的静态供给）

        - 真正负责PVC和PV绑定的是K8s的PV Controller（PV的动态供给）

    - StorageClass动态创建PV，完整流程：

        ```CSS
        #动态存储供应
        创建 PVC
           ↓
        找到 StorageClass
           ↓
        StorageClass 指定 provisioner
           ↓
        CSI Provisioner 创建底层存储
           ↓
        自动生成 PV
           ↓
        PVC 与 PV Bound
        ```

- StorageClass有一个十分重要的概念：Provisioner；CSI

- CSI：API协议，

    - K8s指定CSI协议，规定标准调用接口（CreateVolume，DeleteVolume等）；

    - 按照这套接口写出来的东西就是**CSI驱动；**目的是将存储代码剥离到K8s核心之外

    - StorageClass中的Provisoner就是CSI驱动的名称，比如ebs\.csi\.aws\.com等

- Provisioner：CSI（CSI External\-Provisioner，CSI Driver）

    - 背后创建PV的完整流程：

        ```CSS
        用户创建 PVC
            ↓
        API Server 保存 PVC
            ↓
        external-provisioner 监听到新 PVC
            ↓
        读取 PVC.storageClassName
            ↓
        找到 StorageClass ceph-rbd
            ↓
        检查 StorageClass.provisioner 是否属于自己
            ↓
        调用 CSI Driver 的 CreateVolume
            ↓
        CSI Driver 调用真实存储系统
            ↓
        创建 Ceph RBD / 云盘 / 文件系统子目录
            ↓
        返回 volumeHandle 等信息
            ↓
        external-provisioner 创建 PV 对象
            ↓
        PV Controller 将 PV 与 PVC 绑定
        ```

    - CSI external\-provisioner：维护K8s集群的相关信息，负责监听PVC，选择StorageClass，调用CSI CreateVolume等

    - CSI Driver：维护存储后端的相关信息，负责调用存储后端，创建，删除，挂载存储卷

- CSI Driver在k8s集群中的存在形式依旧类似于AiBrix，Volcano等，位于某个特定的命名空间下面，一个CSI驱动一般是由Deployment \+ DaemonSet的组合形式

    - Kubernetes 就像是一个高度模块化的操作系统。不管你是管理硬盘的 \(CSI\)，管理网络的 \(CNI，如 Calico/Flannel\)，还是管理 AI 算力与复杂调度的 \(Volcano/AiBrix\)，大家都要**打包成镜像，变成 Pod，塞进某个 Namespace，然后配置好 RBAC 权限，最后去监听 API Server 的事件。**
