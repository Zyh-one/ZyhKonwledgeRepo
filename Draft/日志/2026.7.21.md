- 前端CSS，Flex布局

    - 控制CSS盒子模型的布局

    - 在语法形式上，和普通CSS属性没有区别；

```CSS
.container {
    display: flex;
    flex-direction: row;
    justify-content: center;
    align-items: center;
    gap: 16px;
}
```

- display: flex还会让其子元素成为Flex项目

- 两类Flex属性：

    - 父容器属性：直接写在`display: flex` 的顶层父容器中

    - 子容器属性：Flex属性写在子元素中

- 在CSS中，为什么Flex属性被单独提出来了？

    - 前端页面的布局极其重要，且复杂

    - Flex box的出现极大解决了这个问题

    - 后续结合AI开发前端，需要对Flex布局极其熟悉

- 前端CSS，Position（也是CSS属性）：

    - 悬浮、覆盖、固定位置等特殊场景

- 响应式布局：适配不同屏幕宽度

    ```CSS
    .cards {
        display: flex;
        gap: 16px;
    }
    
    @media (max-width: 768px) {
        .cards {
            flex-direction: column;
        }
    }
    ```

    - `@media` 根据屏幕条件切换样式



- TypeScript和JavaScript

    - 相同点：

        - 基础语法完全一致

        - 运行环境完全相同

    - 不同点：

        - JavaScript \(动态类型\)；TypeScript \(静态类型\)

        - 动态类型VS静态类型；类似python解释执行和Go/Java编译执行的区别

            - 动态\~：运行时（代码跑起来才知道数据类型对不对）

            - 静态\~：“编译”时（写代码敲键盘的瞬间就会检查）。

        - TypeScript是转译“伪编译”，区别于GO/Java（直接编译为机器码）

            - TypeScript \-\-\- tsc编译器 \-\-\-\> javaScript

- 直接开始TypeScript的语法学习：

    - 箭头函数；this

    - TypeScript / JavaScript天生异步并发，主进程绝不同步阻塞

        ```JavaScript
        function processAsyncData(urls: string[]) {
          for (const url of urls) {
            // 移除了 await
            const data = fetch(url); 
            console.log(`已发起请求: ${url}`);
          }
        }
        /*
        Python：同步阻塞执行
        TypeScript：异步执行
        因为两者最初解决的问题不同：一个追求“高并发与响应性”，一个追求“逻辑清晰与直觉”
        */
        ```

        - 意义：浏览器操作，在等待数据下载的时间内，整个网页不能完全卡死
