- 前端技术栈

    - 基础3剑客（HTML5，CSS，Js / Ts）：语言，根本

    - 前端框架（Vue / React / Angular）：

        - 目的：不用纯手写复杂的 JS 去操作网页元素

    - 构建工具（Vite / Webpack / Turbopack）

        - 类比python解释器，C\+\+的g\+\+编译器，运行构建项目的根本

    - 包管理器（npm / yarn）

        - 下载和管理项目依赖

        - 重要文件\`package\.json\` 

        - 

- Package\.json

    - 和go的go\.mod，python的poetry\.toml高度类似，配合yarn\.lock验证当前前端环境是否已经完备

    - Package\.json的dependency依赖中包含

        ```JSON
        "devDependencies": {
            "@vitejs/plugin-react": "4.7.0",
            "@types/react": "18.2.16",
            "@types/react-dom": "18.2.7",
            "typescript": "5.1.6",
            "vite": "6.4.3"
          }
        ```

        - 前端的全局环境通常只保留Node\.js和包和包管理器；项目级工具和依赖尽量局部化

    - 浏览器提供了相对统一的最终运行平台

    - Package\.json中的“scripts”把底层工具命令（比如Vite构建）封装成统一入口，实现

        - Yarn 把前端项目的依赖准备和开发、构建、测试等操作统一到了同一个命令入口之下。

- 前端代码是在用户的**浏览器（客户端）**上运行的。

    - 浏览器只认三样东西：**HTML、CSS 和普通的 JavaScript**。

    - 无论前端的生态有多么庞杂，最终都会经历“构建/打包”而产生可供浏览器理解的**dist/文件夹**，其中包含了CSS，HTML，普通的javaScript

- Node\.js环境：

    - 让 JavaScript 能够运行在“浏览器之外”的环境（JavaScript运行时）

        - JavaScript和TypeScript能够开始写后端逻辑，其根源也是来自Node\.js的支持

    - Node\.js负责：

        - 管理代码依赖（包管理器）

        - 代码编译与打包

        - 充当构建工具底座（Vite/Webpack）

- 只要是前端，一定要配置Node\.js环境吗？

    - 开发阶段（你的电脑）：一定需要配置

        - 现代前端工具（Vite，yarn，npm等）基本都是JavaScript程序，需要Node\.js提供运行时环境

    - 部署阶段：通常不需要

        - 当Node\.js把Ts代码“打包”完毕，生成静态干净的**dist/**文件夹，其中包含 HTML、CSS 和 JS 文件，Node\.js任务结束

        - 然后把这些文件扔给线上服务器（如Nginx）即可，浏览器会读懂它们，此时服务器就不需要Node\.js环境

        - 除非（特殊场景）：需要Next\.js服务端渲染

- dist/文件夹

    - 一般配合nginx，作为线上服务器，不需要配置node\.js环境

    - 在配置过程中，需要将dist/ 挂载到nginx容器中，同时还需编写nginx\.conf定义路由规则

- JavaScript：node\.js的出现，使得javaScript开始具备后端能力，故javaScript也被清晰划分为两个应用场景

    - 前端 JavaScript（供浏览器理解）

        - 运行在浏览器中

        - 负责用户界面的交互、动态效果和数据渲染

        - Node\.js（打包工具）

            - Node\.js会将包含 TypeScript、Sass等代码**转换打包**为dist/ 文件夹

    - 后端 JavaScript（由 Node\.js 执行）

        - 运行在服务器上的node\.js环境

        - 获得了真正的“服务器权限”，在服务器上执行各种操作

        - Node\.js（服务器引擎）

            - TypeScript等代码直接由服务器上的 Node\.js 进程来执行

- JIT：（即时编译）

    - 思想：不到运行的最后一刻，绝不把代码翻译成底层机器码

    - JavaScript V8JIT：

        - 根据程序运行时真实出现的数据类型和热点代码，动态生成并调整 CPU 机器码。

    - GPU算子JIT

        - 在程序运行或首次调用某个算子时，根据参数、张量形状、数据类型和目标 GPU，动态编译 GPU kernel，比如Tririon\.jit。

            - Triton 允许使用 Python 风格的语法描述 GPU kernel。被 `@triton.jit` 修饰的函数会在首次调用时经过 JIT 编译，并根据目标 GPU 架构、数据类型、编译参数和 kernel 配置生成对应的 GPU 代码；普通 Python Host 代码本身仍然由 Python 解释器执行。

            - Python启动程序，在加载到 `@triton.jit` 函数定义时，并不会立即被编译为GPU代码；直到kernel被实际调用，Triton 才拿到完整的运行上下文并触发编译。

                - 某种意义上，Python的解释执行也是Triton JIT 能够“延迟到实际调用时再编译”的关键一环

        - CUDA Graph只是记录了算子执行流程，在GPU上规划一部分区域，一部分是算子执行流程，一部分是输入，因此它更倾向在Decode阶段使用，没有编译的过程，因为不属于JIT的范畴
